## 1. 전 작업 공통 불변식 (위반 시 반려)

1. **LineId 재부여 금지.** 세이브 시킹(계약서 C1)·연출 바인딩·CSV가 전부 LineId에 걸려 있다. 어떤 편집 경로(노드 직접 편집·ScenarioOnly 붙여넣기)도 기존 라인의 LineId를 바꾸면 안 된다. 재파싱은 **diff 기반**: 기존 라인은 ID 보존, 신규 라인만 새 ID, 삭제는 명시 경고.
2. **선택지 순서 경고 유지(C3).** 어떤 편집 경로로든 옵션 순서 변경·삽입이 일어나면 기존 세이브 리플레이 경고가 그대로 떠야 한다. 새 편집 경로가 이 검사를 우회하면 안 된다.
3. **라이브 출력도 이미터는 하나다.** D-1의 실시간 합성 출력은 기존 NodeExportResolver·발행 Freeze 해석 경로를 **재사용**한다(ARCHITECTURE 규칙: 규칙 사본 금지). 계약서 A5(`pres_end`)·B(라인 예산)·C1(`#line:`)·D2(set은 Story만)·E2(메인 레인 전용 11종) 전 조항이 라이브 출력에도 적용된다.
4. **편집기 예외 전부 포획.** 크래시 금지(c1b67ee 회귀 주의). X1이 이 규칙의 위반 사례다.
5. **조용히 버리지 않는다(규칙 14).** 붙여넣기 파서가 해석 못 한 줄은 조용히 빠뜨리지 말고 목록으로 보여준다.

## 그룹 0 — 버그·즉시 제거 (X1, X8)

### X1. 에셋 폴더 지정 후 이미지 클릭 시 앱 종료 [버그]

- 원인을 찾아 수정하고, 해당 클릭 경로에 예외 포획(무동작 + 상태줄 사유)을 넣는다. 공통 불변식 4의 위반이므로 같은 패널의 다른 클릭 경로도 포획 여부를 점검한다.
- **수용**: 재현 시나리오에서 크래시 없음 + 예외 시 상태줄 표기. 회귀 테스트 추가.

### X8. 무대 프리뷰 위 버튼 3개 제거

- 오른쪽 아래 무대 프리뷰 위의 `배경폴더` / `초상화폴더` / `새로고침` 버튼을 제거한다.

- **수용**: 버튼 3개 부재 + 에셋 루트 지정·재스캔이 여전히 가능.

## 그룹 1 — 설정노드·변수 모델 (X2, X6, X7, X5, X3)

### X2. 변수에 타입 드롭다운

- 설정노드에서 변수 생성 시 값 입력이 아니라 **타입 선택 드롭다운**을 먼저 보여준다. 현재 지원 타입은 `float(숫자)` 하나뿐이지만 드롭다운 구조로 만들어 이후 타입 추가에 대비한다.
- 계약서 D4: 스탯은 숫자로 선언 출력(런타임이 float으로 읽음) — 타입 정보가 `<<declare>>` 출력과 정합해야 한다.
- **수용**: 변수 생성 플로우에 타입 드롭다운(float만), 선언 출력 불변.

### X6. Set 편집을 타이핑 → 드롭다운 + 슬라이더로

- 대사노드의 SetOperations 편집: 변수명 타이핑 대신 **설정노드에 등록된 변수 드롭다운**으로 선택.
- 수치는 슬라이더로 조절. 슬라이더 범위는 **변수별로 설정노드에서 등록**하며 기본값 `-5 ~ +5`.
- 연산자(`=` `+=` `-=`)는 기존대로 유지. 슬라이더 옆에 수치 직접 입력 필드를 동기화해 두면 범위 밖 값도 넣을 수 있다(범위는 슬라이더 편의지 검증 제약이 아님 — 제약으로 쓸지는 이후 결정).
- **수용**: 드롭다운에 미등록 변수는 나오지 않음, 슬라이더·직접입력 동기화, `<<set>>` 출력 불변.

### X7. Bool 조건은 On/Off 토글

- 조건(플래그)이 Bool 타입이면 Set·조건 편집에서 수치 슬라이더 대신 **On/Off 토글**을 보여준다.
- **수용**: Bool 조건 편집 UI가 토글, 출력은 기존 Yarn 문법 그대로.

### X5. Speaker 등록 + 대사노드 드롭다운 (원천 = game.definition)

- 설정노드에 Speaker 등록 UI를 추가한다. **저장은 `game.definition.json`의 `speakers[{name, characterId}]`에 쓴다** (D-4). 설정노드가 자체 사본을 갖지 않는다.
- 대사노드의 Speaker 입력을 이 목록의 드롭다운으로 바꾼다. 단, 미등록 화자도 오류가 아니다(마스터 플랜 §2.6 — 이름만 표시). 드롭다운 + 자유 입력 겸용(콤보박스)으로.
- **수용**: 설정노드에서 등록한 화자가 game.definition.json에 반영되고, 대사노드 드롭다운과 프리뷰 초상화 해석이 같은 원천을 읽는다.

### X3. 무대 프리뷰에 스탯 HUD

- 등록된 변수(= 플레이어 스탯)의 **현재 갈래 기준 값**을 무대 프리뷰 구석에 작게 표시한다.
- 켜고 끌 수 있는 토글 필수. 기본값은 표시.
- 값의 출처는 프리뷰가 현재 보여주는 라인까지의 `<<set>>` 누적(MiniStageFold의 갈래 근사와 같은 문서 순서 기준). 정확한 분기 시뮬이 아니라 근사임을 UI에 숨기지 말 것(규칙 14).
- **수용**: HUD 표시/숨김 토글, 값이 라인 이동에 따라 갱신.

## 그룹 2 — 선택지 UX (X9, X10)

### X9. 선택지 시작에 Speaker 불요

- 선택지 노드(블록)를 시작할 때 Speaker 입력을 요구하지 않는다. 선택지 라벨은 화자가 없는 버튼 텍스트다.
- **수용**: 선택지 생성 플로우에서 Speaker 필드 제거, 출력 불변.

### X10. 선택지 라벨 vs 선택 후 표시대사의 시각 구분

- 현상: 선택지 박스의 라벨(버튼 텍스트)과 그걸 골랐을 때 아랫줄부터 나오는 실제 표시대사가 UI에서 똑같이 생겨 헷갈린다.
- 라벨과 분기 대사를 **시각적으로 다르게** 표현한다(예: 라벨은 버튼 모양/아이콘, 분기 대사는 일반 대사 줄과 동일). 라벨은 대사가 아니라는 것이 한눈에 보여야 한다.
- 선택 후 분기 대사에서는 **Speaker가 일반 대사와 동일하게 편집·유지**된다(X5의 드롭다운 그대로).
- 계약서 D6: 라벨에 식별 접두 금지 유지. D5: 미리보기 태그 + `<<set>>` 동시 생성 유지.
- **수용**: 라벨과 분기 대사가 UI에서 즉시 구분, 분기 대사의 Speaker 편집 가능, 출력 불변.

## 그룹 3 — CompositionNode 전환 (X11, X13, X4, X12) — 가장 큰 덩어리

> 착수 전 이 그룹 전체를 설계로 먼저 훑고 커밋 계획을 세울 것. X11·X13은 선행 소품, X4·X12가 본체다.

### X11. ScenarioOnly 조건문을 실제 Yarn 문법으로

- Script Preview의 Scenario Only 표기에서 `[조건: 조건1]` `[다른 조건: 조건2]` `[조건 끝]` 대신 **실제 Yarn 문법** `<<if …>>` `<<elseif …>>` `<<endif>>`를 쓴다 (`<<else>>`는 현재 비범위 — 마스터 플랜 §3 — 지원 시점에 추가).
- 이유: X12에서 ScenarioOnly가 편집·붙여넣기 입력면이 되므로, 표기 문법과 파싱 문법이 같아야 왕복이 성립한다.
- **수용**: ScenarioOnly 표기가 Yarn 문법, 기존 대괄호 표기 제거.

### X13. 내보내기는 선택한 양식만

- 현재 내보내기 시 ScriptPreview의 모든 양식이 하나씩 산출된다. 이를 **선택한 양식만** 산출되도록 바꾼다(체크박스 또는 드롭다운, 선택 상태는 프로젝트에 저장).
- **수용**: 선택 양식만 파일 생성, 선택 상태 저장·복원.

### X4. 대사노드 생성 즉시 사용 + 대본 가져오기 제거

- 대사노드를 생성하면 별도 대본 연결 없이 **그 자체가 편집 대상**이다. 생성 직후 빈 라인 목록에서 바로 타이핑 시작.
- LineId는 라인 생성 시점에 부여되고 이후 절대 불변(공통 불변식 1).
- **대본 가져오기 트랙을 제거한다** (D-3). 관련 UI·코드 정리. 긴 외부 대본은 X12의 붙여넣기 파서가 대체 경로다.
- **수용**: 노드 생성 → 즉시 타이핑 가능, 가져오기 진입점 부재, 기존 프로젝트(가져오기로 만든 노드) 로드 호환.

### X12. ScenarioOnly 양방향 편집 + 라이브 CompositionNode 출력 (핵심)

**(a) ScenarioOnly 텍스트 편집·붙여넣기**

- ScriptPreview의 ScenarioOnly를 편집 가능하게 한다. 텍스트를 직접 쓰거나 붙여넣으면 자동으로 라인으로 들어온다.
- 파싱 규칙:
  - `willow: 싫어요.` → Speaker=`willow`, 대사=`싫어요.` — **첫 콜론 기준 분리하되, 콜론 앞 접두에 공백이 없을 때만** 화자로 해석한다.
  - 접두가 등록된 speaker(game.definition)면 화자 확정. 미등록이면 화자로 파싱은 하되 '미등록 화자' 표시(오류 아님 — §2.6 정합).
  - 콜론이 없거나 접두에 공백이 있는 줄 → 무화자(지문) 라인.
  - `<<if …>>` 등 X11의 Yarn 문법은 조건 구조로 해석.
  - 해석 못 한 줄은 조용히 버리지 말고 목록으로 표시(규칙 14).
- **diff 기반 반영**: 편집 결과를 기존 라인 목록과 대조해 — 내용이 같은 라인은 LineId 보존, 수정된 라인은 같은 위치의 ID 보존, 신규 삽입만 새 ID, 삭제는 확인 후 제거. 전량 재생성 금지(공통 불변식 1). 옵션 순서가 바뀌면 C3 경고(공통 불변식 2).

**(b) 다른 프리뷰 양식 연동**

- ScenarioOnly 외의 출력 프리뷰 양식들은 **읽기 전용이되 실제 저장 상태와 라이브 동기화**된다. ScenarioOnly에서 편집하면 즉시 반영.

**(c) 라이브 CompositionNode 출력 (D-1)**

- 대사노드가 생성되는 순간, 지정 폴더에 해당 노드의 정식 출력물이 생성된다. 이후 편집(대사·연출 공급·카메라·오디오)마다 자동 재합성·재저장.
- 합성 경로는 기존 발행 Freeze·NodeExportResolver 해석을 재사용한다(공통 불변식 3). 라이브 출력이라도 계약서 전 조항(A5·B·C1·D2·E2)을 지킨 산출물이어야 한다.
- **발행의 역할 재정의 (D-2)**: 발행은 연출노드 바인딩용 읽기전용 스냅샷(LineId·Speaker·대사·선택지·조건문)만 만든다. 연출이 읽은 대사 버전과 현재 대사가 어긋나면 기존처럼 **경고**(§2.5의 버전 짝 추적은 라이브 모델에서도 유지 — 조용한 드리프트 금지).
- 저장 실패·폴더 접근 불가 시 조용히 넘어가지 말고 상태줄에 알린다.

- **수용**:
  1. ScenarioOnly에 12줄짜리 대본을 붙여넣으면 화자/대사/지문이 올바르게 라인으로 생성된다.
  2. 기존 라인 3줄을 수정·1줄 삽입·1줄 삭제 후에도 나머지 라인의 LineId가 전부 보존된다(테스트로 고정).
  3. 노드 생성·편집 시 지정 폴더의 출력물이 자동 갱신되고, 그 내용이 수동 내보내기 결과와 바이트 동일하다.
  4. 연출↔대사 버전 어긋남 경고가 라이브 모델에서도 동작한다.

## 7. 완료 후 마스터 플랜 6차 개정에 반영할 것

- §2.5: 내보내기 단위·발행 개념을 D-1/D-2로 개정. **불변식(연출↔대사 버전 짝)은 문구만 바꾸고 유지.**
- §2.6: speakers 편집 창구가 설정노드로 생겼음을 기록(원천은 불변).

## 8. 착수 순서 요약

```
그룹 0 (X1 → X8)          : 버그·제거, 반나절
그룹 1 (X2 → X6 → X7 → X5 → X3) : 설정노드·변수, X5는 game.definition 쓰기 포함
그룹 2 (X9 → X10)         : 선택지 UX
그룹 3 (X11 → X13 → X4 → X12)   : CompositionNode 전환 — 설계 선행, 가장 신중히
```

그룹 0–2는 서로 독립이라 병렬 지시 가능. 그룹 3은 X11→X12 순서 의존이 있다.
