## 0. 비전과 전제 (불변)

### 0-1. 무엇을 만드는가

기획자가 **챕터·에피소드 구조를 엑셀로 정하면 그래프가 자동으로 그려지고**, 그 노드를 클릭하면 **작가가 엑셀에서 그냥 대본을 쓰는** 레이어. 대본은 평평화되어 기존 툴의 대사노드로 들어간다.

### 0-2. 변수는 두 층이다 (설계의 심장)

- **Tier 1 (로컬)** — 기존 툴에서 만드는 조건·선택지·set. 에피소드 안에서만 논다. 저장되지 않는다.
- **Tier 2 (고정 스탯)** — 2~5개 정수. 저장되고 챕터를 넘나든다. 그래프의 해금·선택 가능을 정한다.
- **환산은 에피소드 끝 1회.** 엑셀의 `스탯변화`도 즉시 반영이 아니라 로컬 누적 → 끝에서 커밋.

→ **에피소드 = 트랜잭션 경계.** 중간 세이브·롤백·중도 이탈에서 Tier 2가 변하지 않는다. (상세: 규격 §0)

### 0-3. 완전한 분리 — 이 레이어의 존재 이유

| 주체 | 자유 | 구조적으로 깰 수 없는 것 |
|---|---|---|
| 시나리오 작가 | 조건·변수·선택지 무제한 추가 | 세이브 호환 · 에피소드 도달성 |
| 기획자 | 챕터 구조·조건·잠금 | (대사 내용을 몰라도 된다) |
| 프로그래머 | 툴·런타임 기능 추가 | 기존 콘텐츠 호환 |

**분리의 실체는 경계면의 크기다** — 두 층이 주고받는 것은 에피소드 끝 1회, 2~5개 정수뿐이다. **경계면을 넓히는 변경은 반려한다.** (상세: 규격 §0.5)

### 0-4. 기존 툴은 손대지 않는다

기존 VnTool의 대사노드·연출 그래프는 역할이 분명하다. 이 레이어는 **별도 뷰/탭**이며 기존 코드를 수정하지 않는다. 유일한 접점은 ④→⑤(평평화 텍스트 → 기존 X11/X12 파서)다.

### ⚠ 폐기된 계획 — 착수하지 말 것

**`excel-authoring-orders.md` (XL1–XL7)는 폐기다.** 그 계획은 *기존 툴의 대사 편집을 엑셀로 바꾸는* 것이었고, 소유자가 "현재 툴은 역할이 분명하니 고치지 않고 별도 레이어를 만든다"로 방향을 바꿨다.

- 살아남은 기여: 시트 규격 계보(행 유형·색·잠금)와 **E-4 필드별 단일 소유권** 원칙 — 둘 다 이미 `chapter-graph-orders.md`에 흡수됐다. 따라서 파일이 없어도 잃은 것은 없다.
- 원래 우려("이 파일이 docs 루트에 남아 있으면 다음 세션이 기존 툴에 엑셀을 이식하려 시도한다")는 **파일이 아니라 참조로 남아 있었다.** `chapter-graph-orders.md`가 이 파일을 기준 문서·갱신 대상으로 걸어두고 있었고, 세션 0에서 그 두 군데를 끊었다.

## 2. 완성 기준 — 네 개의 게이트

각 게이트는 **객관적으로 확인 가능**해야 한다. 통과하지 못하면 다음 마일스톤에 착수하지 않는다.

### Gate A — 데이터가 화면이 된다
- [ ] 견본 워크북을 프로젝트에 넣으면 그래프가 **엑셀에 적힌 X·Y 위치와 간선 관계 그대로** 그려진다
- [ ] 오류 케이스(미등록 스탯키 · 소수점 · 빈 대사엔트리 · 중복 EpisodeId · 미정의 조건 라벨)가 **파일·시트·행·열까지 짚혀** 보고된다
- [ ] 엑셀 저장 → 뷰 즉시 갱신
- [ ] 뷰에서 노드를 드래그해도 엑셀이 바뀌지 않는다 (읽기전용 확인)

### Gate B — 대본이 대사노드가 된다
- [ ] 견본 에피소드가 **컴파일되는** 텍스트로 나온다
- [ ] 평평화 산출물에 **같은 대사가 두 번 나오지 않는다**
- [ ] 행 수정·삽입·삭제·구간 이동 후 **나머지 LineId가 전부 보존**된다 (테스트로 고정)
- [ ] 규격 §3.3 강제 규칙 6개가 **각각** 오류로 잡힌다
- [ ] **새 임포터 코드를 만들지 않았음**이 코드 경로로 증명된다 — 구체적으로 **`ScenarioTextParser` → `ScriptSynchronizer.Plan` → `ApplyScenarioText` 재사용**으로 증명한다 (규격 §4 G3)
- [ ] **엑셀 저장이 `Ambiguous`로 통째 거부되지 않는다.** 거부될 경우 **원인 행이 보고**된다 (규격 §4 G3-1 — 조용한 무반영 금지)

### Gate C — 보증이 장치가 된다
- [ ] 인위적으로 도달 불가를 만든 견본에서 **원인 조건까지 지목**해 검출한다
- [ ] 픽스처 전환 시 경로 하이라이트가 바뀌고, 픽스처가 내보내기에 섞이지 않는다
- [ ] 검증 오류가 있으면 **내보내기가 거부**된다

### Gate D — 런타임까지 관통 (최종)
- [ ] 내보낸 JSON을 유니티가 수입 → 기존 `EpisodeGraphRenderer`가 **같은 구도로** 그린다
- [ ] 에피소드를 플레이해 스탯을 올리면 → 다음 진입 시 **해금·선택 가능이 실제로 바뀐다**
- [ ] 에피소드 **중도 이탈 시 Tier 2가 변하지 않는다**
- [ ] 옵션 순서를 바꾼 뒤 **구 세이브가 원래 고른 선택지를 리플레이**한다
- [ ] 세 보증(규격 §0.5)이 테스트로 고정된다

## 3. 실행 계획 — 마일스톤과 순서의 이유

```
M0 (런타임)  ━━━━━━━━━━━━━━━━━━━━━━━━━━━  병행. 다른 저장소
M1 (데이터→화면)  ━━━━━━━→ Gate A
                          M2 (대본→노드)  ━━━━━→ Gate B
                                              M3 (검증)  ━━→ Gate C
                                                            M4 (관통) → Gate D
```

### M0 — 런타임 전제 (G9) · **지금 병행 착수**

**작업**: G9-a `YarnVariableBridge` 배선 + 환산 규칙 (U9) · G9-b 선택 기록 강화 (U4) · G9-c 세이브 v2 변수 범위 제한 (U15 착수 시)

**왜 지금, 왜 병행인가**
1. **G9-a 없이는 이 레이어 전체가 장식이다.** 브리지가 사장 상태라 지금은 대사에서 바꾼 값이 에피소드 해금에 전혀 반영되지 않는다. 그래프를 아무리 잘 그려도 게임에서 아무것도 열리거나 잠기지 않는다.
2. **G9-b는 보증 1의 전제다.** 계약서 C3의 위치 기반 선택 리플레이가 유일하게 Tier 1을 세이브로 새게 하는 통로다. 이걸 막지 않으면 "작가가 무엇을 해도 실패 없음"이 거짓이 된다.
3. **저장소가 다르므로 M1~M3와 충돌하지 않는다.** VnTool 작업이 막힌 시간에 굴릴 수 있다.
4. Gate D가 이것에 걸려 있으므로 마지막에 시작하면 전체가 지연된다.

**완성**: Gate D의 2·3·4번 항목이 런타임 단독으로 확인된다.

### M1 — 데이터가 화면이 된다 (G1 → G4)

**작업**: G1 챕터 워크북 리더 + 모델 → G4 그래프 뷰(읽기전용)

**왜 이것을 먼저**
1. **가장 값싸고 가장 먼저 눈에 보인다.** 엑셀 규격이 실제로 읽히는지가 여기서 판명된다.
2. **규격이 틀렸으면 M2 전에 고칠 수 있다.** 에피소드 리더·평평화를 만든 뒤에 챕터 규격을 고치면 양쪽을 다시 만진다.
3. G1의 조건 파서를 G2가 공유한다(규약 사본 금지) — 파서가 먼저 서야 한다.

**왜 G1 → G4 순서**: 모델 없이 뷰를 그릴 수 없다. 반대로 뷰 없이 모델을 검증하면 위치·간선의 오독을 눈으로 못 잡는다.

**완성**: **Gate A**

### M2 — 대본이 대사노드가 된다 (G2 → G3 → G5)

**작업**: G2 에피소드 리더 + 평평화 (**계획 승인 선행**) → G3 기존 파서 연결 → G5 클릭→엑셀 열기·동기화

**왜 M1 다음**: 챕터 규격이 Gate A로 검증된 뒤에 해야 재작업이 없다. 그리고 G2의 도달성 계산에 쓸 스탯변화량 규격이 M1에서 확정된다.

**왜 G2가 가장 위험한가 — 계획 승인이 선행되는 이유**
1. 평평화가 **LineId 전역 유일성(계약서 C1)**을 건드린다. 구간을 복제하면 세이브 시킹이 파손된다.
2. `OUT`은 Yarn으로 번역되는 명령이 아니라 **수렴 지점의 선언**이다 — 검증기가 대조하는 구조를 잘못 설계하면 조용히 어긋난다.
3. 계획서에 **"붙여넣기 시 전체 재생성"이나 "구간 인라인 복제"가 나오면 반려**한다.

**왜 G3가 새 개발이 아닌가**: X11(Yarn 문법 표기)과 X12(붙여넣기 파서 + diff 기반 LineId 보존)가 이미 이 임포터다. `.yarn` 전체 역파싱(마스터 플랜 비범위)이 아니라 X11이 정의한 부분집합만 다룬다. **새 파서를 쓰면 반려.**

**왜 G5가 마지막**: 왕복이 성립한 뒤에 붙이는 편의 기능이다. 먼저 만들면 검증 안 된 파이프라인에 파일 감시를 얹는다.

**완성**: **Gate B**

### M3 — 보증이 장치가 된다 (G7 → G6)

**작업**: G7 검증기 + 도달성 증명 → G6 잠금·픽스처

**왜 G7이 G6·G8보다 앞**
1. **내보내기 전에 무결성이 잡혀야 런타임에 쓰레기가 넘어가지 않는다.**
2. **보증 2(도달 불가 방지)의 유일한 장치가 G7이다.** 이게 없으면 "작가가 특정 에피소드를 영구히 막을 수 없다"가 보장되지 않는다.
3. 도달성 증명은 G1(챕터 조건)과 G2(에피소드 스탯변화량) **둘 다** 필요하므로 M2 이후여야 한다.

**왜 도달성 증명이 가능한가**: 스탯이 2~5개·정수·`최소~최대` 유한 범위라 상태공간이 작고 **완전 탐색이 된다.** float이면 결정 불가능하다 — 경계값 버그를 막으려던 정수 고정(G-3)이 이 보증을 가능하게 만들었다. 그래서 `스탯` 시트의 `최소`·`최대`는 장식이 아니라 **탐색 경계로서 필수**다.

**왜 G6가 G7 다음**: 픽스처("이 조건에서 어디로 가나")와 도달성 증명("어떤 조건에서든 갈 수 있나")은 다른 도구다. 증명이 먼저 서면 픽스처는 그 위의 탐색 도구가 된다.

**완성**: **Gate C**

### M4 — 런타임까지 관통 (G8 + M0 결합)

**작업**: G8 내보내기 → 런타임 수입 → 실플레이 검증

**왜 마지막**: Gate C를 통과한 데이터만 내보낸다. 그리고 M0가 끝나 있어야 스탯이 실제로 해금을 바꾸는지 볼 수 있다.

**완성**: **Gate D** — 이 게이트가 닫히면 레이어가 완성이다.

## 4. Claude Code 작업 지시 요령

- **지시서 기준.** 상세는 `work-orders/chapter-graph-orders.md`. 이 문서는 순서와 게이트만 말한다.
- **커밋은 G 단위.** 각 커밋 메시지에 해당 G의 수용 기준 확인 결과를 남긴다.
- **G2는 계획 승인 선행.** 구현 전에 규격 §7의 계획 항목을 보고한다.
- **반려 조건을 미리 못 박는다** — 붙여넣기 전체 재생성 / 구간 인라인 복제 / 새 임포터 작성 / 위치 기반 라인 매칭 / ~~뷰 드래그가 엑셀에 쓰기~~(G-2 v2로 허용 — 자동 레이아웃은 여전히 반려) / 브리지가 접두로 거둘 것 추측.
- **에셋·파일 관리 작업은 수용 기준을 사람의 동작 시나리오로 쓴다** — "JSON을 연다"가 답에 들어가면 실패(`runtime-ui-tooling-principles.md` §2.2). 같은 정신으로 **엑셀 작업의 수용 기준도 "기획자가 엑셀만 열고 끝나는가"로 쓴다.**
- **조용히 버리지 않는다**(ARCHITECTURE 규칙 14): 읽다 못 해석한 행·거부한 편집은 목록으로 보고.
- **규약은 한 곳**: 조건 파서·경로 조립·행 유형 판정이 두 곳에 생기면 반려.

## 5. 소유자 대기 항목

규격 §7이 정본. 착수 전 답이 필요한 것만:

| # | 항목 | 필요 시점 |
|---|---|---|
| 1 | Tier 1 네임스페이스 접두 문자열 확정 (`$__ep_` 등) — 기존 `$__ch_N`·계약서 §D 선언 규약과 충돌 없는지 | G2 계획 |
| 2 | Tier 1 → Tier 2 환산 규칙의 저작 위치 (권고: 기존 툴의 대사노드가 소유) | G2 계획 |
| 3 | 도달 불가를 오류로 막을지 경고로 둘지 (권고: 오류 + 명시 예외 열) | G7 |

나머지(스탯 범위·옵션별 OUT 분기 승격 등)는 해당 G 착수 시점에 결정하면 된다.

## 6. 하지 말 것

규격 §6이 정본. 특히 이 셋은 **레이어의 존재 이유를 무너뜨린다**:

1. **기존 툴 코드 수정** — 별도 뷰다. 접점은 ④→⑤ 하나.
2. **경계면 확장** — Tier 1의 무엇을 챕터 레이어로 흘리는 변경. 보증 3의 유일한 방어선이다.
3. **`excel-authoring-orders.md`(XL) 착수** — 폐기된 계획이다. §1 참조.
