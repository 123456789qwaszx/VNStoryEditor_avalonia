## 2. 입력 대본 (대본 가져오기에 넣을 원문)

라인 번호는 이 문서의 참조용이다. LineId는 툴이 부여한다.

### Story_Trial_01

```
윌로: 여긴 생각보다 조용하네.
라루: 조용한 게 늘 좋은 건 아니야.
윌로: 그렇긴 해. [adv/]하지만 지금은 좀 앉아 있고 싶어.
라루: 그럼, 어떻게 할래?
윌로: 혼자 두면 마음이 안 놓여.
윌로: 조금만 더 앉아 있을게.
라루: 알겠어. 그럼 그렇게 하자.
```

- L01 윌로 / L02 라루 / L03 윌로(**`[adv/]` 포함**) / L04 라루
- L05, L06 = 선택 분기 대사 (아래 §3에서 조건 갈래로 묶는다)
- L07 라루 (재합류)

> **⚠ `[adv/]`를 어디에 다는지 먼저 확인할 것.**
> 마스터 플랜 §2.4는 연출 노드가 "`[adv/]` 마커 그룹"을 소유한다고 되어 있고, 계약서 §B는 "`[adv/]`는 Phase 0에서는 미지원"이라고 (Phase 0 시점 기준으로) 적혀 있다. 즉 **대본 본문에 직접 타이핑하는 방식인지, 연출 노드에서 마커로 다는 방식인지** 현재 툴 동작을 확인해야 한다.
> - 본문 방식이면 위 대본을 그대로 쓴다.
> - 연출 노드 방식이면 L03에서 `[adv/]`를 **빼고** 가져온 뒤, §4에서 연출 노드의 마커 그룹으로 단다.
> 어느 쪽인지 확인하는 것 자체가 이번 관통의 수확이다. 확인 결과를 마찰 기록에 남길 것.

윌로: 그럼 가보자.

## 3. 툴 편집 지시

### 3-1. 변수 선언 (계약서 D4 — 선언 없으면 컴파일 실패)

- `$trust` = 0
- `$fatigue` = 0

선언 블록이 어디로 나가는지(전용 노드 vs 각 Story 노드 상단)를 **눈으로 확인**한다. Phase 0에서 정해진 위치대로 나오는지가 체크 대상.

### 3-2. 선택지 (L04 뒤)

| 옵션 | 라벨 | 미리보기 태그 | 실제 효과(`<<set>>`) | 분기 대사 |
|---|---|---|---|---|
| 1 | `같이 간다` | `#trust:+10` | `$trust += 10` | L05 |
| 2 | `여기 남는다` | `#fatigue:-5` | `$fatigue -= 5` | L06 |

**계약서 D6 확인:** 라벨에 `s1`/`s2` 같은 식별 접두가 붙어 나가면 안 된다. 툴은 접두 없이 출력하기로 확정됨(§2.3 D6) — 실제로 그런지 발행 산출물에서 확인.

**계약서 D5 확인:** 태그는 표시 전용이고 실제 효과는 본문 `<<set>>`이 담당한다. 툴이 **둘 다** 생성하는지 확인. 하나만 나오면 버그.

### 3-3. 조건 갈래 (Story_Trial_02, L08 뒤)

- `$trust >= 10` → L09
- else → L10

**주의:** 마스터 플랜 §2.3에 따르면 "조건 갈래 안 선택지(MixedChain)"는 미지원이다. 여기는 갈래 **안에 선택지가 없으므로** 유효한 구성이다. 실수로 섞지 말 것.

### 3-4. 노드 연결

Story_Trial_01의 마지막 실행 출구 → Story_Trial_02.

## 4. 연출 지시

에셋이 없으므로 **모양이 맞는지가 아니라 커맨드가 도달하는지**를 본다.

### Set_Trial_01 (Setup — 무대 초기화)

```
<<bg_spawn bg0 room_day>>
<<bg_fade_in bg0 10fr>>
<<slot00 c1 mid>>
<<cast c1 willo a 1>>
<<place_left c1 face>>
<<show c1 e1 14fr>>
<<slot00 c2 mid>>
<<cast c2 raru a 1>>
<<place_right c2 face>>
<<show c2 e1 14fr>>
```

호출 순서 계약(카탈로그 `cast` 노트): **slot → cast → pose/face**. 순서가 뒤집혀 나가면 런타임이 경고만 내고 무시하므로, 툴의 Setup 블록이 순서를 보존하는지가 체크 대상.

### Pres_Trial_01 (LineId별 바인딩)

| L02 | `<<face c2 3>>` `<<dip c2>>` | 표정 + 액팅 |

### Story_Trial_01 (메인 레인 전용 — 대사 노드에 붙어야 함)

```
<<box_named Speaker>>
<<box_protagonist Surface>>
```

> **⚠ 이번 관통의 가장 중요한 검증 하나.**
> 계약서 E2에 따르면 `box_named` / `box_protagonist` / `box_reset` / `beat` / `beat_fx` / `pres_*` 11개는 **서브 러너에 미등록**이라 Set·Pres 노드에 나가면 unknown command 오류다.
> 툴이 이 커맨드들을 어디로 내보내는지 발행 산출물에서 반드시 확인할 것. Set/Pres로 나가면 **버그**다.

참고: `Speaker`(named)와 `Surface`(protagonist)는 `box_reset`의 기본값과 같다. 즉 **화면상 변화는 없다** — 이 두 줄의 검증 대상은 "어느 노드로 나가는가"이지 "보이는가"가 아니다. 화면으로도 확인하고 싶으면 `box_named LetterBox`로 바꿔 넣으면 된다.
> 런타임 U6이 아직 안 들어갔다면 `box_named`의 오타는 **조용히 Portrait로 폴백**된다(계약서 E5·카탈로그 노트). 즉 지금은 오타를 내도 경고가 안 뜬다 — 철자를 정확히 쓸 것: `Portrait/Speaker/LetterBox/OnlyText/BlackBook/Surface`.

## 7. 관통 규율 (제일 중요)

> **고치지 말고 기록만 한다.**

손이 멈출 때마다 `friction-log.md`에 3분류로 적는다:

1. **버그** — 의도대로 안 됨 → 다음 지시서 후보
2. **조작/레이아웃** — 되긴 되는데 불편함 → **판단 보류.** 횟수만 센다. 한 번 겪은 걸로는 설계 못 한다
3. **개념 부재** — 하고 싶은데 툴에 그 개념이 없음 → 기능 백로그

예외 — 그 자리에서 고쳐도 되는 것: **관통 자체가 막히는 크래시.** 그 외에는 전부 기록 후 우회.

우회조차 불가능하면 그 단계를 "차단"으로 적고 다음 단계로 건너뛴 뒤, 8단계에서 어디까지 갔는지 남긴다. **부분 관통도 게이트 정보를 준다.**
