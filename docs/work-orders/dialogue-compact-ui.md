# DialogueNodeEditor 고밀도 대사 편집 UI 개편

> 2026-08-04 소유자 지시(원본: Downloads의 spec 파일). **구현 완료** — 결과 요약은 문서 끝 §13.

## 0. 작업 목적

현재 `DialogueNodeEditor`의 대사 편집 카드는 한 줄이 지나치게 높다.

조건 드롭다운, Set 추가 버튼, 이동·삭제 버튼, 선택지 외곽 박스 등이 각 대사마다 수직 공간을 많이 차지하여, 한 화면에서 대본 전체 흐름을 읽기 어렵다.

이번 작업의 핵심 목표는 다음과 같다.

> 오른쪽 대사 편집 공간을 엑셀처럼 빠르게 훑어볼 수 있는 고밀도 편집 화면으로 바꾼다.  
> 단, 실제 `DataGrid`처럼 딱딱한 표로 만들지는 않고, 현재의 “대사 한 줄당 하나의 카드” 구조는 유지한다.

가장 중요한 사용성은 한 화면에서 많은 대사를 읽고 비교할 수 있는 것이다.

---

## 1. `＋` 버튼을 눌렀을 때 무엇이 나오는지

`＋` 버튼을 누르면 Flyout을 열고 기존 데이터 구조를 사용하는 메뉴를 표시한다.

- 조건 추가 또는 변경
- 선택지 시작
- Set 추가
- 출구(다른 노드로 점프) 추가
  - 다른 노드로 점프는 선택지나 조건 분기 시 각 선택과 조건 루트 끝의 라인에서만 가능하다.

---

## 2. 기존 태그를 어떻게 수정할지

태그를 표시만 하고 수정 방법이 없으면 기능이 퇴보한다.

이미 존재하는 조건·선택·Set 태그는 클릭할 수 있어야 한다.

- 조건 태그 클릭 → 기존 조건 선택 ComboBox를 Flyout으로 표시
- Set 태그 클릭 → 기존 변수·연산자·값 편집 UI를 Flyout으로 표시
- 선택 태그 클릭 → 기존 선택 분기 편집 UI를 표시

평상시에는 편집 컨트롤을 숨기고, 필요할 때만 펼친다.

---

## 3. 대사 행의 조작 버튼 제거

기존 각 대사 카드에 있던 다음 버튼을 모두 제거한다.

- ▲ 위로 이동
- ▼ 아래로 이동
- × 줄 삭제

Hover 시 표시하는 방식도 사용하지 않는다.

조작 버튼을 위해 빈 열 너비를 미리 확보하지도 않는다.

따라서 대사 한 줄의 기본 열은 다음으로 단순화한다.

```text
Index | LineId | Character | 대사 | ＋
```

여기서 행 오른쪽의 `＋`는 줄 추가 버튼이 아니다.

이 버튼은 현재 대사 줄에 다음 메타데이터를 추가하거나 편집하는 버튼이다.

- 조건
- 선택지
- Set
- 출구

---

## 4. 목표 화면 구조

대사 편집 목록 위에 한 번만 표시되는 얇은 열 헤더를 둔다.

권장 크기는 다음과 같다.

```text
Index       28~32
LineId      56~72
Character   80~110
대사        *
태그 추가   26~30
```

오른쪽 패널 폭에 따라 대사 열이 남는 공간을 전부 사용해야 한다.

---

## 5. 평범한 대사 줄

조건, 선택지, Set, 출구가 없는 평범한 대사는 오직 한 줄만 차지해야 한다.

예상 형태:

```text
┌  2 │ ln_002 │ willow │ 천재신가요?                │ ＋ │
└──────────────────────────────────────────────────────────────┘
```

요구사항:

- 카드 하나
- 기본 높이 목표: 34~40px
- 최대한 42px를 넘지 않을 것
- 위아래 Padding은 3~5px 수준
- 카드 사이 간격은 2~4px
- 화자와 대사는 한 줄 입력
- 긴 대사가 카드 높이를 늘리지 않아야 함
- 긴 텍스트는 TextBox 내부에서 가로 이동하거나 클리핑되도록 할 것
- Index는 흐린 색의 읽기 전용 텍스트
- LineId는 읽기 전용
- LineId 또는 Index 툴팁에 revision 등 기존 정보를 유지
- 화자는 기존 AutoCompleteBox 자유 입력 동작 유지
- 대사는 기존 TextBox 직접 입력 동작 유지
- 선택된 무대 프리뷰 기준 줄의 왼쪽 파란 강조 띠 유지

일반 대사에는 빈 조건 영역이나 빈 Set 영역을 만들지 않는다.

현재처럼 모든 대사 아래에 `+ set` 버튼을 항상 표시하지 않는다.

---

## 6. 태그 영역

조건·선택지·Set이 있는 줄에는 메인 대사 행 위에 작은 메타데이터 레일을 표시한다.

예:

```text
        [조건1] [set favor += 1]
┌  2 │ ln_002 │ willow │ 천재신가요?                │ ＋ │
└──────────────────────────────────────────────────────────────┘
```

태그가 하나도 없다면 상단 레일은 생성하지 않는다.

즉, 태그가 없는 줄은 추가 높이를 전혀 가져서는 안 된다.

선택지 라벨 줄이라면 다음처럼 보이게 한다.

```text
        [선택 1]
┌  5 │ ln_005 │   ▶   │ 때린다                     │ ＋ │
└──────────────────────────────────────────────────────────────┘
```

선택지 라벨은 기존 규칙대로 화자 입력을 표시하지 않는다.

---

## 7. 태그 추가 버튼

메인 행의 대사 오른쪽에 작은 `＋` 버튼을 둔다.

이 버튼은 “대사 줄에 메타데이터 추가” 버튼이다.

---

## 8. 조건 분기 표시

조건이 적용된 대사 줄은 다음 두 가지로 명확하게 구분한다.

1. 오른쪽으로 한 단계 들여쓰기
2. 해당 조건 팔레트의 색 사용

---

## 9. 선택지 블록 표시

현재 선택지 전체를 외곽 박스로 감싸는 구현은 유지하되, 선택지로써 제시되는 헤드 라인과 선택 이후 표시되는 라인을 구분한다.

---

## 10. 출구 표시

다른 노드로 이동하는 분기 출구가 있는 줄은 메인 행 아래에 작은 출구 레일을 표시한다.

예:

```text
┌  6 │ ln_006 │ 라루 │ 그럼 맞서겠습니다.                  ┐
└──────────────────────────────────────────────────────────┘
          → 분기 이후: 장면 3
```

---

## 11. Set 표시 규칙

```text
[set favor += 1]
┌  3 │ ln_003 │ willow │ 알겠습니다.                      ┐
└─────────────────────────────────────────────────────────┘
```

---

## 12. 선택한 대사 아래에 줄 추가

현재 편집기 상단에 있는 줄 추가 버튼의 동작을 변경한다.

### 선택된 줄이 있을 때

현재 선택한 대사 행의 바로 다음 위치에 새 줄을 삽입한다.

예:

```text
0  ln_001
1  ln_002  ← 현재 선택
2  ln_003
```

줄 추가 실행 후:

```text
0  ln_001
1  ln_002
2  ln_new  ← 새 줄, 새 선택
3  ln_003
```

### 선택된 줄이 없을 때

활성 대사 목록의 가장 마지막에 새 줄을 추가한다.

### 대사가 하나도 없을 때

첫 번째 줄로 추가한다.

## 13. 구현 결과 (2026-08-04)

전 절 구현. 구조는 전부 기존 것을 재사용했다 — 새 해석 경로 없음(규칙 15):
갈래 계산은 `ConditionFlowResolver`, 전환 항목은 `ConditionChoices`, Set 편집 행은
`BuildSetOperationRow`, 출구는 그래프 분기 간선과 같은 `SetExitTarget(Branch)` 하나.

- **§3~§5**: 메인 행 `Index(30) | LineId(64) | Character(96) | 대사(*) | ＋(28)` 열 헤더 1회.
  카드 Padding (6,3), 카드 간격 3, 대사 TextBox는 NoWrap 한 줄(긴 대사는 칸 안에서 가로 이동).
  Index·LineId 읽기 전용 + rev 툴팁, 화자 AutoCompleteBox·파란 선택 띠 유지.
- **§6·§11**: 태그 레일은 전환·Set이 있는 줄에만 생긴다. 조건 태그(팔레트 색)·선택 N(호박색)·
  조건 종료/선택지 끝(회색)·`set 변수 += 값`(파랑).
- **§2**: 태그는 클릭 → 기존 편집 컨트롤이 Flyout으로 열린다(조건 ComboBox / Set 편집 행).
- **§1·§7**: ＋ Flyout = 조건/선택지(기존 드롭다운) + Set 추가 + 출구(갈래 마지막 줄에서만) + 줄 조작.
- **§8~§10**: 조건 들여쓰기(20px)+팔레트 색 유지, 선택지 외곽 박스 유지(라벨=채워진 버튼 모양,
  분기 대사=들여쓰기), 출구 레일 "→ 분기 이후: 노드명"(클릭으로 편집 — 표시만 하면 퇴보).
- **§12**: [줄 추가]가 선택 줄 바로 아래 삽입(`InsertScriptLine(scriptId, index)`), 새 줄이 새 선택.

**지시서에서 벗어난 판단 1건**: §3이 ▲▼✕ 행 버튼을 제거하지만, 줄 이동·삭제 진입점이
아예 사라지면 §2의 원칙(수정 방법 없는 표시는 퇴보)에 걸린다. 행에서는 제거하되
＋ Flyout의 "줄" 섹션(▲ 위로 / ▼ 아래로 / ✕ 삭제)으로 옮겼다.

검증: 전체 475 테스트 통과 + 앱 스모크 9초. 저장 형식·출력 불변(순수 화면 재구성).
수동 확인(한 화면 밀도 체감, 태그 Flyout 편집 감각)은 handoff/next-tasks.md T2에 합류.
