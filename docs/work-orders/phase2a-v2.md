# Phase 2a-v2 작업 지시서 (W17–W21) — 에셋 탐색기 · 프리뷰 창 분리 · 연출 편집 UX

전제 문서: `docs/vntool-master-plan.md`(5차 개정), `docs/runtime-ui-tooling-principles.md`, `docs/runtime-contract.md`. **커밋은 W 단위.** 2a-v1(W13–W16) 위에 쌓는다.

## 배경과 목표 (소유자 피드백 2026-08)

1. 배경·초상화 폴더가 **왼쪽에 탐색기처럼** — 정확한 폴더 구조 + 안에 뭐가 있는지.
2. 프리뷰는 형식이 아니라 **"완성된 비주얼노벨이라 가정하고 보는 뷰"** — 대사창 포함, **별도 창**, **정해진 해상도**(1920×1080 확정, game.definition에서 교체 가능).
3. 커맨드 연출 연결이 까다롭고 복잡 — **직관적으로**. 프로토 데모라 친절해야 함.

확정된 설계 결정: 프리뷰 직접 조작 **포함**, 커맨드 텍스트 직접 입력 **허용**, 기준 해상도 **1920×1080 기본값**.

## 설계 원칙 (전 W 공통)

- **세 입력 경로, 한 통로.** 직접 조작·에셋 드래그·텍스트 입력·갤러리 — 어떤 방식으로 만들어도 전부 같은 `ProjectEditor` 편집 명령으로 수렴한다(모델 변경 유일 통로·되돌리기 원칙 유지). 프리뷰용 별도 쓰기 경로 금지.
- **텍스트가 진실, 툴은 편의.** 어떤 방식으로 만들었든 결과 커맨드는 항상 `<<이름 인자…>>` 텍스트로 병기 표시. 텍스트 입력 파싱은 카탈로그(parameters 순서·타입) 기준 검증 — 산출물 되읽기가 아니라 **입력 방법**이므로 역파싱 금지 원칙과 무관.
- **미처리 가시화(규칙 14) 유지.** 직접 조작이 못 만드는 커맨드는 갤러리·텍스트로 만들 수 있고, 프리뷰가 못 그리는 커맨드는 Unhandled 뱃지로 보인다.
- **친절함은 빈 상태에서.** 에셋 미설정·공급 없음·발행 안 됨 등 모든 빈 화면에 "다음에 할 일" 한 줄 + 이동 버튼. 기능 잠금이 아니라 안내.

## W17. 좌측 에셋 탐색기

1. 좌측 패널에 "에셋" 섹션(기존 편집 자료 현황판과 나란히, 접기 가능): 트리 = 에셋 루트 2개(배경/초상화) → 실제 폴더 구조 그대로(하위 폴더 포함).
2. **배경**: 폴더 규약 그대로 파일 목록 + 썸네일, 파일명 = spriteKey 표시.
3. **초상화**: 매니페스트 기준으로 **캐릭터 → variant → emotion** 그룹 트리(파일 시스템이 아니라 키 구조로 보여준다 — 연출가의 머릿속 단위). 각 항목 썸네일.
4. **문제 표시**: 매니페스트에 있는데 파일 없음 / 파일 있는데 매니페스트에 없음(고아) / speakers 매핑에 있는데 초상화 없는 캐릭터 — 항목 옆 아이콘+문구. 원칙 문서 §2.5(침묵을 화면으로).
5. 새로 고침 버튼(감시 없음 — v1 결정 유지). 항목은 W20 드래그의 소스가 된다.
6. 빈 상태: "에셋 폴더가 설정되지 않았습니다 — [폴더 지정…]".

수용: 픽스처 에셋으로 트리·그룹·문제 표시 확인 테스트(뷰모델 수준), 스모크.

## W18. 프리뷰 창 분리 + 대사창 표시

1. **별도 Avalonia 창** "무대 프리뷰": 기준 해상도 1920×1080의 고정 종횡비 스테이지(창 크기 무관 레터박스 스케일). 해상도는 `game.definition.json`의 `preview.resolution`(기본 1920×1080)에서 읽음.
2. 메인 창의 라인 선택을 **따라가기 토글**(기본 켬)로 동기화. 창 하단에 현재 노드·인덱스·LineId 표시와 이전/다음 라인 버튼(프리뷰 창에서도 라인 이동 가능).
3. **대사창 근사 렌더**: 폴드의 boxKind별 레이아웃 근사 — Speaker(하단 박스+이름표), OnlyText(무테 텍스트), LetterBox(상하 밴드+중앙 텍스트), Portrait/Surface/BlackBook은 v1에선 Speaker 근사+종류 뱃지. 화자명은 speakers 매핑 표시명, 본문은 선택 라인 대사. 위치·크기는 기준 해상도 비율 고정(런타임 픽셀 재현은 2b).
4. 기존 편집기 내 프리뷰 패널은 유지하되 축소판으로(같은 폴드·같은 렌더 코드 공유 — 사본 금지), "창으로 열기" 버튼.
5. Unhandled 뱃지·갈래 근사 표시는 프리뷰 창에도 동일하게.

수용: 1920×1080 좌표계 고정 렌더 테스트(뷰모델), 창 리사이즈 시 레터박스 유지 수동 확인, 스모크.

## W19. 연출 편집 UX — 갤러리·칩·텍스트 입력

1. **갤러리형 커맨드 추가**: 라인 카드의 "연출 추가" → 팝업: ① 프리셋(공급 노드 것, ★ 우선) ② 최근 사용(프로젝트 저장) ③ 카테고리(카탈로그 categories) — 액팅류는 강도순 부그룹(미세/가벼움/보통/강함 — 레퍼런스 §23.3 매핑을 카탈로그 메타에 추가) ④ 이름 검색. 각 항목에 표시명+출력 커맨드명+한 줄 설명(카탈로그 notes 요약).
2. **칩형 인자 편집**: 대상(slot/alias) 인자는 자유 입력 대신 **현재 폴드 상태의 무대 위 후보**(슬롯·@alias·캐릭터명 표기) 드롭다운 + 직접 입력 허용. duration 인자는 칩(0fr·4fr·6fr·10fr·14fr·24fr·1.2s — §23.6 표) + 직접 입력. direction·focusPreset·screenPoint 등 토큰 타입은 카탈로그 type 기준 후보 목록.
3. **함정 노트 인라인 표출**: 카탈로그 notes(음수 클램프, size_reset float 초 등)를 해당 커맨드 편집 UI에 ⚠ 아이콘+툴팁으로 — 이미 있는 데이터를 화면으로.
4. **텍스트 직접 입력**: 라인 바인딩에 한 줄 입력창 — `<<face_swap @1 5 4fr>>`(꺾쇠 유무 허용) 입력 시 카탈로그 기준 파싱→구조화 추가. 미지의 커맨드명·인자 초과·타입 불일치는 **즉시 인라인 오류**(추측 보정 금지 — 원칙 §2.3). 각 커맨드 카드에는 항상 생성될 텍스트 병기.

수용: 파서 왕복 테스트(입력→구조→병기 텍스트 동일), 오류 케이스(미지 커맨드·인자 초과) 인라인 표시, 갤러리 후보가 공급 범위를 존중(기존 AvailablePresentationCommandResolver 재사용 — 사본 금지).

## W20. 프리뷰 직접 조작 + 에셋 드래그

인식 22종 어휘 = 직접 조작 어휘. 모든 조작은 "선택된 라인의 바인딩에 커맨드 추가/수정"으로 귀결(ProjectEditor 경유, 되돌리기 동작).

1. **캐릭터 클릭** → 팝오버: 표정 그리드(해당 캐릭터의 emotion 썸네일 — 선택 시 `face_swap`, 미등장 상태면 `face`), 등장/퇴장(`fade_in`/`fade_out`), 좌우 반전(`mirror`), variant 전환(`pose`). 이미 그 라인에 같은 종류 커맨드가 있으면 **수정**(중복 추가 금지 — 예: face_swap 값 교체).
2. **배경 클릭** → 배경 선택 팝오버(탐색기와 같은 목록) → `bg_sprite`(기존 배경 리그 대상) 또는 첫 배경이면 `bg_spawn`.
3. **에셋 드래그**: 탐색기 배경 → 프리뷰 = 2와 동일. 탐색기 초상화(캐릭터/감정) → 프리뷰 = 무대에 있으면 `face_swap`/`face`, 없으면 캐스팅 시퀀스 유도(슬롯 선택 팝오버 → `slot`+`cast`+`fade_in` — **매크로가 아니라 개별 커맨드 3개가 그대로 바인딩에 보인다**. 툴이 마법을 부리는 게 아니라 표준 등장 시퀀스를 대신 타이핑해줄 뿐 — 원칙 §2.3).
4. 조작 결과는 병기 텍스트로 즉시 확인 가능(W19-4와 동일 카드). 프리뷰는 편집 직후 재폴드.
5. 발행된(읽기 전용) 결과를 보고 있을 때는 직접 조작 비활성 + "작업 중 연출을 편집하려면…" 안내(발행 불변 원칙).

수용: 각 조작이 기대 커맨드를 생성/수정하는 테스트(편집 명령 수준), 중복 방지(같은 라인 face_swap 교체), 되돌리기 1회로 원복, 발행 결과 위 조작 차단.

## W21. 검증·마감

1. 전체 테스트 + 회귀: 직접 조작·텍스트 입력으로 만든 커맨드가 기존 발행→이미터 경로에서 손으로 만든 것과 동일 출력(골든 1케이스).
2. 데모 친절함 점검: 신규 프로젝트 → 에셋 미설정 → 폴더 지정 → **대사노드 생성 후 직접 입력(그룹 3 전까지는 현행 가져오기도 허용)** → 연출 → 프리뷰 확인까지 **안내 문구만 따라가면 도달**하는지 수동 시나리오 1회.
   ※ 그룹 3(X4·X12) 완료 시 "ScenarioOnly 붙여넣기"로 재교체 — `composition-node.md` §4 참조.
3. ARCHITECTURE에 편집 경로 수렴 원칙(세 입력 경로, 한 통로) 추가.

## 비범위

위치·크기·이펙트의 직접 조작(2b에서 배치가 그려질 때), 프리뷰 창에서의 재생(2c), 애니메이션 미리보기, 에셋 파일 감시.
