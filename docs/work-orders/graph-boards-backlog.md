# 그래프 판(보드) 확장 백로그 — 파일 단위 판과 파일 간 연결

2026-08-06 작성. 소유자 지시: "나중에는 이런 판을 여러 개 파일 단위로 저장한 다음, 그 파일
내의 노드를 그래프로 보여주고, 서로 다른 파일의 노드끼리도 연결될 수 있도록 한다. 그런데
지금은 작업이 너무 커질 것 같으니 판 크기만 늘리고 나머지는 작업 목록으로 정리한다."

**W41(판 크기 12000×8000 확장)로 당장의 좁음은 해소됐다.** 이 문서는 그 다음 단계다 —
착수 전 소유자 승인이 필요하며, 순서와 범위는 착수 시점에 다시 확정한다.

## 0. 이미 있는 것 (다시 만들지 말 것)

지금 구조가 이 방향의 절반을 이미 갖고 있다:

- **StoryFile이 이미 있다.** 프로젝트는 파일(StoryFile) 목록이고 노드는 파일에 속한다.
  좌측 파일 목록에서 파일별 "그래프에 펼침" 체크와 "현재 작업 파일" 라디오가 이미 동작한다.
- **파일 접기 = FileProxy.** 접힌 파일은 한 캔버스 안에서 프록시 카드(노드 행 목록)로
  그려지고, 간선 endpoint만 프록시 행으로 옮겨 붙는다 — 연결 자체는 끊기지 않는다.
- **파일 간 연결은 이미 된다.** 실행 출구·공급 연결 전부 NodeId를 가리키므로
  (`GraphProjectionBuilder`가 화면만 계산) 서로 다른 파일의 노드끼리 이미 연결·유지된다.
- **좌표는 노드 소유(`StoryNode.Layout`), 단일 좌표 공간.** "파일 단위 판"의 핵심 결정은
  이 좌표를 판(파일)별 공간으로 바꿀 것인가다 — 아래 GB-1의 결정 사항.

즉 남은 일의 본질은 "파일 개념 추가"가 아니라 **"한 캔버스에 전부 그리는 화면을 판 단위
화면으로 바꾸는 것"**이다.

## 1. 작업 목록 (GB = Graph Boards)

### GB-1 — 판 전환 화면: 파일 = 판 하나

한 번에 한 파일(판)만 캔버스에 그린다. 판 전환은 탭 또는 좌측 파일 목록 클릭.

- **결정 필요**: 좌표를 판별 공간으로 재해석할지(파일마다 (0,0)부터), 지금의 단일 공간을
  유지한 채 화면만 필터할지. 판별 공간이 자연스럽지만 기존 프로젝트 좌표 이행이 필요하다.
- 판별 뷰 상태(스크롤 오프셋·배율) 기억 — 뷰 상태이므로 저장하지 않는다(원칙 E)면
  세션 안에서만, 저장한다면 workspace 상태(파일 펼침과 같은 층)로.
- 미니맵·범위 선택·이어 재생은 그대로 판 안에서 동작해야 한다.

### GB-2 — 판 사이 연결의 표현: 포탈 포트

다른 판의 노드로 가는 간선을 화면에 어떻게 그릴 것인가. 데이터는 이미 NodeId라 문제없다 —
문제는 표현이다.

- 제안: 판 경계에 **포탈 칩**("→ 파일B · 노드명"). 클릭하면 그 판으로 전환 + 해당 노드 선택.
- 연결 만들기: 포트를 끌어 좌측 파일 목록의 노드 행(또는 판 탭)에 놓으면 파일 간 연결 —
  지금의 FileProxy 행 드롭과 같은 규칙을 재사용한다(사본 금지).
- 노드 간 이어 재생(W39)은 NodeId 기반이라 판을 넘어도 이미 동작한다 — 판 전환 UI만
  따라가면 된다(재생이 다른 판의 노드로 넘어가면 그 판을 연다).

### GB-3 — 큰 판의 성능: 가상화와 드래그 배칭

노드 수백 개부터 실비용이 나온다. 판 크기가 아니라 **노드 수**가 비용이다.

- 뷰포트 밖 카드·간선을 만들지 않거나 숨긴다(가상화). Rebuild가 전량 재생성이므로
  스크롤·줌에 따른 증분 갱신 설계가 필요하다.
- 드래그 중 `MoveNode`가 픽셀 단위로 프로젝트 변경을 만든다 — 드래그 중에는 화면만 옮기고
  놓을 때 한 번 커밋(Undo 1건)으로 바꾼다. 다중 선택 이동은 N배로 이득.
- 미니맵 갱신도 지금은 전량 재그리기 — 노드 수가 커지면 같이 손본다.

### GB-4 — 판 위의 길찾기 편의 (작은 것들, 독립 착수 가능)

- 새 노드를 좌상단 고정 위치가 아니라 **현재 뷰포트 중앙**에 생성.
- 선택 노드로 화면 이동(그래프 밖에서 노드를 선택했을 때 판이 따라가기).
- "전체 보기" 버튼(노드 전체가 들어오는 배율로) · 배율 프리셋(50/100/150%).
- 노드가 판 경계 밖으로 끌려 나가지 않게 상한 클램프(지금은 좌상단 0만 클램프).

## 2. 권장 순서와 근거

**GB-4 → GB-1 → GB-2 → GB-3.** GB-4는 지금 판(W41)에서도 바로 값어치가 있는 소품이다.
GB-1이 구조 결정(좌표 공간)을 품으므로 먼저 서고, GB-2는 그 위의 표현이다. GB-3은
실제로 노드 수가 문제 될 때 — 미리 짓지 않는다(현재 수십 개 규모에서는 불필요).

## 3. 비범위 (이 백로그에 넣지 않은 것)

- 판의 파일 분리 저장(프로젝트 파일 바깥의 개별 판 파일) — 지금 StoryFile은 프로젝트
  안의 논리 단위다. 물리 파일 분리는 저장 스키마 결정이 따로 필요하다.
- 다인 협업·판 잠금 — 마스터 플랜 비범위 그대로.
