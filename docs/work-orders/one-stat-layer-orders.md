# 계층을 하나로 — 런타임 쪽 작업 지시

2026-09-17 · 소유자 결정 · **저작 쪽 준비 완료, 런타임 쪽 착수 전**

이 문서는 **런타임 쪽에 부탁하는 일**이다. 저작 쪽(VnTool)에서 이미 끝낸 것과 저쪽에서
해 주셔야 하는 것을 가른다. 계약의 정본은 [`../runtime-contract.md`](../runtime-contract.md)이고,
충돌하면 그쪽이 이긴다.

---

## 0. 무엇을 하나 — 한 문장

**스탯의 계층을 하나로 합친다.** 「작가 전용 스탯」이라는 개념을 없애고, 대사가 물을 수
있는 낱말을 **챕터 스탯 하나**로 만든다.

소유자: *"조건이나 스탯 역시, 게임 전역 최소한 챕터단위로 하나의 계층만 쓰는 게 맞다고
판단했습니다. 오히려 작가전용 스탯이라는 개념을 완전히 삭제합니다."*

### 죽는 분리와 사는 분리

| 분리 | |
|---|---|
| **어휘의 분리** — 기획자 스탯 / 작가 변수 | ⛔ **죽는다.** 사전이 둘이라 갈렸고, 대사 분기가 물을 낱말이 없었다 |
| **읽기와 쓰기의 분리** — 어디서나 읽고 **간선에서만** 쓴다 | ✅ **산다.** 이게 없으면 세이브/로드 복귀와 도달성 증명이 깨진다 |

⚠ 둘을 묶어서 "계층"이라고 불러 온 것이 혼란의 원인이었다. **없애는 것은 첫째뿐이다.**

## A. `stat("키")` — 대사가 스탯을 **읽는** 길 (부탁)

### 왜 필요한가

2026-09-01(G0)에 `PublishStats` 다리를 걷으면서 **A계층 스탯이 Yarn에서 사라졌다.** 그런데
저작 쪽은 챕터 조건을 **모든 대사 카드에 공급하고 있었다** — 기능이다(*"개발자를 안 부르고
조건을 건다"*). 그래서 그날부터 이 기능이 **죽어 있었다**: 조건을 고를 수는 있는데 고르면
산출이 막혔다(`ValidateProgressionStatReferences`가 `$진행스탯`을 차단으로 잡았다).

계층이 하나가 되면 대사가 물을 낱말은 챕터 스탯뿐이므로, **읽는 길이 있어야 한다.**

### 규격

```yarn
<<if stat("trust") >= 3>>                        ✅ 읽기
<<if stat("trust") >= 3 && stat("fatigue") <= 2>> ✅ 복합 (시트의 `;`가 `&&`로 나간다)
<<if stat("met_willow") == 1>>                   ✅ 깃발 — 0/1 정수다
```

| | |
|---|---|
| 이름 | `stat` — 툴 쪽 상수는 `YarnSyntax.StatFunction` 한 곳이다 |
| 인자 | 스탯 키 **문자열** 하나. Yarn 식별자로 정규화된 이름이다(공백·기호는 `_`) |
| 반환 | **정수**. 깃발도 정수 0/1이다(2026-08-19 — 별도 타입 없음) |
| 없는 키 | 저쪽 정책대로. 툴은 `스탯` 시트에 없는 키를 <b>산출 전에</b> 막는다 |

### ⛔ 함수여야 한다 — 변수로 심으면 안 된다

`$trust`로 심으면 읽기와 함께 **`<<set $trust = 5>>`가 문법적으로 유효해진다.** 대사 중의
스탯 쓰기는 세이브/로드 복귀와 도달성 증명이 **못 보는 뒷길**이고, 2026-08-14에 대본 J열을
폐지한 이유가 그것이다. 함수에는 왼쪽 변이 없어 **쓸 수가 없다** — 금지가 아니라 불가능이다.

> G0가 걷은 다리는 **양방향**이었다. 되살리는 것은 **읽기 절반**이다.

### 타이밍

⚠ **저쪽에 함수가 없으면 번들이 컴파일에서 선다.** 조용히 빗나가는 것보다 나은 실패지만,
**반영 전에는 export를 미룬다.** 이름을 바꾸시려면 말씀 주시면 상수 한 곳만 고치면 된다.

## B. 작가 전용 YarnVariable 삭제

저쪽에서 이미 하기로 한 일이고, 여기서는 **맞물림만** 적는다.

| 이쪽이 함께 하는 것 | |
|---|---|
| `＋ set`·변수 드롭다운 등 **저작 표면**을 걷는다 | 쓰는 프로젝트가 없다(소유자 확인: *"있다 하더라도 그냥 버립니다"*) |
| `declarations.yarn`의 작가 변수 `<<declare>>`를 안 낸다 | 스탯 쪽 선언은 그대로 |
| **`Tier1Namespace`가 통째로 죽는다** | `__t1_{판Id}_` 접두는 **어휘가 둘이라 이름이 부딪혀서** 있던 것이다. 하나면 부딪힐 게 없다 |

내보낸 .yarn이 `$trust`와 `$__t1_file123_flag`가 섞이던 것에서 **한 종류**로 정리된다.

⚠ 이쪽 절반은 **먼저 가도 안전하다** — 덜 내보내는 것은 아무것도 안 깨뜨린다.

## C. `EpisodeOption.ViaNodeId` 칸 철거 (함께)

### 지금 상태

저작 쪽은 2026-09-17(R7 P-6)부터 **이 칸을 안 채운다** — 늘 빈 문자열이다.

「길에 매단 연출」을 같은 재생 순서의 **에피소드 한 칸**으로 펴기 때문이다:

```text
전: A —"문구"→ B     (간선에 Via가 매달려 있다)
후: A —"문구"→ 연출 —자동→ B
```

런타임이 A를 틀고, 고른 뒤 연출을 틀고, 묻지 않고 B로 간다 — **순서가 같다.** 곁칸은 같은
것을 말하는 두 번째 방법이었다.

### 부탁

⚠ **급하지 않다.** 계약이 *"없으면 빈 문자열로 언제나 낸다"*고 이미 적고 있어 **안 걷어도
아무 문제가 없다.** 남겨 두는 비용은 늘 빈 칸 하나다.

걷으려면 **양쪽이 함께** 움직여야 한다 — `Ked.Progression`은 런타임 코어의 **사본**이고
`runtime-sync.txt` 지문이 둘을 묶는다. 한쪽만 고치면 대조가 깨지고 런타임이 로드에서 죽는다.

**A·B와 한 번에 묶는 것을 권한다.** 어차피 같은 지문에 걸린다.

## D. 도달성 증명의 상태 벡터 — **합의 요청** (지시가 아니다)

### 무엇이 문제인가

작가 변수가 없어지면 *"아까 그 장면 봤나"* 같은 기억이 전부 **챕터 깃발**로 들어온다.
그런데 증명기는 상태를 **(에피소드, 스탯 정수 벡터)** 로 완전 탐색한다:

- 주석: *"스탯 5개 × 범위 0~10이라도 이 안에 넉넉히 든다"*, `StateLimit = 250_000`
- **깃발 하나당 상태공간 ×2.** 연출용 깃발 스무 개면 ×100만 — 상한에 걸린다

걸리면 보고가 조용히 내려앉는다:

> `'X'에 도달할 수 있는 경로가 없습니다` (오류) → `도달하는 경로를 찾지 못했습니다(탐색이 상한에서 중단됨)` (경고)

**보증이 「증명」에서 「못 찾았음」으로 바뀌는데 화면은 거의 같아 보인다.**

### 제안

> **간선 관문이 안 읽는 스탯은 상태 벡터에서 뺀다.**

어느 표시/해금 조건도 안 묻는 깃발은 **어느 간선을 탈 수 있는지에 영향을 못 준다.**
툴이 계산할 수 있고 저작자가 표시할 일도 없다. 대사가 읽는 것은 빼도 된다 — 증명기는
대사로 갈리는 길을 **어차피 넓게(열려 있다고) 잡으므로** 건전성은 그대로고 정밀도만
조금 떨어진다.

### ⛔ 그래서 물어보는 것이다

`ChapterReachabilityProver`의 머리에 이렇게 적혀 있다:

> ⚠⚠ **이 구현은 2026-08-18부터 남의 오라클이다. 고치기 전에 알려야 한다.**
> 여기 동작을 바꾸면 — **버그 수정이라도** — 두 구현이 조용히 갈린다.

제안이 답을 안 바꾼다고 이쪽이 판단해도, **그 판단이 틀렸을 때 저쪽 테스트는 초록인 채로
갈린다.** 그래서 이쪽에서 **한 줄도 안 건드렸다.**

**여쭙는 것:** 이 축소를 받아들이시겠는가, 그리고 받아들인다면 코퍼스
(`Tests/Fixtures/reachability-oracle.json`)를 다시 뽑는 시점은 언제가 좋은가.

## 2. 순서와 맞물림

| 순서 | |
|---|---|

스탯을 읽을 길이 A다. 하나만 하면 대사 분기가 물을 것이 **아무것도 없는** 상태가 된다.
