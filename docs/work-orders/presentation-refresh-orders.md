## 0. 왜 이 순서인가

```
W64 Core 사본 최신화 ──▶ W65 카탈로그 최신화 ──▶ W66 MoveBy 슬라이더 편집 ──▶ W67 ease ──▶ W68+ 계통 확장
    (재현의 계산기)         (어휘의 진실)            (첫 편집 경험)              (런타임 개통 후)   (같은 패턴 반복)
```

- 프리뷰 재현의 계산기(리듀서·종점 산수)가 낡은 채로 편집 UI를 올리면 **그래프가
  거짓말한다.** 그래서 Core부터.
- 카탈로그가 죽은 커맨드 57개를 내밀고 있으면 "목록에 뜨는 칸은 채우면 반드시
  동작한다"(원칙 2.1)가 이미 깨져 있다. 편집 UI를 얹기 전에 어휘부터.
- MoveBy 하나로 **선언→폴드→슬라이더→커밋→발행** 전 구간을 뚫어 두면, 계통 확장은
  같은 패턴의 반복이 된다.

## 2. W64 — Core 사본 최신화 (런타임이 정본)

패키지화 대신 감사(audit) 동기화. 절차가 산출물이다 — 다음 동기화(EaseFunctions가
저쪽에 서는 날)가 같은 절차를 다시 탄다.

1. **감사** — 줄바꿈 정규화 diff로 3분류: ⓐ 런타임에만(가져온다) ⓑ 내용 차이(런타임
   본으로 교체) ⓒ **툴에만 있는 멤버·파일**(목록화 — README·csproj는 툴 살림이므로
   유지, 코드 멤버는 교체 후 컴파일이 깨지는 것만 되살리고 **왜 필요한지 주석**을 남긴다.
   장차 저쪽에 올려 보낼 후보 목록이 된다).
2. **이식** — 런타임 트리를 복사(`.asmdef`·`Tests/`·`.meta` 제외), ⓒ 복원.
3. **보수** — 컴파일 오류는 전부 ⓒ 누락이거나 새 API 적응이다. **런타임 쪽 파일은
   손대지 않는다** — 역방향 수정 금지, 필요하면 목록에 적어 소유자가 저쪽에 전달.
4. **고정** — `Ked.Presentation.Core.Tests`(현 220) + 전체 테스트(현 1197) 통과.
   런타임 `Tests/`에서 이쪽에 없는 커버리지가 보이면 가져올지 판단해 기록.
   동기화 절차를 `src/Ked.Presentation.Core/README.md`에 적는다(누가 정본인가 포함).

**수용**: 전체 테스트 통과 · ⓒ 목록이 run-log에 남음 · README에 절차 · **무대
프리뷰가 런타임과 같은 그림을 그린다**(current-state §7의 "패키지화 시점" 항목이
"사본 최신 · 절차 확립"으로 갱신됨).

## 3. W65 — 커맨드 카탈로그 최신화 (어휘의 진실 회복)

정본은 **브리지 등록 실측**이다(§1의 스캔). 문서·기억이 아니라 코드에서 뽑는다.

1. **대조 보고 먼저** — 3열 표(카탈로그에만 57 / 양쪽 106 / 런타임에만 2)에
   시그니처 대조(핸들러 인자 수·타입 ↔ 카탈로그 parameters)까지 얹어 소유자에게.
   사라진 57종은 **폐지/이관 중/유보**를 종별로 확정받는다 — 특히 emoji·idle·몸짓
   계열은 통째로 사라져 별도 시스템으로 이관 중일 가능성이 크다.
2. **적용** — 확정본대로: 폐지 항목 제거 · `focus_on`/`focus_clear` 추가 · 시그니처
   불일치 수정(`move_by`는 이미 대조 완료 — slot·x·y·duration 일치). "이관 중"은
   제거하되 보고서에 남긴다.
3. **연쇄 갱신** — 갤러리·`ArgumentTokenCandidates` 후보·`CommandText` 파싱 후보가
   카탈로그 하나에서 나오는지 확인(사본이 있으면 그것부터 수술).
4. **기존 대본 보호 (침묵 금지)** — 폐지 커맨드가 남은 대사·연출 노드는 **검증
   보고에 "런타임에 없는 커맨드"로 선다.** 조용히 지우지 않고, 조용히 내보내지도
   않는다(내보내면 런타임이 unknown command로 죽는 걸 저작에서 미리 짚는 것 —
   엔딩키 충돌 거부와 같은 이유). 발행 차단까지 갈지 경고까지만 갈지는 보고서에서
   소유자가 정한다.

**수용**: 실측 스캔 = 카탈로그 (자동 대조 테스트로 고정 — 다음에 또 벌어지면
테스트가 먼저 안다. 스캔 결과를 픽스처로 저장소에 둔다) · 견본 프로젝트(DevSync
`test3`) 검증 보고에 유령 커맨드가 어긋남으로 잡히는 것 확인.

## 4. W66 — MoveBy 편집: 프리뷰 + 커맨드 목록 + 슬라이더

소유자 UX: *연출 그래프에서 연출노드 클릭 → 툴 프리뷰를 보면서, 프리뷰에 합쳐진
커맨드 목록에서 커맨드를 고르고, 노출된 개별 수치를 슬라이더로 실시간 조절.*

기존 자리에 얹는다 — 새 창·새 탭이 아니다:

- **커맨드 스트립**: `StageSceneView`(도킹·분리 공용 렌더러)에 현재 라인의 커맨드
  칩 목록(♪ 칩과 같은 자리 감각). 칩 선택 = 그 커맨드가 편집 대상.
- **인스펙터 밴드**: 선택 칩 아래로 수치 노출. `move_by`면 —
  `[x −6u…+6u]` `[y −6u…+6u]` (u 스냅, Shift 미세) · `[duration 0…48fr]` (fr 스냅,
  0 = 즉시 스냅임을 표시) · `[ease]` 곡선 썸네일(개통 전엔 OutCubic 고정 표시 —
  **편집 칸으로 내밀지 않는다**, 원칙 2.1).
- **커밋 규칙** — 직접 조작의 연장이다: 드래그 **중**은 렌더만(프로젝트 변경·
  `QueueReload()` 없음 — 성능 규칙), 놓는 순간 기존 `PresentationStageActions` →
  `ProjectEditor` "같은 종류는 수정" 통로로 한 mutate. undo 1회 = 슬라이더 조작
  1회. 병기 텍스트 즉시 갱신. 발행 결과 공급 화면에서는 기존 잠금 규칙 그대로 잠긴다.
- **카탈로그 채널 선언** — `move_by` 항목에 `motion` 선언(노드 `CharSlot_Track` ·
  x·y 상대 u · durationParam · defaultEase OutCubic — 모양은
  `motion-graph-orders.md` MG1 제안 그대로). 선언 없는 커맨드는 인스펙터가 수치를
  내밀지 않는다(추측 금지) — 텍스트·갤러리 편집은 지금대로.

둘로 가른다. **b는 a를 막지 않는다**:

- **W66a — 슬라이더 + 정지 재현**: 조절 즉시 무대에 **종점 고스트 + 이동 궤적
  폴리라인**. 종점은 `MoveByReduction`, 시작값은 직전 라인 폴드 — 이징 없이도
  정확한 값들이라 런타임 의존이 없다. **여기까지로 이미 쓸모가 선다.**
- **W66b — 시간 재현(재생·스크럽)**: 배치 내 시간축을 실제 곡선 모양으로 재생.
  `EaseFunctions`가 필요하다 — 런타임 Core에 서고(`ease-open-orders.md` §2·§3)
  W64의 동기화 절차로 넘어온 뒤. 시간 의미론은 `motion-graph-orders.md` §2가 정본
  (한 라인 = 한 배치 동시 시작 · 같은 축 둘째는 첫째를 즉시 완주시킴 · 이어 그리기 금지).

**수용**: ① 슬라이더 조작 → 병기 텍스트의 해당 인자만 변함(고정 테스트) ② undo
원복 ③ `InputPathEquivalenceTests`에 슬라이더 경로 추가 — 같은 편집을 텍스트로
했을 때와 발행 동일 ④ 궤적·종점이 리덕션 값과 일치(테스트) ⑤ (b) 스크럽 t 위치 =
`EaseFunctions` 평가값 · 골든 대조 < 1e-4.

## 5. W67 — ease 편집 개통

**선행**: 소유자가 [`ease-open-orders.md`](ease-open-orders.md)를 런타임 쪽에 전달,
§4(다섯째 위치 인자)까지 개통 확인.

- 카탈로그 `move_by` parameters에 ease 칸 추가(후보 = 골든 덤프의 목록).
- 인스펙터의 ease 썸네일이 선택기로 열림 — 곡선 미리보기 갤러리에서 고르면 텍스트
  다섯째 인자로. **기본값(OutCubic)과 같으면 생략**해 내보낸다(기존 대본 최소 diff).
- 곡선 **드래그** 편집과 표준 스냅은 여기 아님 — 후속(§7).

**수용**: 선택 → 텍스트 갱신·생략 규칙 테스트 · W66b 재생이 고른 ease의 모양으로 논다.

## 6. W68+ — 계통별 데려오기 (한 계통 = 한 W)

MoveBy에서 뚫은 패턴(채널 선언 → 폴드 확인 → 인스펙터 노출 → 왕복 테스트)의 반복.
계통 분류와 정확한 소속은 **W65 대조 보고에서 런타임 Commands 폴더 기준으로 확정**하고,
순서는 소유자가 고른다. 실측 기준 후보:

| 계통 | 런타임 실재 커맨드 (2026-08-20 스캔) | 비고 |
|---|---|---|
| Move | `move_by`✓ · `move_reset` · `char_move_to` · nudge(`left/right/up/down`, `*_per`) | move_reset은 두 축(Track+Focus)을 함께 민다 |
| Anchor | `show`(SetAnchorReduction 경로) · `slot`/`slot00~02` | 배치축 — 시간 편집이 아니라 자리 편집 |
| Place | `place` · `place_*` 14종 | 둘째 인자는 screenPoint가 아니라 focus(신체 지점) |
| ShotResponse | `shot_zoom` · `shot_track` · `shot_to` · `shot_reset` · `shot_focus_to` | 코어 `ShotIntentMath`가 이미 있다 |
| Depth | `size` · `size_front/mid/back/close/far/reset` | 프리셋 값은 튜닝에서 온다 |

## 7. 후속 보류 — 곡선 드래그 그래프 에디터

[`motion-graph-orders.md`](motion-graph-orders.md)의 MG1–MG4(마야식 곡선 렌더·끝점
드래그·ease 곡선 드래그+스냅·`@curve`). **슬라이더 UX가 아트 검증을 통과한 뒤**
소유자가 여전히 원하면 착수한다 — 슬라이더로 충분하면 만들지 않는 것이 이득이다.
그 문서의 불변식·시간 모델·외부 초안 정정표는 이 계획의 전제로 계속 유효하다.

## 9. 하지 않을 것

- 패키지화 — 이번엔 아니다. 대신 W64가 **반복 가능한 동기화 절차**를 남긴다.

  스크럽/드래그 중간값의 프로젝트 변경 · 죽은 커맨드의 조용한 삭제/조용한 발행 —
  전부 기존 원칙 그대로다.
- 새 창·새 탭·새 저장 포맷. 편집의 자리는 기존 프리뷰·기존 편집 통로다.

## 10. 후속 트랙 — 연출 프리셋 (2026-08-20 소유자 접수)

액터(@1 등)를 타깃으로 한 커맨드 묶음을 **프리셋으로 저장**해 두고, 쓸 때 액터만 현재
캐릭터/슬롯으로 지정해 불러오는 개념(옛 beat 노드 감각 — 노드 자체는 안 쓴다).
대본 패널의 묶음 경계(무대 대상 단위)가 그 단위의 밑그림이다. 이징 보관함과 같은
복사 계열 설계가 자연스럽다: 프리셋은 프로젝트 자산, 불러오기 = 대상 치환 복사.
범위·저장 위치·UI는 착수 시 설계.
