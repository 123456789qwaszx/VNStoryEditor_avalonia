## 0. 무엇을 만드나 — 한 문장

**간선에 "대사 없는 연출 한 덩어리"를 매달고, 그 간선이 챕터를 끝낼 수 있게 한다.**

두 요구가 같은 기능이었다:

| 누가 | 무엇을 원했나 |
|---|---|
| 팀장 | 특정 에피소드 **사이**의 트랜지션 연출 |
| 소유자 | 엔딩에서 재생할 연출 (대사 없이) |

둘 다 *어떤 길을 탈 때 연출 하나를 재생한다*이다. 엔딩은 거기에 **키가 하나 더** 있는 것뿐이다.

## 1. 합의된 것 (2026-08-18)

| | 결정 | 근거 |
|---|---|---|
| 연출을 매다는 자리 | **간선** | 트랜지션·엔딩이 같은 기능이고, 둘 다 "길을 탈 때" 일어난다 |
| 저작 표면 | 기획자는 **간선 행 하나**에 종류·엔딩키·연출을 함께 적는다 | 엔딩이라는 한 개념이 한 행에 모인다 |
| 계약 표면 | 엔딩키는 **도착 에피소드의 `EndingKey`**로 실린다 | 저쪽 D2("한 곳이 정한다") 유지 · 계약 변경이 `ViaNodeId` 하나로 줄어든다 |
| 연출 참조 이름 | **`ViaNodeId`** | 계약서 §H-3에 이미 있는 이름. 이름이 둘 도는 것이 모호함보다 나쁘다 |
| `OptionDestination` | **필요 없다** | 엔딩 간선도 도착(엔딩 에피소드)이 있으므로 "도착 없는 길"이 안 생긴다 |

> **`ViaNodeId`의 "노드"는 Yarn 노드다** — 에피소드 노드가 아니다. 이 모호함은 이름을
> 하나로 유지하는 값과 바꾼 것이고, 주석으로 못 박는다.

### 저작 표면과 계약 표면이 갈리는 이유

기획자가 보는 그림과 런타임이 먹는 모양은 **다를 수 있고, 여기서는 달라야 한다.**
번역은 이미 하고 있는 일이다(`Int → "Number"`, `AtLeast → "GreaterOrEqual"`).

- **저작**: 엔딩 = 간선의 성질. 한 행에서 다 보인다
- **계약**: 엔딩키 = 도착 에피소드의 것. 시나리오 층이 다음 챕터를 고를 때 쓴다

## 2. `간선` 시트 — v11

### 지금 (v9)

```
출발 · 도착 · 스탯변화 · 선택지 · 표시조건 · 해금조건 · 잠금시 숨김 · 잠금 안내문
```

### v11 — 세 열이 는다

```
출발 · 도착 · 종류 · 스탯변화 · 선택지 · 표시조건 · 해금조건 ·
잠금시 숨김 · 잠금 안내문 · 엔딩키 · 연출
```

| 열 | 값 | 뜻 |
|---|---|---|
| **`종류`** | `선택지` / `자동` — 드롭다운 | **누가 고르나.** 빈칸은 `선택지`와 같다(구판 호환) |
| **`엔딩키`** | 자유 문자열 | 있으면 **이 길이 챕터를 끝낸다.** 유니티가 이 키를 보고 처리한다 |
| **`연출`** | 연출 노드 이름 | 이 길을 탈 때 재생할 **대사 없는 연출**. 비면 없음 |

**축이 둘이다.** `종류`(누가 고르나)와 `엔딩키`(끝나는가)는 **직교**한다 —
넷이 전부 실재한다:

| | 예 |
|---|---|
| 선택지 → 에피소드 | "믿는다" → 다음 화 |
| 자동 → 에피소드 | 말없이 페이드하며 다음 화 |
| 선택지 → 엔딩 | "이대로 떠난다" → 챕터 끝 |
| 자동 → 엔딩 | 마지막 화가 끝나면 자동으로 엔딩 |

`연출`은 세 번째 축이고 넷 어디에나 붙는다.

> ⚠ **`종류`는 `에피소드` 시트의 `종류`(Main/Attachment)와 다른 축이다.** 시트가 다르니
> 열 이름은 그대로 두되, 안내서에 이 구분을 적는다.

### `종류`가 닫는 것 — `ked-progression` D5

지금은 **선택지 문구가 비면 자동 진행**이다. 그래서 *문구를 실수로 지운 것*과
*의도한 자동 진행*이 데이터로 구별되지 않는다. `종류`가 그것을 명시로 만든다:

- `종류=선택지`인데 문구가 비었다 → **오류** ("문구를 지웠거나 종류를 잘못 골랐습니다")
- `종류=자동`인데 문구가 있다 → **오류**

### `에피소드` 시트의 `엔딩키` 열은 폐지한다

같은 사실이 두 곳에 있으면 어긋난다. 엔딩키의 주인은 **간선 하나**가 된다.

## 3. 이행 (구판 → v11)

`ChapterWorkbookMigrator`가 앱이 열 때 한 번에 돌린다(`.bak` 남김) — 구→v5→…→v11.

| 구판 | v11 |
|---|---|
| 간선에 `종류` 열 없음 | 열을 만들고 **문구가 있으면 `선택지`, 없으면 `자동`** |
| 에피소드 행의 `엔딩키` | 그 에피소드로 **들어오는 모든 간선**의 `엔딩키` 칸에 복사한 뒤 열 삭제 |
| 간선에 `연출` 열 없음 | 빈 열만 만든다 |

> **들어오는 간선이 없는 엔딩 에피소드**는 이행에서 키를 잃는다. 그런 에피소드는
> 이미 도달 불가라 검증기가 따로 짚고 있으므로, **경고로 남기고 진행**한다
> (v8에서 부착 에피소드의 관문이 갈 곳을 잃었을 때와 같은 처리다).

## 4. 연출 노드 — 자동 생성

**선례가 있다.** 에피소드를 만들면 대본 워크북이 생기고 그 엑셀노드가 판에 자동으로
선다(`EpisodeSyncService`). 한 층 위에 같은 손놀림을 올린다.

- 간선에 **`엔딩키` 또는 `연출`**이 적히면 → 연출 그래프에 **연출 노드가 자동으로 선다**
- 노드 이름은 툴이 짓고 **간선 행의 `연출` 칸에 적어 넣는다**
  (툴이 챕터 워크북에 쓰는 것은 허용된다 — 불가침은 대본 워크북뿐이다, v4)
- 그 노드의 **내용은 사람이 연출 그래프에서 채운다.** 툴은 자리만 만든다

### 왜 이름을 엑셀에 적어 넣나

간선의 신원은 **(출발, 도착, 문구)**다. 배선을 프로젝트 파일에만 두면 기획자가 문구를
고치는 순간 **조용히 끊어진다.** 같은 행에 이름을 적어 두면 문구가 바뀌어도 살아남는다.

배선이 가리키는 연출 노드가 사라지면 **고아로 세운다** — 말없이 지우지 않는다.

## 5. 검증

### 5-1. 새 규칙

| # | 규칙 | 등급 |
|---|---|---|
| 1 | `종류=선택지`인데 문구가 비었다 | 오류 |
| 2 | `종류=자동`인데 문구가 있다 | 오류 |
| 3 | `종류=자동`인 간선이 한 에피소드에 둘 이상 | 오류 (기존 규칙의 이사) |
| 4 | `엔딩키`가 있는데 도착이 비었다 | 오류 |
| 5 | `연출`이 가리키는 노드가 판에 없다 | 경고 (고아) |
| 6 | 엔딩키가 있는 간선인데 `연출`이 비었다 | **없음** — 연출 없는 엔딩도 정상이다 |

### 5-2. ⚠ 엔딩키 충돌 — 저작 쪽만 잡을 수 있다

> **같은 도착 에피소드로 들어오는 간선들이 서로 다른 `엔딩키`를 가지면 내보내기가
> 거부한다.**

계약 표면에서 엔딩키는 **에피소드 하나에 하나**다. 조용히 하나를 고르면 나머지가
사라지고, **JSON에 도착한 시점에는 이미 키가 하나라 수입기가 볼 수 없다.**

이것은 **검증 소유 경계의 예외**다. 지금까지 "그래프 무결성은 수입 쪽이 정본"이었지만
이 하나는 저작 쪽만 볼 수 있다. `ked-progression`도 같은 이해다.

> **"한 에피소드 = 한 엔딩" 가정**을 깔고 간다. 엔딩마다 대사가 다르니 에피소드가 따로
> 있는 것이 자연스럽고, 깨지면 **에피소드를 하나 더 만드는** 싼 우회가 있다.

## 6. 내보내기 — 저작 → 계약 번역

`ChapterProgressionExporter`:

| 저작 (엑셀) | 계약 (`progression.json`) |
|---|---|
| 간선의 `엔딩키` | **도착 에피소드**의 `EndingKey` · `IsChapterEndingCandidate=true` |
| 간선의 `연출` | 그 `Option`의 **`ViaNodeId`** |
| 간선의 `종류` | 나가지 않는다 — 계약은 `ChoiceLabel` 빈 문자열로 이미 구별한다 |

`종류`는 **저작 쪽 안전장치**이지 런타임 입력이 아니다. 계약을 넓히지 않는다.

⚠ **`ViaNodeId`는 저쪽 `EpisodeOption`에 자리가 생긴 뒤에** 내보낸다. 그전까지 이 칸은
저작·화면에만 살고 JSON에 안 나간다 — 없는 필드를 내면 수입기가 모르는 키를 만난다.

## 7. 화면

**연출 그래프**(둘째 탭)에서 다룬다. 새 탭을 만들지 않는다 — 연출은 연출 그래프에서
만든다는 규칙이 그대로 선다.

- 자동 생성된 연출 노드가 판에 선다. 내용은 사람이 채운다
- **어느 간선에 연출이 비었나**를 보는 목록이 필요하다 — 검증 보고 자리에 세운다

**챕터 그래프**에서는 엔딩 간선이 눈에 보여야 한다(간선 라벨에 엔딩키 표시).

## 9. 안 하는 것

- **앨범** — 엔딩 목록이 곧 앨범이지만, "도달했나"는 플레이어 데이터라 저쪽 G4(세이브)가
  서야 채워진다. 지금은 자리도 만들지 않는다
- **시나리오 그래프** (챕터를 잇는 판) — 엔딩키가 서고 저쪽 `EndingRule`이 실물로 돌아간
  뒤에 본다
- **bool 스탯을 켜는 경로** — 소유자가 "당장은 무시" (별건, `run-log` 참조)
