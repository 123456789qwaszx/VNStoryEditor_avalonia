# 모션 그래프(곡선 드래그 에디터) — 상세 규격 · **착수 보류**

2026-08-20 작성 · 같은 날 소유자 재조정으로 **후속 보류** — 순서의 정본은
[`presentation-refresh-orders.md`](presentation-refresh-orders.md)다(슬라이더 편집이
먼저, 이 곡선 에디터는 슬라이더 UX가 아트 검증을 통과한 뒤 소유자가 여전히 원하면).
단계 번호는 W 계열에서 회수하고 **MG1–MG4**로 둔다 — W 번호는 착수가 정해질 때 받는다.
**§0 불변식 · §0.5 외부 초안 정정표 · §2 시간 모델은 보류와 무관하게 유효하다** —
슬라이더 편집(계획서 W66)도 같은 전제 위에 선다.

**커맨드를 곡선으로 펼쳐 보고, 편집하면 정규 커맨드 텍스트로 다시
접히는** 그래프 편집. 마야 그래프 에디터의 저작 감각을 목표로 하되, **저장 포맷을
발명하지 않는다** — 진실은 언제나 커맨드 텍스트다.

`move_by slot +2u 0u 12fr`은 이미 곡선이다: 시작값 0(직전 폴드 상태), 끝값 +2u,
길이 12fr, 모양 OutCubic. 키 2개짜리 1채널 커브를 텍스트로 적어 둔 것에 불과하다.
그래프 에디터는 이것을 펼쳐 보여 주고, 편집을 역방향으로 사상해 같은 텍스트 자리에
되접는다. **새 실행 단위도, 새 스키마도, StageState 침범도 없다.**

## 0. 설계 요지 (불변)

1. **텍스트가 진실, 그래프는 렌즈.** 어떤 편집이든 결과는 커맨드 텍스트로 접힌다.
   자체 클립·키프레임 포맷을 만들지 않는다. 왕복 무손실이 수용 기준 그 자체다.
2. **재현은 근사가 아니다.** 곡선 평가는 런타임(DOTween)과 수치 등가다(ε = 1e-4).
   심판은 `ease-golden.json`(런타임이 덤프)과 코어 `EaseFunctions`다.
3. **규칙 사본 금지.** 이미 있는 것을 쓴다 —
   duration: `Ked.Presentation.Core/Tokens/DurationToken`(24fps) ·
   unit: `UnitToken`(1u = 기준폭/48 — "40px"는 1920 기준의 파생값이지 상수가 아니다) ·
   텍스트 파싱/조립: `Vn.Authoring/Definition/CommandText` ·
   종점 산수: `MoveByReduction` · 시작값: 폴드(`CoreStageFold`/`StageReducer`) ·
   곡선 모양: 코어 `EaseFunctions`. **이 중 하나라도 다시 구현하면 반려다.**
4. **조용히 버리지 않는다.** 채널 선언이 없는 커맨드는 곡선으로 펼치지 않고
   **미해석 레인**에 원문 칩으로 보인다. 왕복 시 원문·원위치 그대로 나간다.
5. **네 번째 입력 경로다.** 갤러리·텍스트·직접 조작에 이어 그래프 편집도 같은
   `ProjectEditor` 편집 명령으로 수렴한다(ARCHITECTURE §3 수렴 원칙). 되돌리기
   한 번 = 조작 하나. `InputPathEquivalenceTests`에 그래프 경로를 추가한다.
6. **성능 규칙 준수.** 스크럽·드래그 중간값은 렌더만 갱신한다 — 프로젝트 변경도
   `QueueReload()`도 부르지 않는다. 확정(마우스 업)만 편집이다.
7. **셸 규칙 준수.** 우클릭은 소유자 보류. 연출 그래프 탭은 기능 동결이므로
   **그 판에는 아무것도 얹지 않는다** — 이 그래프의 자리는 무대 프리뷰 쪽이다(§5).

### 0.5 외부 초안(`motionlab-orders.md`)에서 계승한 것 / 고친 것

초안 작성자는 의도만 알고 실코드를 몰랐다. 뼈대는 좋아서 계승하고, 코드와 어긋나는
전제는 고쳤다. **어긋난 전제 위에 지은 단계는 순서까지 달라졌다.**

## 2. 시간 모델 — 그래프가 그리는 시간축은 "라인 하나의 배치"다

라인 경계가 상태 경계다(계약 §0.1). 한 라인 앞의 커맨드들은 **한 배치로 동시에
시작**하고, 라인 사이는 사용자 진행 게이트라 고정 타임라인이 아예 없다. 그러므로:

- 그래프의 X축 = **선택한 라인의 배치 내부 시간**(0 ~ 배치 최장 duration). fr 눈금, 초 병기.
- 채널(축)마다 레인 하나. 모든 세그먼트는 t=0에서 시작한다 — 개별 시작 오프셋
  같은 것은 **없고, 만들지 않는다**(그건 런타임에 없는 개념을 툴이 발명하는 것이다).
- 같은 라인·같은 축에 `move_by`가 둘이면 런타임은 두 번째의 `DOKill(true)`가
  첫째를 **즉시 완주**시킨다. 그래프도 그대로 그린다: 첫째는 t=0의 **계단**,
  둘째가 곡선. 예쁘게 이어 그리면 그래프가 거짓말한다.
- `duration <= 0` = 계단(즉시 스냅). 런타임과 같다.
- 시작값은 **직전 라인까지의 폴드 상태**에서 온다 — `StageReducer`가 이미
  `move_by`를 접고 있으므로 같은 것을 읽는다. 종점은 `MoveByReduction`으로
  계산한다 — 재생·정착·그래프가 같은 값을 본다.

여러 웨이포인트("0프레임 키, 12프레임 키, 그다음 키")가 필요해지는 날은 **라인을
나누는 것**이 정답인지, 배치 안 순차 개념을 런타임에 새로 여는 것인지가 소유자
결정이 된다 — 그 전에 툴이 앞서가지 않는다.

## 3. 단계

각 단계가 독립적으로 유용하고, MG1에서 멈춰도 연출 디버깅 도구로 가치가 있다.

### MG1. 채널 선언 + 읽기 전용 곡선 렌더 + 스크럽

**선행**: `ease-open-orders.md` §2·§3·§5 (골든 덤프 · 코어 `EaseFunctions` ·
채널 사상 회신). 코어 이징이 서기 전에 임시 이징을 툴에 넣지 않는다 — 사본 금지.

1. **카탈로그 채널 선언.** `game.definition.json`의 `move_by` 항목에 기계가 읽는
   선언을 더한다 (모양 제안 — 구현에서 다듬되 "선언만이 근거" 원칙은 불변):

   ```json
   "motion": {
     "node": "CharSlot_Track",
     "axes": [ { "param": "x", "axis": "x", "unit": "u" },
               { "param": "y", "axis": "y", "unit": "u" } ],
     "relative": true,
     "durationParam": "duration",
     "defaultEase": "OutCubic"
   }
   ```

   - `defaultEase`는 런타임 스펙 기본값의 **기록**이다(편집 칸이 아니다).
     `parameters`에 ease 칸을 더하는 것은 **런타임 개통 후 MG3에서** 한다 —
     "목록에 뜨는 칸은 채우면 반드시 동작한다"(원칙 2.1)를 어기지 않기 위해서다.
   - 로더 무해성: `motion` 선언이 없는 커맨드는 기존과 완전히 같게 동작한다(테스트).
   - 이름·정규식으로 축을 추측하는 코드는 반려 사유다.

2. **곡선 렌더 + 스크럽.** 선택한 라인에 대해: 좌측 채널 목록(선언에서 파생),
   우측 시간×값 곡선(Avalonia 커스텀 드로잉), 하단 플레이헤드. 스크럽하면 무대
   프리뷰의 해당 슬롯이 `시작값 + (종점-시작값) × EaseFunctions(t)` 위치로 움직인다.
   - Y축 단위 토글 u ↔ px(`UnitToken` 환산).
   - 미해석 레인: `motion` 선언이 없는 그 라인의 커맨드를 원문 칩으로.
   - 스크럽은 렌더만 — 편집·저장·QueueReload 없음(불변식 6).

**수용**: ① 견본 라인(move_by 2개 — 다른 축 + 미해석 1개)이 곡선·계단·칩으로
보인다 ② 스크럽 t의 프리뷰 오프셋 = 코어 평가값(표시 검증 테스트) ③ 골든 대조 —
`EaseFunctions` 대 `ease-golden.json` 전 샘플 < 1e-4 (VnTool 쪽에서도 픽스처로
고정 — 사본 코어가 낡는 사고를 이 테스트가 잡는다) ④ 로더 무해성 테스트.

### MG2. 끝점 드래그 → 텍스트 왕복

- 세그먼트 **끝점 세로 드래그** = delta 변경(u 스냅, Shift 미세) ·
  **가로 드래그** = duration 변경(fr 스냅).
- 확정 시 `CommandText` 조립으로 그 커맨드의 **해당 인자만** 바뀐 텍스트가
  `ProjectEditor`의 기존 커맨드 수정 통로를 지난다. 다른 라인·다른 인자 불변.
- ease는 이 단계에서 **건드리지 않는다**(드롭다운도 아직 — 실을 자리가 없다).
- undo 1회 = 드래그 1회 원복.

**수용**: ① 드래그 → 텍스트의 해당 인자만 변한다(불변 라인 고정 테스트)
② undo 원복 ③ `InputPathEquivalenceTests`에 그래프 경로 추가 — 같은 편집을
텍스트로 했을 때와 발행 결과 동일 ④ 무편집 왕복: 열고 닫기만 하면 텍스트 불변.

### MG3. ease 편집 — 곡선 드래그 + 표준 스냅

**선행**: `ease-open-orders.md` §4 (`move_by` 다섯째 인자 개통). 개통 확인 후
카탈로그 `parameters`에 ease 칸을 추가한다(후보 토큰 = 골든 덤프의 목록).

- 1단: 세그먼트 몸통 드래그 → 표준 Ease 전 항목과의 오차(샘플 RMS)를 실시간 계산
  → 최근접으로 스냅. 후보를 고스트로 미리 보이고, 확정 시 텍스트의 ease 인자 갱신.
  드롭다운 직접 선택 병행.
- 기본값과 같으면 다섯째 인자를 **생략**해 내보낸다(기존 대본과의 최소 diff).
- 스냅 오차가 임계 이상이면 **"표현 불가"를 명시**하고 최근접으로 스냅하되 오차를
  보인다(조용한 근사 금지). 이 사례 로그가 MG4 결정의 증거 목록이 된다.

**수용**: ① 합성 곡선 → 의도한 enum 스냅(고정 테스트) ② 출력 텍스트에 enum 이름
③ 기본값 생략 규칙 테스트 ④ 표현 불가 사례가 로그로 남는다.

### MG4. (보류) 커스텀 커브 탈출구 `@curve`

MG3의 표현 불가 사례가 실제로 쌓이기 전에는 **착수 금지.** 쌓이면: 커브를 D층
프리셋으로 저장하고 커맨드가 `@key`로 참조, 런타임은 `@` 접두에서 커브 평가로
분기하는 지점 하나. 그 전까지 런타임 변경 0.
