# Phase 2c + 저작 편의 지시서 — 툴 안 실시간 재생과 갈래 인식 (W31–W36)

2026-08-06 작성. 소유자 지시: **두 트랙 모두 진행한다.** 근거:
[architecture-decisions.md](../handoff/architecture-decisions.md) **H-5**(유니티와의 계약은 Text뿐,
수용 기준은 툴 안) · **H-2**(무대 상태 계산은 코어 한 벌) · Phase 2b 완료(소유자 수동 확인 2026-08-06).

## 0. 설계 전제

- **H-5가 2c의 모양을 정한다.** 유니티의 시간 모델(DOTween 이징·코루틴 타이밍)을 재현할
  의무가 없다 — 목표는 "런타임과 같은 재생"이 아니라 **"작가가 흐름을 확인하기 좋은 재생"**이다.
  트윈은 단순 보간이면 충분하고, 이징이 다르다고 실패가 아니다.
- **상태는 코어, 시간은 툴.** 각 라인의 확정 상태는 지금처럼 `CoreStageFold`(코어 리듀서)가
  계산하고, 재생은 그 **정지 프레임 사이를 보간**하는 층이다. 코어에 시간을 넣지 않는다 —
  코어 복사본 수정 없이 전부 툴 쪽 층으로 만든다(H-4).
- **재생 상태는 저장하지 않는다**(원칙 E: 계산은 저장하지 않는다). 재생 위치·속도는
  뷰 상태이고 프로젝트 파일에 닿지 않는다.
- **시간 규약**: 커맨드 duration 토큰은 코어 `DurationToken`으로 해석하고,
  **1fr = 1/24초**로 환산한다(툴 재생용 근사 — H-5). 환산은 한 곳에만 둔다.
- 갈래 인식(트랙 B)은 리듀서 밖의 "어떤 라인을 먹일지 고르는 층"이다(§6.4) —
  두 트랙은 서로 독립이라 어느 쪽을 먼저 해도 된다.

## 트랙 A — Phase 2c: 툴 안 실시간 재생

목표 화면: 프리뷰(도킹·분리 창)에서 **[▶ 재생]**을 누르면 현재 노드의 라인이 처음부터
자동으로 흐른다 — 대사가 타자기로 찍히고, 캐릭터가 위치·크기로 미끄러지듯 움직이고,
등장/퇴장이 페이드되고, 라인이 자동으로 넘어간다. 클릭 한 번이면 그 라인을 즉시 완성하고
다음으로 넘어간다(비주얼노벨의 진행 입력 그대로).

### W31 — 재생 골격: 재생 컨트롤 + 라인 자동 진행 ✅ 완료 (`bb4a310`, 746 테스트)

`StagePlayback` 순수 진행 모델(테스트 8종) + 도킹/분리 창 공용 컨트롤 행 + 재생 중
무대 클릭=즉시 다음. 체류 = 1.4초 + 글자당 0.045초(상한 6초). 끝에서 ▶ = 처음부터.

> 세션 프롬프트:
>
> W31을 수행해줘. 근거: phase2c-playback-and-authoring.md §0·§W31.
>
> 목표: 프리뷰에 재생 루프의 뼈대를 만든다. 이 단계는 **보간 없이** 라인 경계 상태를
> 순서대로 넘기는 슬라이드쇼다 — 시간 축과 UI 자리를 먼저 세운다.
>
> 작업:
> 1. 재생 컨트롤: 프리뷰(도킹 패널·분리 창 공용 — 사본 금지)에 [▶ 재생/⏸ 일시정지]·
>    [⏮ 처음부터]·진행 표시(현재 라인 n/전체). 재생 중에는 선택 라인이 따라 움직인다
>    (기존 라인 선택 갱신 경로 재사용 — 재생용 별도 상태 경로를 만들지 않는다).
> 2. 라인 자동 진행: 라인당 머무는 시간 = 기본값(예: 대사 길이 비례 + 최소값) —
>    타자기(W32)가 오면 "타자 완료 + 여운"으로 바뀐다. 시간의 원천은 UI 타이머 하나.
> 3. 진행 입력: 재생 중 무대 클릭 = 이 라인 즉시 완료 → 다음 라인. 일시정지 중 클릭은
>    기존 조작(조절창)이다 — 재생 중에는 조작 대신 진행이 우선임을 상태로 분명히 한다.
> 4. 재생이 끝(마지막 라인)에 닿으면 멈추고 [⏮]로 돌아갈 수 있다.
>
> 수용 기준 (사람 시나리오):
> - "라인 여러 개인 노드에서 ▶를 누르면 라인이 순서대로 자동으로 넘어가고, 프리뷰
>   무대가 각 라인의 확정 상태로 바뀐다. 클릭하면 즉시 다음 라인으로 간다.
>   ⏸ 후 조절창 조작이 기존처럼 동작한다."
> - 재생 로직은 뷰와 분리된 순수 진행 모델(테스트 가능)로 두고 단위 테스트를 붙인다
>   (진행·일시정지·클릭 스킵·끝 도달).
>
> 커밋은 W31 단위로.

### W32 — 타자기 + 진행 입력 완성 ✅ 완료 (`4b92a28`, 748 테스트)

라인 3단계(타자 30자/초 → 여운 1.2초 → 다음), 타자 중 클릭=전문·그 뒤=다음, 선택지
라인은 클릭 대기. 타자는 대사창 텍스트 한 곳만 갱신(전체 재렌더 없음). 속도 설정화는 W34 백로그.

> 세션 프롬프트:
>
> W32를 수행해줘. 선행: W31. 근거: phase2c-playback-and-authoring.md §W32.
>
> 목표: 대사창 텍스트가 글자 단위로 찍힌다 — 비주얼노벨의 체감을 결정하는 축이다.
>
> 작업:
> 1. 타자기: 재생 중 LineText를 글자 단위로 노출. 속도는 툴 설정(문자/초, 기본값 상식선)
>    — 게임별 데이터가 아니라 툴 편의 설정이다(작가의 확인 속도지 게임 사양이 아니다).
> 2. 진행 입력 규칙 완성: 타자 중 클릭 = 전문 즉시 표시, 타자 완료 후 클릭 = 다음 라인.
>    자동 진행은 "타자 완료 + 여운 시간" 뒤에만.
> 3. 선택지 라인: 옵션 제시 화면에서 자동 진행을 멈추고 클릭을 기다린다. 갈래 인식(W35)
>    전에는 어느 옵션을 눌러도 문서 순서 진행(현재 근사 그대로) — 뱃지가 그 사실을 말한다.
>
> 수용 기준: 타자·스킵·여운·선택지 정지의 진행 모델 단위 테스트 + 수동 확인 1회.
>
> 커밋은 W32 단위로.

### W33 — 전이: 정지 프레임 사이 보간 ✅ 완료 (`bdde1ef`, 758 테스트) — 트랙 A 지시 범위 종료

슬롯 자리 lerp·새 등장 페이드 인·배경 크로스페이드. 전이 시간 = 라인 duration 최댓값
(코어 DurationToken, **24fps 규약** — §0의 1fr=1/60초 가정을 코어 확인으로 정정), 기본 0.35초·상한 1초.
클릭 1차 = 전이+타자 완료, 2차 = 다음. 일시정지·정지는 확정 상태 그대로.

> 세션 프롬프트:
>
> W33을 수행해줘. 선행: W31. 근거: phase2c-playback-and-authoring.md §0(H-5 근사 허용)·§W33.
>
> 목표: 라인이 넘어갈 때 무대가 끊기지 않는다 — 이전 라인의 확정 상태에서 다음 라인의
> 확정 상태로 **보간**한다. 코어가 낸 두 정지 프레임 사이를 툴이 잇는 것이지,
> 커맨드별 트윈의 재구현이 아니다.
>
> 작업:
> 1. 보간 대상: 초상 rect(위치·크기), 가시성(알파 페이드 — 등장/퇴장), 샷(줌·팬),
>    배경 교체(크로스페이드). 전부 선형 보간이면 충분하다(H-5).
> 2. 보간 시간: 라인의 커맨드 duration 중 최댓값을 코어 DurationToken으로 읽어 쓰되
>    (1fr=1/60초, §0), 없으면 기본 전이 시간. 상한을 둬서 저작 확인이 느려지지 않게 한다.
> 3. 진행 입력(클릭)은 보간도 즉시 완료한다.
> 4. 일시정지·정지 시에는 지금처럼 확정 상태(정지 프레임)만 보인다 — 기존 화면 불변.
>
> 수용 기준: place 이동·size 변경·등장/퇴장·배경 교체가 재생 중 부드럽게 이어지는 수동
> 확인 + 보간 계산(시작/끝/중간값·스킵)의 단위 테스트. 재생 정지 상태의 기존 테스트 불변.
>
> 커밋은 W33 단위로.

### W34 — (후속 백로그, 이번 범위 아님)

특정 라인부터 재생, `[adv/]` 마커 그룹 재생, `#main_free` 대기, 재생 속도 배율,

## 트랙 B — 저작 편의

### W35 — 갈래 인식 프리뷰 ✅ 완료 (`e64e4d6`, 755 테스트)

`BranchFlow`(대본·발행 공용 분석) + `StageBranchSelection`(뷰 상태, LineId 키).
옵션 클릭=갈래 선택(재생 중이면 곧장 진행), 갈래 칩 순환(갈래→건너뜀→근사), 커서 갈래
우선, 스탯 HUD 갈래 기준. PassedBranchApproximation = "미선택 갈래 있음"의 정확한 뜻이 됐다.

> 세션 프롬프트:
>
> W35를 수행해줘. 근거: phase2c-playback-and-authoring.md §W35, phase2-design-brief.md §6.4
> (갈래 인식은 리듀서 바깥 — 어떤 라인을 먹일지 고르는 층), known-issues K10 자리.
>
> 목표: 조건·선택 갈래가 있는 노드에서 프리뷰가 "문서 순서로 전부 적용" 근사 대신
> **작가가 고른 갈래**를 접는다. 스탯 HUD(X3)도 같은 갈래 선택을 따른다.
>
> 작업:
> 1. 갈래 선택 층: `MiniStageFold.LinesUpTo`가 있는 자리에 "갈래 필터"를 만든다 —
>    선택지 블록마다 어느 옵션을 탔는지, 조건 갈래는 참/거짓 어느 쪽인지의 선택 상태.
>    선택은 뷰 상태다(저장하지 않는다 — 원칙 E).
> 2. UI: 프리뷰의 선택지 제시 화면에서 **옵션을 클릭하면 그 갈래로 접는다**(현재는 표시만).
>    조건 갈래는 라인 목록/프리뷰에서 갈래 배지를 클릭해 토글. 현재 어떤 갈래 조합을
>    보고 있는지 표시가 남는다.
> 3. `PassedBranchApproximation`(문서 순서 근사) 뱃지는 "선택 안 한 갈래가 있는" 경우에만
>    남는다 — 전부 골랐으면 근사가 아니라 실제 그 갈래의 상태다.
> 4. 스탯 HUD: 선택 갈래 기준의 `<<set>>` 누적으로 바뀐다(문서 순서 근사 은퇴).
> 5. 재생(W31+)과 만나면: 재생 중 선택지에서 클릭한 옵션이 곧 갈래 선택이 된다.
>
> 비범위 유지: MixedChain(조건 갈래 안 선택지)·`<<else>>`·중첩 조건은 여전히 유효하지 않은
> 구성/미지원이다 — 이 단위는 "지원하는 구성의 갈래를 고르는 것"이지 문법 확장이 아니다.
>
> 수용 기준: 갈래 필터의 단위 테스트(옵션 선택별 라인 집합·스탯 누적) + 사람 시나리오
> "선택지에서 B를 클릭하면 B 갈래의 무대·스탯이 보이고, A로 바꿔 보면 화면이 바뀐다".
>
> 커밋은 W35 단위로.

### W36 — (후속 백로그, 이번 범위 아님)

저작 편의 추가 후보: 라인 목록에서 갈래 트리 표시, 조건 값 시뮬 입력(변수 슬라이더로
"이 값이면 어느 갈래인가"), 노드 간 이어 재생. W35 뒤 소유자와 정한다.

## 진행 순서

두 트랙은 독립이다. 기본 순서는 **W31 → W32 → W35 → W33** — 재생 뼈대와 타자기로
"흐름 확인"이 먼저 서고, 갈래 인식이 재생의 선택지 정지(W32-3)와 맞물리는 시점에 들어와
클릭-갈래 연결(W35-5)까지 한 번에 닫는다. 전이(W33)는 마지막 광택이다.
소유자가 순서를 바꾸면 그쪽이 우선한다.
