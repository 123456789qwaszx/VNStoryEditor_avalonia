## 0. 한 줄 목표

**시나리오 그래프의 챕터 판이 챕터 그래프와 같은 구도로 읽힌다** — 엑셀노드 사이에 간선이
처음부터 이어져 있고, 간선 위에 선택지 문구·조건·스탯변화가 보이며, 작가의 자유 씬은
그 간선 위에 매달린 연출로 읽힌다:

```
[시작에피소드] ──[ 라루를 믿는다 · trust +1 ]──▶ 자유씬1 ─ 자유씬2 ─▶ [EP01]
              ──[ (진행) ]──────────────────────────────────────────▶ [EP02]
```

## 1. 전제 — 이미 성립해 있는 것들 (이 계획이 새 데이터를 만들지 않는 근거)

| 전제 | 어디서 성립했나 |
|---|---|
| 옵션 ↔ 챕터 간선은 **라벨로 짝**이다 | 검증기 라벨 짝 규칙 (2f9691a) — "이 간선에 씬을 단다" = "그 라벨의 옵션에 배선한다"와 동치 |
| 자유 노드의 길 = 다른 자유 노드 or 에피소드 종료 | 출구 규칙 (323a21b) — 엑셀노드로 못 가므로, 간선에 매달린 체인은 반드시 그 간선 안에서 끝난다 |
| 간선 = 유일한 스탯 변화 지점 | 간선 스탯변화 (4dc55a7) — "자유 씬은 고정된 전이 위의 연출"이 구조적으로 참 |
| 배선 데이터 = `BranchExits`(옵션별) + `DefaultExitTargetNodeId` | 기존 모델 — **T 단계는 이 데이터를 바꾸지 않는다. 그리는 방법만 바꾼다** |
| 챕터 모델은 챕터 그래프 뷰가 읽은 것 하나 | `ChapterGraphView._entries` + `EntriesReloaded` 이벤트 — 두 곳이 따로 읽지 않는다 (챕터 데이터 패널 때 세운 원칙 그대로) |

## 2. 의미론 확정 (그리기 전에 못 박는 규칙)

| # | 규칙 | 근거 |
|---|---|---|
| T-R1 | 미러 간선의 원천은 **챕터 워크북의 간선 시트**다. 시나리오 그래프는 읽기만 한다 — 간선의 문구·조건·스탯변화 편집은 챕터 그래프/엑셀에서 | 소유권 분할 (G-2 v3.1). 편집 창구가 둘이면 어긋난다 |
| T-R2 | 간선 포트의 대상 = **라벨 짝 옵션 + 기본 진행(무라벨 간선)**뿐 | 라벨 짝이 유일한 대응 규칙이다 |
| T-R3 | `IN`으로 안에서 해소되는 옵션은 간선에 **안 붙는다** — 보드에도 안 나온다 | 내부 구간은 엑셀 안의 콘텐츠다 (G-4) |
| T-R4 | 간선이 없는 라벨 옵션(= 에피소드 종료)은 **종료 스텁 간선**에 붙는다 | 안 이은 옵션 = 에피소드 종료 (Gate B). 타임라인이 끊기지 않아야 한다 |
| T-R5 | 자유 씬 체인의 실행 의미는 **불변**: 옵션 → 자유 씬들 → (출구 없음 =) 에피소드 종료 → 챕터가 간선대로 전이 | T는 시각 재배치이지 실행 모델 변경이 아니다. 발행·이미터·런타임 무변경 |
| T-R6 | 미러 간선과 툴 배선 선은 **한 층**으로 합쳐 그린다: 간선의 경로가 곧 배선된 체인을 지나는 경로다 | "간선에 데이터를 담는 게 아니라 시각적 타임라인" — 선이 두 벌이면 타임라인이 아니다 |

## 3. 단계

### T1 — 간선 미러 + 철도 배선 (읽기 전용) · 반나절~1일

> **(2026-08-15 개정 — 소유자 철도 노선 그림 + 외부 시각 조언 문서 반영.)** 원안의
> "간선 중앙에 칩(문구·조건·스탯변화)"을 폐기하고 아래로 바꾼다. 조언 문서의 핵심 장치
> 하나는 **기각**한다: "선택지의 Line 비율을 간선 길이에 투영"은 우리 규격과 충돌한다 —
> `CHOICE`는 **파일 맨 끝 0~1개**(§3.2 마지막 라인 특별취급, Gate B의 전제)라 선택은
> 항상 에피소드 끝이고, 초반/중반/후반이라는 정보가 존재하지 않는다. 대신 조언 문서
> §4(같은 지점 세로 묶음)가 우리 현실에서 **항상 참**이며, 그것이 곧 철도 그림이다.

**무엇**: 시나리오 그래프의 펼친 챕터 판에서, 챕터 간선을 **직교(철도) 배선**으로 그린다 —
출발 카드에서 수직 줄기가 내려오고, **단일 분기점**에서 옵션 가지들이 세로로 갈라져
도착 카드로 수평 진입한다. 가지 위 칩:

- 기본 표시 = **선택지 문구만** (`● 라루를 믿는다`, 무라벨 진행은 무표식 직행선).
  스탯변화·조건은 기본 화면에 **안 보인다** — 시나리오 그래프는 작가가 흐름을 읽는
  화면이고, 수치는 챕터 그래프의 책임이다.
- **칩 클릭 = 읽기 전용 상세 플라이아웃** (조건라벨 · 스탯변화 · 잠금 안내문 —
  기존 Flyout 패턴 재사용). 배선·편집은 없다(T2).
- 카드에 대사 줄 수(`42 lines`) 표기, 대본 없는 에피소드는 대시 테두리.

**어떻게**
- `MainWindow`: `ChapterGraph.EntriesReloaded → Graph.SupplyChapters(entries)` 배선
  (기존 `EntriesReloaded → RebuildFileList` 옆에 한 줄). `GraphEditorView`가
  `IReadOnlyList<ChapterEntry>`를 들고 다시 그린다.
- 매칭: 판 `StoryFile.Name == ChapterId` (EnsureChapterBoard 규약) · 노드
  `DialogueNode.ExcelEpisodeId == episode.EpisodeId`.
- 그리기: `GraphEditorView`의 챕터 프레임(`DrawChapterFrames`) 옆에 `DrawChapterEdges` —
  카드 뒤·프레임 앞 z순서. 칩만 히트 대상(클릭 상세).
- 짝이 안 맞는 간선(도착 엑셀노드가 판에 없음 = 아직 동기화 전)은 **긋지 않는다** —
  없는 것을 그리면 거짓말이다. 동기화가 노드를 세우면 따라 나타난다.

**수용**: ① 챕터 그래프에서 간선을 잇고 [다시 읽기] → 시나리오 그래프에 철도 배선이 선다
② 기본 칩에는 문구만 — 스탯변화·조건 문자열이 캔버스 기본 상태에 없다 ③ 칩 클릭 →
읽기 전용 상세(조건·스탯변화) ④ 챕터 없는 판(일반 프로젝트)은 아무 변화 없다
⑤ 배선 데이터·발행·이미터·런타임 불변.

**테스트**: 헤드리스 — 견본 챕터 동기화 후 판에 간선 수만큼 미러 배선, 같은 출발의
옵션 가지들이 같은 분기점 X를 공유, 기본 칩 텍스트에 `trust`가 **없음**, 클릭 상세에
있음, 비챕터 판은 0개.

### T2 — 포트 이사 · 1일

**무엇**: 옵션 포트(배선 진입점)를 엑셀노드 카드에서 떼어 **짝 간선의 칩**으로 옮긴다.
칩 클릭 = 그 옵션의 자유 씬 배선 플라이아웃(대상 자유 노드 콤보 + 해제) — 내부는 기존
`SetExitTarget(Branch, 옵션 줄 LineId, …)` / 기본 진행 칩은 `SetExitTarget(Default, …)`
그대로. 간선 없는 라벨 옵션은 종료 스텁 간선(T-R4)을 그려 같은 칩을 단다.

**어떻게**
- 칩 → 옵션 대응: 엑셀노드 대본에서 `OpensOption` 줄 중 텍스트가 간선 라벨과 정확 일치하는
  것 (라벨 짝 규칙 재사용 — 대응 코드를 새로 발명하지 않는다).
- 카드의 기존 옵션 포트 그리기는 챕터 판에서만 제거(일반 프로젝트 카드에는 그대로).
  `DialogueNodeEditor`의 출구 편집 UI는 유지 — 같은 데이터의 다른 창구이고, T-R5로 의미가
  같다.
- 배선된 체인(자유 씬)이 있으면 간선 경로가 체인을 경유해 그려진다(T-R6) — 배치는 아직
  작가 드래그 그대로, 선만 경유.

**수용**: ① 칩에서 자유 노드를 골라 배선 → `BranchExits` 반영 + 선이 체인을 경유한다
② 해제하면 간선이 직행으로 돌아온다 ③ 유령 간선(라벨 짝 없음)은 칩이 비활성 + 기존
검증 오류가 그대로 선다 ④ 안 이은 옵션의 스텁에 배선하면 "씬 후 에피소드 종료"가 된다.

**테스트**: 칩 배선 → `BranchExits` 왕복, 스텁 배선, 유령 간선 비활성, 기본 진행 칩 →
`DefaultExitTargetNodeId`.

### T3 — 타임라인 배치 · 1일

**무엇**: 챕터 판의 배치를 레이아웃이 소유한다 — 엑셀노드는 챕터 그래프와 **같은 깊이
레이아웃**(`ChapterBranchPlanner.Layout` 재사용)으로 서고, 간선에 배선된 자유 씬 체인은
그 간선 경로를 따라 자동 배치된다. 배선 안 된 자유 노드만 드래그가 남는다.

**어떻게**
- 엑셀노드 좌표: 판을 그릴 때마다 `ChapterBranchPlanner.Layout(chapter)`를 시나리오 그래프
  축척으로 투영 (챕터 그래프와 같은 구도 = 두 화면이 같은 지도).
- 체인 좌표: ~~간선의 출발·도착 사이를 균등 분할~~ **(2026-08-15 소유자 개정)** 클립
  간격은 고정이고 **간선이 내용만큼 길어진다** — 타임라인은 내용이 많으면 길어지는 것이
  자연스럽다. 겹침 회피는 행 분리(챕터 레이아웃의 빈 행 규칙 재사용).
- 배선 안 된 자유 노드: 기존 `Layout` 좌표·드래그 유지 (작업대 위의 자재).

**수용**: ① 챕터 그래프와 시나리오 그래프의 에피소드 구도가 같다 ② 배선하면 체인이 간선
위로 이동하고, 해제하면 원래 자리로 돌아온다 ③ 배선된 노드 드래그는 무시되거나 비활성
(열린 결정 T-D1) ④ 접기/펼치기·FitFile이 그대로 동작한다.

## 6. 위험

- **T2의 칩↔옵션 대응이 라벨 정확 일치에 걸려 있다** — 라벨을 엑셀에서 고치면 배선이 칩에서
  떨어져 보인다(데이터는 남음). 검증기의 라벨 짝 오류가 이미 이 어긋남을 잡으므로 신규
  장치는 안 만들되, 칩 없는 배선을 "떠 있는 배선" 표식으로 보인다.
- **T3는 되돌리기 쉬운 순서로** — T1·T2만으로도 소유자 목표의 대부분(이어져 보임 + 간선
  중심 배선)이 성립한다. T3가 실사용에서 어색하면 T2 상태로 멈출 수 있게 커밋을 나눈다.
