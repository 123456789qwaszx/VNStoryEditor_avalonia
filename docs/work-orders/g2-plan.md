# G2 계획 — 에피소드 워크북 리더 + 평평화

D10에 따라 승인 대기 없이 쓰고, 아래 **자기 반려 점검**을 스스로 통과시킨 뒤 구현에 들어간다.
규격 정본은 `chapter-graph-orders.md` §3.2~§3.4다. 이 문서는 그 규격을 **어떻게** 실행할지만 말한다.

## 0. 무엇을 만드는가

```
에피소드 워크북(11열)  →  EpisodeWorkbookModel  →  검증(§3.3 6규칙)  →  평평화  →  X11 문법 텍스트
```

산출 텍스트는 **기존 파서가 이미 아는 문법**이어야 한다. 새 문법을 만들지 않는다.

## 1. 모델 — 행을 유형으로 읽는다 (G2-a)

`유형`(C열)이 행의 정체를 정하고, 나머지 열의 의미가 거기서 갈린다.

| 유형 | LineId | 갖는 것 | 라인인가 |
|---|---|---|---|
| (빈칸) 대사 | 있음 | 태그·화자·내용·스탯변화 | **그렇다** — 연출·세이브 타깃 |
| `IF` | **없음** | 조건라벨·IN | **아니다** (소유자 확정) |
| `CHOICE` | 있음 | — | 그렇다 |
| `OPTION` | 있음 | 조건라벨·IN·내용(라벨) | 그렇다 |

행 유형 판정은 **한 곳**에 둔다(`EpisodeRowKind.Of(...)`). 규약 사본 금지 — 평평화·검증·G5가
같은 판정을 쓴다.

`인덱스`(A열)는 **문자열이 아니라 정수**로 읽는다. `IN`/`OUT`이 이 값으로 서로를 가리키므로
비교 가능해야 한다. 정수가 아니면 오류(자동 보정 금지).

## 2. 구간과 §3.3 강제 규칙 6개 — 각각 어디서 잡는가 (G2-b)

구간은 인덱스 범위가 아니라 **태그 한 쌍**으로 정해진다. 먼저 태그를 훑어 구간 목록을 만들고,
그 위에서 규칙을 친다.

```
SectionTable = { 시작인덱스 → Section(StartRow, EndRow, OutTarget) }
```

| # | 규칙 | 잡는 자리 | 진단 |
|---|---|---|---|
| 1 | `IN=X`면 인덱스 `X`에 `INPUT`이 있어야 | `SectionTable` 조회 실패 | `IN` 셀(F열)을 짚어 "인덱스 X에 INPUT 태그가 없습니다" |
| 2 | `INPUT`엔 짝 `OUT`이 반드시 | 구간 테이블 조립 중, `INPUT` 이후 다음 `INPUT`/파일 끝까지 `OUT`이 없으면 | `INPUT` 행의 태그 셀(D열) |
| 3 | 구간 = `INPUT`~`OUT` **양끝 포함** | 규칙이 아니라 **정의**다. 구간 조립이 이대로 하면 위반이 발생할 수 없다 | — |
| 4 | 한 `INPUT`을 둘 이상이 가리키면 오류 | `IN` 수집 시 **소유자 표**(구간→가리킨 행) 조립, 둘째부터 오류 | 나중에 가리킨 `IN` 셀 + 먼저 가리킨 행 번호 |
| 5 | 구간 안 중첩 `IN` 금지 | 구간 범위 안의 행에 `IN`이 있으면 | 그 `IN` 셀 |
| 6 | `OUT` 대상이 자연 수렴 지점이어야 | **평평화 후** 대조 (§4) | `OUT` 셀(G열) + 계산된 실제 수렴 지점 |

**규칙 3을 "구현하지 않는" 것이 옳다.** 양끝 포함은 구간의 정의이지 검사 대상이 아니다 —
검사로 만들면 정의와 검사 두 곳에 같은 규약이 생긴다(규약 사본 금지). 수용 기준의 "6개가 각각
오류로 잡힌다"는 규칙 3에 대해서는 **정의대로 포함됨을 고정하는 테스트**로 갚는다.

추가로 잡는 것(§3.2·D6):
- `CHOICE` 블록은 **파일 맨 끝에 0개 또는 1개**. 중간에 있거나 둘 이상이면 오류.
- `IF` 행에 LineId가 있으면 오류(라인이 아니다).
- 대사·`OPTION` 행에 LineId가 없으면 → 오류가 아니라 **신규 행**으로 다룬다(§5).
- **옵션별 `OUT`이 서로 다른 비-`END` 인덱스로 갈리면 v1 오류**(D6). `$__ch_N` 승격은 범위 밖.

## 3. 평평화 (G2-c) — `IN`을 가진 자리로 구간을 **옮긴다**

```
주 흐름 = 어떤 구간에도 속하지 않는 행들을 인덱스 오름차순으로

IF 행      →  <<if {라벨의 조건식}>>
                  구간 행들 (원위치에서 사라진다)
              <<endif>>

OPTION 행  →  -> {라벨}
                  구간 행들 (옵션 본문으로)
```

**복제가 아니라 이동이다.** 규칙 4가 한 구간의 소유자를 하나로 강제하므로 각 행은 산출물에
**정확히 한 번** 나온다 → LineId 전역 유일성(계약서 C1)이 구조적으로 지켜진다. 이것이
"평평화 산출물에 같은 대사가 두 번 나오지 않는다"(Gate B 2번)의 증명이고, 테스트로도 고정한다.

**`<<if>>` 조립은 `YarnSyntax.AppendCondition`을 쓴다.** 자기 문자열 연결 금지 — 이미 Preview·
이미터가 공유하는 조립기가 있고, 평평화는 그 **세 번째 소비자**가 된다(지시서 G2 ⚠).
`internal`이므로 같은 어셈블리(`Vn.Authoring`) 안에 둔다.

**조건식의 출처는 챕터 워크북 `조건` 시트다**(G-7). 에피소드는 라벨만 적는다. 따라서 평평화는
`ChapterGraphModel`(또는 라벨→식 표)을 입력으로 받는다. 미정의 라벨은 오류.

**스탯변화(J열)**는 이번 산출에서 `<<set>>`으로 내지 않는다 — Tier 1 누적 → 에피소드 끝 1회
환산이 규격이고(§0), 그 환산의 저작 위치는 **기존 툴의 대사노드**다(D1). G2는 스탯변화를
모델에 **읽어 싣기만** 하고 G7(도달성)이 소비한다. 산출 텍스트에 넣으면 즉시 반영이 되어
§0의 트랜잭션 성질이 깨진다.

## 4. `OUT`은 "수렴 지점의 선언"이다 — 검증기가 무엇과 대조하는가

Yarn에는 **노드 안의 줄 단위 goto가 없다.** 그래서 `OUT=34`는 명령으로 번역되지 않고
"평평화하면 자연히 34로 흐른다"는 **주장**이 된다. 검증기는 그 주장을 계산 결과와 맞춰 본다.

대조 방법 — 평평화 산출을 만들 때 각 구간에 대해 **자연 후속 인덱스**를 함께 계산한다:

| 구간을 부른 자리 | 자연 후속 = |
|---|---|
| `IF` 행(인덱스 i) | `<<endif>>` 다음에 오는 것 = **주 흐름에서 i 다음 행의 인덱스** |
| `OPTION` 행 | 선택 블록이 끝난 뒤 = **`CHOICE` 블록 다음 주 흐름 행의 인덱스**. 그런 행이 없으면 `END` |

`선언한 OUT ≠ 계산된 자연 후속`이면 오류. 메시지에 **둘 다** 적는다:
"`OUT=34`라고 적혀 있지만 평평화하면 40으로 흐릅니다".

이 대조는 **평평화 결과 위에서** 한다. 원본 행 순서로 계산하면 구간이 옮겨진 뒤의 흐름을
못 보고, 그게 정확히 `OUT`이 막으려는 착오다.

`OUT=END`는 "여기서 에피소드가 끝난다"는 선언이고, 자연 후속이 없을 때만 참이다.

## 5. LineId — 텍스트 경계에서 잃지 않는다 (G3-1 이행)

**정본 표기는 Yarn 접미형 `#line:ln_0001`**(D8). 평평화 산출의 각 대사·옵션 줄이 이 태그를 단다.

```
윌로: 복도는 생각보다 조용했다. #line:ln_0001
```

**출력 프리셋은 엑셀 경로 전용으로 새로 둔다**(D9). `ScenarioOnly`는 사람이 읽는 화면이라
`includeLineId: false`가 옳고, 거기에 ID를 켜면 저작 화면이 지저분해진다. 새 프리셋은
표기를 새로 만들지 않고 `YarnSyntax`·기존 포맷터를 공유한다.

**파서 확장** — `ScenarioTextParser`가 줄 끝의 `#line:{id}`를 **떼어내 신원으로 돌려준다**.
현재는 그 태그가 대사 본문에 그대로 남아 매 왕복 내용 비교가 어긋난다(세션 0 선조사).
떼어낸 ID는 `ScenarioLine.LineId`로 실려 `ScriptSynchronizer`에 넘어간다.

**동기화는 ID 일치로 매칭한다.** ID가 있는 줄은 내용 추정 경로를 타지 않으므로
`Ambiguous`가 **구조적으로 발생하지 않는다**. 그래도 발생하면 통째 거부 + 원인 행 목록(규칙 14).

**LineId가 없는 행**(기획자가 새로 타이핑한 줄)은 태그 없이 나가고 `ScriptSynchronizer`가
새 ID를 발급한다. 그 ID를 **엑셀 B열에 되써야** 다음 왕복에서 신원이 유지된다 —
§3.2가 B열을 "툴 소유"로 정한 이유다. **되쓰기는 G5의 일**이고 G2는 발급된 ID를 결과에 담아
넘기기만 한다. G2에서 엑셀에 쓰지 않는다.

## 6. G3가 X11/X12 파서를 재사용하는 코드 경로

새 임포터를 만들지 않는다는 것의 증명은 이 한 줄이다:

```
평평화 텍스트
  → ScenarioTextParser.Parse            (X12a 파서. #line: 분리만 추가)
  → ScriptSynchronizer.Plan             (X12a diff. ID 일치 매칭)
  → ProjectEditor.ApplyScenarioText     (기존 적용 경로. 전량 재생성 없음)
  → DialogueNode                        (조건 = ConditionDefinition{Name=라벨, Expression=식})
```

`ApplyScenarioText`는 이미 이 셋을 잇고 있다(`ProjectEditor.Scripts.cs:66`). G3는
**엑셀 출처 텍스트를 같은 입구에 먹이는 일**이지 새 경로를 내는 일이 아니다.

조건 부착 지점은 `<<if>>` **아래 첫 대사 줄**이고, 그 줄이 `BranchExits`가 말하는
"갈래를 여는 줄"이 된다 — 양쪽 모델이 어긋나지 않는다(지시서 §1).

**W47 대응(G3-2)**: 행을 지우면 그 줄이 소유하던 조건·선택 전환·`set`·갈래 출구가 함께 접힌다.
동작은 유지하되 **행별 목록과 배지로 보고**한다.

## 7. Tier 1 네임스페이스 접두 (D2)

기본은 `$__ep_`. 기존 `$__ch_N`(선택 전환 체인)과 접두가 겹치지 않고, 계약서 §D의 선언 규약도
`<<declare>>` 자동 출력이라 이름만 다르면 충돌하지 않는다. **붙이는 주체는 이미터**이며
브리지가 접두로 거둘 것을 추측하는 것은 여전히 금지다(브리지는 명시 목록만 왕복).

G2 범위에서는 접두를 **쓰지 않는다** — 산출 텍스트에 `<<set>>`이 없기 때문이다(§3).
접두는 대사노드 쪽 이미터가 Tier 1 변수를 낼 때의 규약이므로, 실제 적용은 그 이미터를 건드릴 때다.
여기서는 문자열만 확정해 둔다.

## 8. 자기 반려 점검 — 착수 전 확인

| 반려 조건 | 이 계획은 |
|---|---|
| 붙여넣기·동기화에서 라인 전량 재생성 | **아니다.** `ScriptSynchronizer.Plan`을 그대로 쓴다 |
| 구간 인라인 복제 | **아니다.** 이동이고, 규칙 4가 소유자를 하나로 강제한다 |
| 새 텍스트 임포터 작성 | **아니다.** §6의 네 단계가 전부 기존 코드다 |
| 라인을 위치(행 번호)로 매칭 | **아니다.** `#line:` ID가 신원이다 |
| 그래프 뷰가 엑셀에 쓴다 | **아니다.** G2는 어디에도 쓰지 않는다 |
| `<<if>>`를 `YarnSyntax` 밖에서 조립 | **아니다.** §3에 못박았다 |
| 브리지가 접두로 추측 | **해당 없음.** G2는 브리지를 만지지 않는다 |
| 조건 파서·경로 조립·행 유형 판정이 두 곳에 | **아니다.** 조건 파서는 `ConditionExpressionParser` 하나, 행 유형 판정은 `EpisodeRowKind` 하나 |
| 해석 못 한 행을 보고 없이 넘김 | **아니다.** 모든 거부·미해석이 파일·시트·행·열 진단이 된다 |
| 기존 대사·연출 그래프 코드 수정 | **아니다.** 손대는 기존 코드는 `ScenarioTextParser`의 `#line:` 분리 하나뿐이고, 그건 X12 경로를 **더 옳게** 만든다(사람이 붙여넣은 태그도 신원이 유지된다) |

→ **통과. 구현에 들어간다.**

## 9. 착수 순서와 커밋

1. **G2-a** 리더 + 모델(행 유형·구간 테이블) + §3.3 규칙 1·2·4·5 + §3.2 구조 검증
2. **G2-b** 평평화 + `OUT` 자연 수렴 대조(규칙 6) + D6 옵션 분기 오류
3. **G2-c** `#line:` 표기와 엑셀 전용 출력 프리셋
4. **G3** 파서 확장(`#line:` 분리) → `ApplyScenarioText` 연결 + G3-2 보고
5. **G5** 클릭→엑셀 열기·파일 감시·LineId 되쓰기·동기화 보고 패널

완료 조건은 **Gate B 6항목**이다.
