# 에피소드 그래프 뷰 — 협업 문서 정리와 현황 대조

원본: `에피소드 그래프 뷰.pdf` (11장, 소유자 작성, 협업자 공유용 중간 보고).
이 문서는 그 내용을 글로 옮기고, **지금 코드가 실제로 어디까지 와 있는지**를 장별로 대조한다.
주말 "워크플로우 관통" 작업의 기준 문서다.

기준 시점: 2026-08-14, 테스트 997 통과.

## 1. 원문이 말하는 것 (장별 요약)

### 1장 — 실제 제안 형태
- 한 파일 안에 여러 에피소드, 각 에피소드는 하나의 xlsx
- 노드를 클릭하면 엑셀이 열린다

### 2장 — 구조 예시 / 데이터 정규화
예시 구조의 특징 다섯: ① 화자와 대사 라인 ② 엑셀 자체의 인덱스 사용
③ 인덱스 단위 In-Out으로 `goto` 구현 ④ Spine·BGM·간단한 연출을 엑셀로 컨트롤
⑤ xlsx 파일 + 인덱스로 간편한 QA 디버거

**핵심 지침 4개**
1. 툴 내부에서 대사 편집 금지 (엑셀 기능이 강력하고 유지보수가 편하다)
2. 파일별 에피소드 묶음 = **챕터**
3. 챕터 내 에피소드 그래프에서 노드 클릭 → 엑셀 열기
4. 조건 분기·선택지·스탯 밸런스 기획과 **시나리오 대본 테이블을 분리**

### 3장 — 에피소드 그래프 형태도
- 별도의 그래프 뷰를 현재 툴에 추가
- 그래프는 엑셀 데이터를 토대로 **자동 생성**(드래그 불가)
- 변수·조건은 엑셀에서 기획자가 미리 정해 두고 **그것만** 사용
- 왼쪽에 챕터 목록, 각 챕터는 하나의 파일 단위
- 그래프 안에서 **챕터 단위 박스가 에피소드들을 감싼다**
- **챕터를 접으면 표 형태로 바뀌고**, `엔딩`만 다른 챕터의 시작 에피소드와 선으로 연결

### 4장 — 변수·조건 계층 분리 (A/B)
| | A 계층 | B 계층 |
|---|---|---|
| 정체 | 2~5개 플레이어 스탯 | 툴 내부 조건 노드에서 정의 |
| 범위 | 에피소드 개방·잠금에만, 시나리오에 노출 안 됨 | 특정 에피소드 안에서만 |
| 소유 | 기획자·프로그래머(사전 정의, 시스템·UI 연동) | **시나리오 작가**(직접 만들고 뗌) |
| 예 | 보석량, 클리어 횟수, 호감도, 엔딩 해금 | 다쳤음·음식·삽·만난 횟수 |
| 변환 | — | **반드시 A로 환산해 반영** (에피소드 종료 시 결산) |

**이유**: 작가가 뭘 하든 게임이 안 깨진다 → 겁먹지 않고 만들고 버릴 수 있다 → 퀄리티가 올라간다.

### 5장 — 그래프 뷰 데이터 명세
`에피소드` 시트 11열(A EpisodeId 필수 … K 메모)과 `간선` 시트 6열(출발·도착 필수 …).
말미: *"이 데이터들은 엑셀로 저장되며, 툴로 편집.(실시간 동기 x. 저장 및 불러오기)"*

### 6장 — 작업 흐름
1. 기획자가 툴에서 에피소드 그래프를 만든다 → 에피소드 추가 시 xlsx 생성 → 엑셀에
   챕터·에피소드·간선 입력 → 자동으로 그래프가 그려짐(위치 편집 불가)
2. 에피소드 클릭 시 엑셀이 열린다
3. 엑셀에서 대사를 편집하면 **실시간 반영**. 툴은 **읽기전용**(엑셀 → 툴 단방향)

### 7장 — 형태 예시 (스크린샷)
챕터 / 그래프 뷰 / 대사(읽기 전용). 특정 에피소드 클릭 시 대본 엑셀이 열리고,
편집한 것이 실시간 반영된다.

### 8장 — 대본 엑셀 (예시)
**"테이블 구조 미결, 상의 필요함"** — 문서 전체에서 유일하게 명시된 미결 사항.

### 9장 — 시나리오 그래프(임시)
- 에피소드 그래프 뷰에서 챕터·에피소드 제작, 엑셀에서 대본과 조건·선택지 라벨 작성
- 시나리오 그래프에는 **좌측 목록의 챕터가 전부 표시**되고, 에피소드는 **챕터 단위 박스**로 감싸짐
- 챕터 체크 해제 시 **표 형태로 접힘**

### 10장 — 시나리오 그래프 (엑셀노드)
- **엑셀노드**: 빈 포트를 가지며 대본은 편집 불가
- 엑셀에서 사전 정의한 **A 계층 변수·조건·선택지로 외부 포트를 뚫어 둔다**
- 그 포트에 **커스텀 대본(자유 노드)** 을 연결. 커스텀 쪽 조건·변수는 작가가 직접 설정
- **대사 본문은 Excel만, 출구는 VN Tool이 소유**
- 예: 엑셀이 `choice1: 조조를 믿는다 / choice2: 유비를 믿는다`를 선언 → 툴에서
  `조조를 믿는다 → HappyRoute`, `유비를 믿는다 → Route2`로 배선 (각 루트는 10~20줄 규모)

### 11장 — 화면 흐름 예시 / 왜 이런 구조인가
- `Day1_아침` ExcelNode(150줄) → Line78에서 조건·선택지 분기 `{호감도 >= 30}` →
  Yes/No 각각 **Special(작가 자유 노드)** → 다시 본류 → `Day1_저녁` ExcelNode(86줄)
- ExcelNode: 클릭하면 대사는 볼 수 있지만 수정 불가. **이어지지 않은 포트는 에피소드 종료**
- CustomNode에서 되는 것: 대사 추가 · **B 계열 조건 추가** · B 계열 조건을 활용한 Choice 추가 ·
  **B 계열 변수 Set**
- 기존 `A→B→C→D`에서 `A→B→Custom01→C→D`, 조건부 `B→(Condition=true)Custom01→C`,
  선택지 `B→(Choice a=Custom_A / b=Custom_B)→C` 등 자유 조합

**왜**: 엑셀은 대량 대사에 강하나 그래프 구조 파악·조건 편집·연출에 약하다. 유기적인 게임은
작은 수정이 전체에 파급되므로 **변수를 제한하고 정적인 환경**을 만들어야 하고(에피소드 그래프
뷰의 존재 이유), 동시에 작가에게는 **자유 실험 공간**이 있어야 한다.
→ **작가 혼자서 10줄 이벤트를 넣고, 호감도 조건을 걸고, 선택지를 하나 넣고, 직접 본 뒤
마음에 안 들면 빼는 것을 개발자를 한 번도 안 부르고 할 수 있어야 한다.**

## 1-b. 전체 흐름 — 두 탭이 순차적 무대다 (소유자 구두 보강, 2026-08-14)

원문의 장들이 이 순서를 전제하고 있다. 문서에 명시돼 있지 않아 따로 적는다.

```
[1단계 · 에피소드 그래프 탭]  주인: 기획자
  챕터·에피소드·간선을 툴에서 클릭으로 입력 → 그래프 자동 생성
        ↓ 에피소드 클릭
  대본 엑셀에서 대사 작성 + 선택지·조건 라벨 붙이기
  (조건은 기획자가 미리 정리해 둔 A 계층 라벨을 드롭다운으로 가져다 씀)
        ↓ 저장하면 툴이 실시간으로 읽어 감
  ─────────── 여기까지 완성되어야 다음 단계로 ───────────
        ↓
[2단계 · 시나리오 그래프 탭]  주인: 시나리오 작가
  시작 상태: 챕터가 박스로 있고, 그 안에 에피소드가 ExcelNode로 서 있다
             (ExcelNode = 읽기 전용, 포트만 열려 있음)
        ↓
  작가가 조건 노드로 B 계층 변수·조건을 자유롭게 만들고
  대사 노드를 추가해서 ExcelNode의 포트에 연결
        ↓
  연출 뷰어에서 실시간으로 보면서 느낌을 확인
```

**두 탭의 역할이 다르다**: 1단계 탭은 **구조를 굳히는 곳**(기획자 소유, 드래그 불가),
2단계 탭은 **살을 붙이는 곳**(작가 소유, 자유 배치). 같은 데이터를 다른 각도로 보는 것이
아니라 **작업 단계가 다르다**.

그래서 **"챕터 박스 + ExcelNode"는 장식이 아니라 2단계 작업의 무대 그 자체다.**
이것이 없으면 작가는 자기 대사 노드를 어디에 붙여야 하는지 알 수 없다.

## 3. 문서 내부의 어긋남 3건 (수정본에 반영할 것)

### ① "실시간 동기 x"(5장) ↔ "실시간 반영"(6·7장)
두 장이 같은 단어를 반대로 쓴다. **사실**: 둘 다 파일 저장 단위로 실시간이다(감시 0.25초).
데이터에 따라 방향만 다르다.

> **정정 문구(안)** — "파일을 저장하는 순간 반영된다(0.25초). 구조 데이터는 툴↔엑셀 양방향,
> 대본은 엑셀→툴 단방향이다. 클라우드 동기화를 거치면 그 앱의 내려받기 지연이 더해진다."

### ② "툴 내부에서 대사 편집 금지"(2장) ↔ 스크린샷의 '대사 편집' 탭(7·9장)
설계는 맞는데 화면이 오해를 만든다. 중간 보고에서는 **"합의와 다르게 만들어졌나"** 로 읽힌다.

> **정정 문구(안)** — 스크린샷 캡션에 *"본문은 읽기 전용. 편집은 엑셀에서."* 한 줄.
> 그리고 실제로 **16번(배지 + 잠금)을 구현**해야 화면과 문서가 같은 말을 한다.

### ③ 소유권이 흩어져 있다
누가 무엇을 쓰는지가 2·5·6·10장에 조금씩 나뉘어 있다. **앞쪽에 한 장짜리 표**로 박으면
①②가 한 번에 해소된다.

| 대상 | 원본(쓰는 쪽) | 툴에서 |
|---|---|---|
| 대사 본문·화자·스탯변화 | **엑셀 대본** | 읽기 전용 |
| 에피소드·간선·조건 라벨 | **엑셀 챕터** (툴도 셀 단위로 씀) | 편집 가능 |
| 노드 위치 | **툴이 계산** | 드래그 불가 |
| 출구·연결·자유 노드 | **툴** | 편집 가능 |
| A 계층 스탯의 존재 | `game.definition.json` | 읽기 전용(값 범위는 엑셀) |

> **참고**: 4장의 "X·Y는 툴이 계산"은 옛 지시서(G-2: 엑셀 X·Y가 원천)와 어긋났었는데,
> **규격 `chapter-graph-orders.md`의 G-2를 v3로 이미 개정**해 두었다(2026-08-12).
> 문서와 코드가 같은 말을 하고 있으니 추가 조치는 필요 없다.

## 4. 규격상 **안 되는 것** (협업자에게 미리 알릴 목록)

중간 보고의 값어치는 "이건 됩니다"보다 **"이건 안 됩니다"** 를 지금 알리는 데 있다.
아래는 작가·기획자가 당연히 될 것으로 여기기 쉬운데 v1 규격이 막아 둔 것들이다.

| 안 되는 것 | 이유 | 대신 |
|---|---|---|
| 에피소드 **중간**에 선택지 | 선택지 블록은 파일 **맨 끝에 0개 또는 1개** | 에피소드를 둘로 쪼갠다 |
| 조건 **안에 조건**(중첩 구간) | 평평한 표에서 `INPUT`/`OUT` 짝이 모호해짐 | 구간을 나란히 둔다 |
| 선택지 옵션마다 **다른 출구**(에피소드 내부) | 자연 낙하로 동시에 만족 불가 → v1 오류 | 옵션별 분기는 **챕터 간선**으로 |
| `>` `<` `!=` 조건 | 런타임에 없는 비교를 만들지 않기 위해 | `>=` `<=` `==` 셋 |
| 소수점 스탯 | 경계값 버그 차단 + 도달성 증명의 유한성 | 정수 |
| 줄 **사이**로 되돌아오는 자유 노드 | Yarn에 노드 안 goto가 없다 | 에피소드를 쪼개 그 경계로 |
| 스탯이 챕터를 넘어 유지 | **런타임 미구현** (21번) | 결정 필요 |

> 11장의 `A→B→Custom01→C→D`는 **에피소드 경계에서** 성립한다. 한 엑셀 파일 안의 78번째
> 줄에서 툴 노드로 나갔다가 79번째 줄로 돌아오는 형태는 불가능하다 — 그 지점에서 에피소드를
> 나누면 같은 그림이 된다. 이건 도구의 한계가 아니라 Yarn 실행 모델의 성질이다.

## 5. 주말 관통 작업 (우선순위)

목표: **2단계 탭(작가의 무대)을 세운다.**
`챕터 박스 안의 ExcelNode → 포트 → 작가의 CustomNode → 연출 뷰어 확인`

| 순서 | 작업 | 규모 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | **ExcelNode 배지 + 대사 편집 잠금** (16) | 반나절 | 없으면 툴에서 고친 대사가 다음 동기화에 증발한다. 문서 모순 ②도 함께 해소. **모든 후속의 전제** |
| 2 | **포트 개통 — 선택지 출구** (17·19) | 1~2일 | 연결할 대상이 없으면 2단계 자체가 성립 안 함. "안 이은 포트 = 에피소드 종료" 규칙 확정으로 Gate B 반칸도 함께 풀린다 |
| 3 | **챕터 박스 그루핑** (14·15) | 1일 | **2단계의 무대.** 작가가 어느 ExcelNode가 어느 챕터인지 봐야 붙일 곳을 정한다 |
| 4 | **조건 자동 공급 + 가드레일** (18·20) | 1일 | 자유 노드가 A 조건을 바로 쓰고, A 스탯에 Set 걸면 경고(도달성 증명이 장님이 되지 않게) |
| 5 | 챕터 접기 → 표 형태 (14b) | 반나절 | 박스가 선 뒤의 편의 |

**정직한 규모 판정**: 1~4를 합치면 3.5~4.5일치다. 주말 이틀에는 안 들어간다.
**관통(end-to-end 시연)만이 목표라면 1→2→4가 최소 경로**이고, 3(챕터 박스)은 한 챕터만
보이는 현재 화면으로도 시연이 가능하다 — 다만 **작가에게 실제로 넘기려면 3이 반드시 필요**하다.
관통 시연과 인계는 다른 완성도라는 것을 구분해서 잡는 편이 안전하다.

**주말 이후 남는 것**: 21번(런타임 Tier 2 영속화)은 이 저장소 밖의 작업이라 별도 세션이
필요하다. 그 전까지 A 계층 조건은 **한 챕터 안에서만** 참이다 — 협업자에게 이 한 줄은
반드시 전달돼야 한다.

## 6. 문서를 다시 보낼 때 얹을 것 (권고)

중간 보고로서 이 문서에 없는 것은 **"어디까지 됐는지의 경계"** 하나다. 스크린샷이 있으면
받는 사람은 보이는 것을 전부 "지금 되는 것"으로 읽는다. 세 가지만 더하면 된다:

1. **각 화면 옆에 한 단어** — 되는 것 / 만드는 중 / 아직. 특히 '시나리오 그래프(임시)'는
   *디자인이* 임시인지 *동작이* 임시인지 구분되게.
2. **§4의 "안 되는 것" 표** — 나중에 발견되면 "왜 미리 말 안 했냐"가 되는 목록.
3. **막혔던 것과 우회 방법 세 개** — Yarn에 줄 단위 goto가 없어서 구간 이동으로 푼 것,
   도달 불가를 막으려고 전수 탐색을 넣은 것, 클라우드 2-writer 충돌을 단일 writer로 푼 것.
   요청받지 않은 판단을 얼마나 했는지가 여기서 드러난다.
