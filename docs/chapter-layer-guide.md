# 챕터 레이어 사용 안내

챕터(에피소드 구조·분기·조건)를 만드는 층의 사용법입니다. 대사 한 줄 한 줄을 쓰는
[작가 가이드](writer-guide.md)와는 다른 층입니다 — **작가 가이드는 대사 그래프(시나리오 그래프 탭),
이 문서는 챕터 그래프 탭**을 다룹니다.

기준 시점: 2026-08-12 (챕터 v2 8단계, 테스트 979 통과).

---

## 0. 먼저 알아야 하는 것 하나

**엑셀이 원본입니다.** 툴에서 하는 편집(드래그·패널·＋분기)은 전부 **엑셀 셀에 즉시 저장**되고,
저장 감시가 그 파일을 다시 읽어 화면이 따라옵니다. 화면이 원본이 되는 순간은 없습니다.

그래서 이런 성질이 따라옵니다:

- 엑셀에서 파일을 열어 놓고 있으면(잠김) 툴이 **쓰지 않고 사유를 알려 줍니다.** 반쯤 쓰인
  워크북은 생기지 않습니다.
- 툴 편집에는 **Ctrl+Z가 없습니다.** 대신 파괴적인 쓰기(에피소드·간선 삭제)는 직전 상태를
  `{파일}.bak`으로 굴려 남깁니다. 실수하면 `.bak`을 `.xlsx`로 되돌리면 됩니다.
- 대량(대사)은 엑셀에서, 소량(구조·조건·스탯 2~5개)은 툴에서 — 이게 이 층의 설계 의도입니다.

## 2. 파일이 어디 있는가

```
{프로젝트 폴더}/
├─ project.vnproject.json      ← [열기…]로 여는 것
├─ chapters/{챕터Id}.xlsx      ← 챕터 워크북 (구조·분기·조건)
├─ episodes/{에피소드Id}.xlsx  ← 에피소드 워크북 (대본)
└─ exported/{챕터Id}.progression.json   ← [내보내기]의 결과
```

챕터·에피소드 워크북은 **툴이 만들어 줍니다.** 직접 만들 필요는 없지만, 열어서 고치는 것은
정상적인 사용법입니다(대사는 오히려 엑셀에서 쓰는 게 맞습니다).

## 3. 화면

**[챕터 그래프] 탭** (시나리오 그래프 탭 옆).

- **왼쪽** — 챕터 목록. 챕터 하나 = 판 하나(1:1). 에피소드 수와 오류(⚠)가 보입니다.
  - 클릭 = 그 챕터로 전환 · **우클릭 = 이름 바꾸기** · **[＋] = 새 챕터**(Id는 사람이 정합니다)
  - 챕터 삭제는 없습니다 — 워크북 파일 삭제는 되돌릴 수 없어 툴이 대신하지 않습니다.
    지우려면 [폴더 열기]로 사람이 지웁니다.
- **가운데** — 그래프 판. 카드 = 에피소드, 선 = 간선.
  - `ROOT` 파란 칩 = 시작 에피소드(`에피소드` 시트의 **첫 행**) · `🔒` = 표시/해금 조건 있음 ·
    `★` = 엔딩 · `⚠` = 오류 또는 도달 불가
- **오른쪽** — 속성 패널. 선택한 것에 따라 [에피소드] 또는 [간선]이 열립니다. 아래에는
  항상 [조건 (라벨 ↔ 식)]이 있습니다.
- **위 툴바** — 챕터 콤보 · [다시 읽기] · [폴더 열기] · [내보내기] · [＋ 에피소드] ·
  **[깊이 정렬]**(시작에서의 깊이대로 열을 세움 — 명시 동작, 누르기 전 배치는 .bak으로 남음) · 픽스처 콤보
- **아래** — [검증 보고]. 오류가 있으면 저절로 펼쳐지고 머리글에 건수가 섭니다.

## 4. 조작 문법 (그래프 판)

| 하고 싶은 것 | 방법 |
|---|---|
| 에피소드 선택 | 카드 **클릭** → 오른쪽 속성 패널 |
| **대본 쓰러 가기** | 카드 **더블클릭** → 그 에피소드 엑셀이 열립니다(없으면 규격대로 만들어서 엽니다). .xlsx의 기본 앱이 스프레드시트가 아니면(예: 엑셀 미설치) 열지 않고 폴더에서 파일을 보여 주며 사유를 알립니다 |
| 위치 옮기기 | 카드 **드래그** → 놓는 순간 그 행의 X·Y 셀에 저장. 끄는 동안 간선이 따라옵니다 |
| 간선 편집 | **간선 또는 그 라벨을 클릭** → 오른쪽 간선 패널 |
| 선택 풀기 | 판의 **빈 곳 클릭** |

오른쪽 단추로는 드래그가 시작되지 않고, 더블클릭이 이동과 겹치지 않습니다.

## 5. 작업 흐름

### ① 챕터 만들기

왼쪽 [＋] → 챕터 Id(예: `ch06`) → `chapters/ch06.xlsx`가 규격대로 생기고 판이 열립니다.
`스탯` 시트는 `game.definition.json`의 변수로 채워집니다(읽기전용 미러 — 원천은 그쪽입니다).

### ② 분기 짓기 — 이 층의 핵심

1. 출발점 카드를 클릭합니다(처음이면 `ROOT`).
2. 오른쪽 **[다음 에피소드]** 칸에 **새 분기 Id**를 적고, 선택지 라벨(예: "라루를 따라간다")을
   적은 뒤 **[＋ 분기]**.
3. 새 에피소드가 **부모 깊이 + 1 열의 빈 줄**에 서고 간선이 이어집니다. 열은 시작
   에피소드에서의 깊이가 정하므로 다른 부모의 자식과 겹치지 않고, 합류(두 분기가 다시
   만남)는 가장 깊은 부모 다음 열에 서서 간선이 뒤로 꺾이지 않습니다.
   행 추가와 간선 연결이 **한 번의 저장**이라 절반만 성공하는 일이 없습니다.
4. 부모 선택이 유지되므로 **분기를 연달아** 만들 수 있습니다.

이미 있는 에피소드로 잇는 것(합류·순환)은 아래 **[연결]**입니다.

> 자동 배치는 **새 노드의 첫 자리 제안**일 뿐입니다. 기존 노드는 절대 저절로 움직이지
> 않고, 이후 자리는 드래그로 사람이 정합니다. 배치가 어지러워지면 **[깊이 정렬]**을
> 누르세요 — 도달 가능한 노드 전부가 깊이 열로 서고, 누르기 전 배치는 .bak에 남습니다.

### ③ 조건 걸기

조건은 **라벨 ↔ 식** 표에 한 번 등록하고, 여기저기서 **라벨로만** 부릅니다.

1. 오른쪽 아래 **[조건 (라벨 ↔ 식)]** 에 라벨(예: `신뢰높음`)과 식(`trust >= 3`)을 적고
   **[조건 추가/수정]**. 같은 라벨이면 수정입니다.
2. **간선을 클릭** → 조건 콤보에서 그 라벨을 고르고,
   - **잠기면 숨김** 켜기 = 조건 미달이면 선택지 자체가 안 보임
   - 끄기 = 잠긴 채 보이고 **잠금 안내문**이 뜸(예: "신뢰가 부족하다")
3. **[적용]**.

에피소드 자체의 **표시조건/해금조건**은 카드를 선택해 속성 패널에서 겁니다.

### ④ 대본 쓰기

카드를 **더블클릭**하면 그 에피소드 엑셀이 열립니다. 저장하면 툴이 자동으로 읽어
대사 노드에 반영하고, 새 줄에는 LineId를 되써 줍니다(B열).

### ⑤ 검증하고 내보내기

아래 [검증 보고]가 자동으로 돕니다. 구조 오류뿐 아니라 **도달성 증명**이 돌아서,
"어떤 경로로도 이 노드에 닿을 수 없다"를 **원인 조건까지 지목**해서 말해 줍니다.

의도적으로 닿을 수 없는 노드(미완성·폐기 예정)는 속성 패널의 **[도달불가 허용]** 을 켜면
오류가 알림으로 낮아집니다.

**[내보내기]** → `exported/{챕터Id}.progression.json`. **검증 오류가 있으면 파일을 만들지 않고**
사유를 보고 패널에 세웁니다. 픽스처는 테스트 데이터라 내보내기에 섞이지 않습니다.

## 6. 엑셀 규격 요약

### 챕터 워크북 — `chapters/{챕터Id}.xlsx` (5시트)

| 시트 | 내용 |
|---|---|
| `에피소드` | EpisodeId · 제목 · 인덱스 · 종류 · 대사엔트리 · **X · Y** · 표시조건 · 해금조건 · 엔딩키 · 메모 · (도달불가 허용) |
| `간선` | 출발 · 도착 · 선택지 라벨 · 조건 · 잠금시 숨김 · 잠금 안내문 — **행 하나 = 선택지 하나** |
| `조건` | 라벨 · 조건식 · 설명 |
| `스탯` | 스탯키 · 표시명 · 초기값 · 최소 · 최대 (2~5행) — **읽기전용 미러**, 원천은 `game.definition.json` |
| `픽스처` | 픽스처명 · 활성 · 스탯 초기값 · 고정 선택 — 재생루트 확인용, **내보내기 제외** |

- **시작 에피소드 = `에피소드` 시트의 첫 행**입니다(시트에 시작 열이 없습니다).
- `간선`의 선택지 라벨이 비면 분기 없는 일반 진행입니다.

### 에피소드 워크북 — `episodes/{에피소드Id}.xlsx` (11열)

| 열 | 이름 | 누가 쓰나 |
|---|---|---|
| A | `인덱스` | 사람 — **10·20·30 방식**(행 번호가 아닙니다) |
| B | `LineId` | **툴** — 손대지 마세요 |
| C | `유형` | 빈칸=대사 / `IF` / `CHOICE` / `OPTION` |
| D | `태그` | `INPUT` / `OUT` |
| E | `조건라벨` | 챕터 `조건` 시트의 라벨 |
| F | `IN` | 들어갈 구간의 인덱스 |
| G | `OUT` | 나갈 목적지 인덱스 또는 `END` |
| H · I | `화자` · `내용` | 대사 본문 / OPTION 라벨 |
| J | `스탯변화` | `trust +1; anger -1` — 정수만 |
| K | `메모` | |

## 7. 조건식 문법 — 정확히

```
trust >= 3           스탯 비교
anger <= 0
trust == 5
cleared:main05.02    그 에피소드를 클리어했는가
A ; B                AND (세미콜론)
```

**쓸 수 있는 연산자는 `>=` · `<=` · `==` 셋뿐입니다.** `>`나 `<` 하나짜리도, `!=`도 받지 않습니다 —
런타임에 없는 비교를 저작 시점에 통과시키면 게임에서 깨지기 때문입니다.

- **값은 정수만.** 소수점은 거부됩니다(`2.5 >= 3` 같은 경계값 버그를 원천 차단).
- **`스탯` 시트에 없는 키는 오류**입니다. 툴이 오타를 비슷한 이름으로 고쳐 주지 않습니다.

## 8. 구간 (INPUT / OUT)

에피소드 안에서 조건·선택지가 "어디로 들어갔다 어디로 나오는지"를 태그로 적습니다.
구간의 경계는 인덱스 범위가 아니라 **태그 한 쌍**입니다.

```
31  OPTION   IN=900     "옵션1 라벨"
32  OPTION              "옵션2 라벨"
34  (대사)                      ← 수렴 지점
…
900 (대사)   태그=INPUT         ← 구간 진입
…
908 (대사)   태그=OUT  OUT=34   ← 구간 종료 + 나갈 곳

실행:  31 → 900 … 908 → 34
```

검증기가 막는 것: `IN=X`면 X행에 `INPUT`이 있어야 함 · `INPUT`엔 짝 `OUT`이 반드시 있어야 함 ·
한 `INPUT`을 둘 이상이 가리키면 오류 · **구간 안에 또 `IN` 금지(중첩 금지)** ·
`OUT` 대상은 평평화 후 **자연히 그리로 흐르는 자리**여야 함.

> `OUT`은 "거기로 점프하라"가 아니라 **"평평화하면 자연히 거기로 흐른다"는 선언**입니다.
> 검증기가 실제로 그런지 대조해서 어긋나면 오류를 냅니다.

`CHOICE` 블록은 **파일 맨 끝에 0개 또는 1개**만 올 수 있습니다.

## 9. 툴이 거부하는 것 (그리고 그 이유)

| 상황 | 툴의 반응 |
|---|---|
| 엑셀이 그 파일을 열고 있음 | 쓰지 않고 사유 보고 — 반쯤 쓰인 워크북을 만들지 않기 위해 |
| `cleared:` 참조가 있는 에피소드를 개명 | **거부.** 조건식은 사람 소유라 툴이 고쳐 주지 않습니다 — 시트를 먼저 고치세요 |
| 검증 오류가 있는 채로 내보내기 | 파일을 만들지 않고 사유 전체를 보고 |
| 없는 스탯키·소수점·미지원 연산자 | 오류. 자동 교정하지 않습니다 |

간선 끝점과 픽스처의 고정 선택은 개명 시 **자동으로 따라갑니다**(안 따라가면 유령이 되므로).
