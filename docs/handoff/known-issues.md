## 🔴 K1. 라이브 출력이 낡은 파일을 지우지 않는다

**증상**: 노드 이름을 바꾸거나 노드를 지워도 출력 폴더의 이전 `Story_옛이름.yarn` 3종이 남는다.
번들 이름이 노드 이름에서 나오므로(`YarnBundleEmitter.SanitizeNodeName`) 새 이름으로 파일이 하나 더 생길 뿐이다.
**근거**: `YarnBundleEmitter`에 파일 삭제 경로가 없음(코드 확인). `LiveOutputService`는 쓰기만 한다.
**영향**: 유니티가 폴더를 통째로 읽으면 **없어진 노드의 옛 대사가 그대로 재생될 수 있다.** 선언 파일 합집합도 낡은 변수를 포함한다.
**해결 방향(미확정)**: ① 라이브 출력 폴더를 VnTool 전용으로 선언하고 매 저장 시 관리 대상 파일을 회수(위험 — 사용자 파일 삭제) ② 매니페스트를 함께 써서 낡은 파일을 화면에 "고아"로 보여 주기(규칙 14와 정합, 삭제는 사용자가) ③ 번들 이름을 노드 이름이 아니라 노드 Id로.
**소유자 판단 필요** — ①은 파일을 지우는 동작이라 임의로 만들지 않았다.

## 🟡 K4. ScenarioOnly 붙여넣기로 선택지를 만들 수 없다

**설계상 비범위**: 파서가 `->` 라벨을 "해석 못 한 줄" 목록으로 보낸다. 선택 전환은 붙여넣기가 **건드리지 않고 보호**한다(테스트로 고정).
**영향**: 선택지가 있는 대본을 통째로 붙여넣으면 라벨 줄이 빠진 채 들어오고, 선택 구조는 UI로 따로 만들어야 한다.
**의도**: 선택지는 `OptionId` 안정성·C3 순서 경고가 걸려 있어 텍스트 왕복을 함부로 열지 않았다.
**해결 방향**: 라벨 문법(`-> 텍스트`)을 파서 어휘에 넣고 `OptionId`를 diff로 잇는 별도 설계가 필요하다 — 소유자 요청 시 착수.
