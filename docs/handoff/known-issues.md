## 🟡 K1. 라이브 출력이 낡은 파일을 지우지 않는다 — **보이게 만듦** (T3, ②안)

**증상(그대로)**: 노드 이름을 바꾸거나 노드를 지워도 출력 폴더의 이전 `Story_옛이름.yarn`이 남는다.
번들 이름이 노드 이름에서 나오므로(`YarnBundleEmitter.BundleNameOf`) 새 이름으로 파일이 하나 더 생길 뿐이다.

**T3에서 한 것**: 낡은 파일을 **고아 출력**으로 화면에 올린다 — 상태줄 요약(앞 3개 + 나머지 개수)과
[양식…] 플라이아웃의 전체 목록. 판정 기록은 출력 폴더의 `.vntool-output.json`(`OutputManifest`)이고,
기록이 없는 폴더에서도 이름 형식(`Story_`/`Set_`/`Pres_`/`declarations.yarn`)으로 찾아내되
"(기록 없음)"으로 구분한다. 기록을 읽지 못하면 그 사유까지 화면에 낸다(규칙 14).
판정 기준은 "이번에 쓴 파일"이 아니라 **지금 프로젝트가 만들 수 있는 파일**이라, 막혀서 못 쓴 노드의
파일은 고아로 몰리지 않는다. 테스트 8건으로 고정(`OutputManifestTests`·`LiveOutputReportTests`).

**남은 위험(그래서 🔴이 아니라 🟡)**: **VnTool은 파일을 지우지 않는다.** 사용자가 목록을 무시하면
유니티는 여전히 없어진 노드의 옛 대사를 재생할 수 있다. 이건 결함이 아니라 선택이다 —
근거는 [architecture-decisions.md](architecture-decisions.md) C-3.
**③안(노드 Id로 번들 이름)은 미채택**: 세이브 키(C2)·점프 대상이 함께 바뀌는 계약 변경이고
삭제 문제도 못 고친다. 같은 문서 C-3에 근거를 남겼다.
**수동 확인 남음**: 실제 앱에서 노드 삭제·이름 변경 후 목록이 뜨는지 — [next-tasks.md](next-tasks.md) T2에 합류.

## ✅ K2. X1 크래시 — **재현 없음으로 종결** (T2-1, 2026-08-05)

**확인**: 소유자가 원래 시나리오(에셋 폴더 지정 → 탐색기/프리뷰 이미지 클릭)를 재현했고 크래시가 없었다.
**남는 사실**: 8/4 크래시의 **근본 원인은 끝내 확정되지 않았다.** 방어(`UiGuard` + 디스패처 안전망 +
디코더 전체 포획, `21b2a7d`)가 덮은 것인지 원래 다른 조건이었는지 구분할 근거가 없다.
그래서 "고쳤다"가 아니라 "재현되지 않는다"로 닫는다 — 다시 죽으면 이제는 로그가 남는다.

## 🟡 K4. ScenarioOnly 붙여넣기로 선택지를 만들 수 없다

**설계상 비범위**: 파서가 `->` 라벨을 "해석 못 한 줄" 목록으로 보낸다. 선택 전환은 붙여넣기가 **건드리지 않고 보호**한다(테스트로 고정).
**영향**: 선택지가 있는 대본을 통째로 붙여넣으면 라벨 줄이 빠진 채 들어오고, 선택 구조는 UI로 따로 만들어야 한다.
**의도**: 선택지는 `OptionId` 안정성·C3 순서 경고가 걸려 있어 텍스트 왕복을 함부로 열지 않았다.
**해결 방향**: 라벨 문법(`-> 텍스트`)을 파서 어휘에 넣고 `OptionId`를 diff로 잇는 별도 설계가 필요하다 — 소유자 요청 시 착수.

## 🟡 K5. 라이브 출력·내보내기 상태 계산이 매번 전체 합성이다

- `LiveOutputService`: 디바운스 1회마다 **프로젝트의 모든 대사 노드**를 합성한다.
- `DialogueNodeEditor.RefreshExportState`: 편집기 Rebuild마다 그 노드를 합성한다.

**근거**: 코드상 그렇다. **측정은 안 했다** — 샘플(노드 6개) 규모에서는 체감 문제가 없었다.
**주의**: 노드가 수십 개인 실제 프로젝트에서 타이핑이 무거워지면 여기가 첫 번째 용의자다.
조기 최적화 대신 **측정 후 판단**(변경 노드만 합성 / 캐시).

## 🟡 K6. 라이브 출력 폴더가 클라우드 동기화 폴더면 쓰기 충돌 가능

**상태**: 안내 문구만 넣었다("클라우드 동기화 폴더는 쓰기 충돌이 날 수 있습니다").
실패 시 상태줄로 알리므로 조용히 깨지지는 않는다. 재시도·잠금 대기는 없다.

## 🟡 K7. 유니티 실재생 게이트 — **소유자 판단으로 해제, 실행 기록은 없음** (2026-08-05)

소유자가 "걱정할 필요 없다"고 판단해 2b 착수 조건에서 뺐다.
**다만 이것은 검증이 아니라 판단이다.** 기본 트리오 / 선택지 번들(`$__ch_N`) / `[adv/]` 번들을
유니티에서 실제로 재생해 확인한 기록은 <b>없다</b>. 계약서 F절 잔여(씬 변수 저장소 배선,
옵션 라벨 접두, `YarnVariableBridge` 미배선, CanvasScaler 해상도)도 그대로 남아 있다.

**왜 그래도 진행할 수 있나**: Phase 2b의 수용 기준이 "유니티 화면과 구도 일치(수동)"이라
2b 검증이 사실상 이 게이트를 다시 친다. **2b에서 계약 위반이 나오면 원인 후보 1번은 여기다** —
`work-orders/phase2-design-brief.md` §5에 같은 경고를 남겼다.
