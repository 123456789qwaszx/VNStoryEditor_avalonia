# VnTool 출입구 레퍼런스 — 모든 입출력의 형식과 관리 기준

2026-08-06 작성. 소유자가 관리자로서 툴의 모든 입출력을 정확히 관리하기 위한 기준 문서.
아래 내용은 전부 코드에서 확인한 사실이다(추측 없음). 규범 충돌 시 코드와
`runtime-contract.md`가 우선한다.

## 0. 한눈에 — 프로젝트 폴더의 권장 배치

```
MyGame/                          ← 이 폴더가 곧 백업·이관 단위다
  project.vnproject.json         [핵심·툴 소유] 프로젝트 목차 — "열기"는 항상 이 파일
  script/<scriptId>.vnscript.json[핵심·툴 소유] 대본 (LineId 정체성 + locale 본문)
  story/<fileId>.vnstory.json    [핵심·툴 소유] 노드 (그래프·연출 바인딩)
  results.vnresults.json         [핵심·툴 소유] 발행된 불변 결과
  game.definition.json           [관리자 소유] 게임 어휘 — 손편집 대상
  ExportedTuning/                [런타임 소유] 유니티 덤프 사본 — 읽기 전용 취급
  assets/
    backgrounds/                 [관리자 소유] 배경 PNG — 파일명 = 키
    portraits/                   [관리자 소유] 초상화 PNG — 폴더 규약 = 키
  output/                        [산출물] 라이브 출력 지정 시 — 원본 아님
    Story_*.yarn Set_*.yarn Pres_*.yarn declarations.yarn
    Script_*.csv Review_*.csv Direction_*.csv
    .vntool-output.json          산출 기록 (고아 탐지용)
```

- **[툴 소유]**: 툴만 쓰게 두고 손대지 않는다. 전부 결정적 직렬화 JSON이라 git diff는 된다.
- **[관리자 소유]**: 손으로 관리하는 파일 — definition과 에셋 폴더 둘뿐이다.
- **[런타임 소유]**: 원천이 유니티다. 여기서 고치지 않고 다시 덤프해 통째로 복사한다.

## 1. 입구 (툴이 읽는 것)

### 1-1. 프로젝트 (`.vnproject.json` + 부속)

- **열기는 manifest 하나**: `project.vnproject.json`. 개별 `.vnstory.json`·`.vnscript.json`을
  열려고 하면 툴이 거부하고 manifest를 열라고 안내한다.
- manifest는 목차·파일 간 관계만 담고, 실제 내용은 부속 파일에 있다:
  `script/<scriptId>.vnscript.json`(대본), `story/<fileId>.vnstory.json`(노드),
  `results.vnresults.json`(발행 결과 — 발행이 있을 때만 생성).
- 저장은 원자적(임시 파일 → 교체)이고 **부속을 먼저, manifest를 마지막에** 쓴다 —
  중간에 죽어도 manifest가 없는 파일을 가리키지 않는다.
- 인코딩 UTF-8(BOM 없음). 형식 버전이 있어 다른 버전이면 명확한 오류로 알린다.
- ⚠ 부속 파일 손편집 금지 — LineId·리비전·발행 해시가 계약이다. 편집은 툴 안에서.

### 1-2. `game.definition.json` (게임 어휘 — 관리자의 파일)

- 위치·이름 고정: **프로젝트 파일과 같은 폴더의 `game.definition.json`**.
- 담는 것: `variables`(변수 등록), `speakers[{name, characterId}]`(화자→캐릭터 키 매핑),
  `preview.resolution`("1920x1080" 형식, 없으면 1920×1080),
  `runtimeTuningPath`(튜닝 폴더 재지정 — §1-3).
- **없거나 깨져도 프로젝트는 열린다** — 자동완성·드롭다운 후보가 없어질 뿐이다.
  미매핑 화자도 오류가 아니다(이름만 표시).
- 화자는 툴의 설정노드 등록 UI로도 편집된다 — **UI는 창구일 뿐 원천은 이 파일 하나다**
  (저장하려면 프로젝트가 먼저 저장돼 있어야 한다). 손편집과 UI 편집이 같은 파일을 본다.
- 관리 권장: 게임마다 하나, git으로 이력 관리. 여러 프로젝트가 같은 게임 어휘를 쓰면
  이 파일을 복사하지 말고 프로젝트 폴더를 게임 단위로 묶는 쪽을 권장.

### 1-3. `ExportedTuning/` (런타임 튜닝 덤프 — 실좌표 배치의 근거)

- **해석 순서**: ① definition의 `runtimeTuningPath`(프로젝트 상대 또는 절대)가 있으면
  그 경로(없는 경로면 경고가 남는다), ② 없으면 프로젝트 폴더의 `ExportedTuning/`
  (폴더가 없으면 조용히 미수입 — 안내 대상이지 경고가 아니다).
- 내용(14파일, 유니티 U12 내보내기 그대로):
  `base-resolution.json`, `portrait-dimensions.json`, `rig-schemas.json`,
  `export-report.json`, `schema.md`(**필드 의미·단위의 규범 문서**),
  `presets/` 9종(depth, focus-tuning, mask-motion, role-anchor, screen-flash,
  screen-noise, screen-vignette, surface-layout, visual-focus).
- 스키마 = 코어 `Ked.Presentation.Core/Tuning/` DTO와 1:1 (별도 로더 없음, 사본 금지).
- **없으면**: 저작은 계속되고 좌표는 근사 배치 + "좌표 근사" 뱃지. 오류가 아니다.
- **갱신 절차**: 유니티에서 튜닝이 바뀌면 → 다시 덤프 → 폴더째 덮어쓰기 →
  툴의 **에셋 새로 고침**(폴더 내용 변경은 자동 감지하지 않는다 — 명시적 새로 고침 규칙).
- **툴 안 진입점 (W46)**: 에셋 탐색기의 [튜닝…] 버튼 — ① **기본 튜닝 생성**: 앱에
  내장된 기본값(런타임 실측 덤프의 스냅샷)으로 규약 폴더를 만든다(내용이 있는 폴더는
  불가침). ② **튜닝 폴더 연결…**: 갖고 있는 덤프 폴더를 골라 규약 자리로 복사한다
  (같은 파일은 덮어씀 — "통째 교체" 규약의 UI판). 둘 다 프로젝트 저장이 선행 조건이다.
- ⚠ 여기 파일을 손으로 고치지 않는다 — 고치면 툴 프리뷰와 실제 게임이 어긋난다.
  원천은 언제나 유니티 덤프다.

### 1-4. 에셋 폴더 (배경·초상화)

- 루트 경로는 **프로젝트에 저장**된다(`assetRoots.backgroundsPath / portraitsPath`,
  프로젝트 상대 권장·절대도 동작). 지정은 좌측 에셋 탐색기에서.
- **새 프로젝트는 첫 저장 때 자동 준비된다 (W48)**: `assets/backgrounds`·`assets/portraits`
  폴더가 만들어지며 루트로 지정되고, 기본 튜닝(§1-3)도 함께 생성·연결된다.
  이미 튜닝이 있으면 불가침. 수동 지정은 거의 쓸 일이 없는 예외 경로가 됐다.
- **가져오기 (W48)**: 섹션 헤더의 [가져오기…] — 아무 폴더의 PNG를 골라 규약 자리로
  복제한다. 배경은 파일명 그대로(중복 이름은 건너뜀), 초상화는 캐릭터·변형을 정하면
  빈 표정 번호(01, 02…)부터 차례로 들어간다. [폴더 열기]는 그 자리를 파일 탐색기로 연다.
- **배경**: 파일명이 곧 키(Ordinal, 확장자 제외). 하위 폴더 포함 키(`night/alley`) —
  런타임 `Resources/Backgrounds/{key}`와 동형. PNG.
- **오디오 (W59)**: `assets/bgm`·`assets/sfx` — 파일명(확장자 제외)이 곧 clipKey.
  mp3·wav·ogg. 첫 저장 때 자동 준비되고, 연출 조절창의 오디오 탭이 이 목록으로
  `bgm`/`sfx` 커맨드를 단다(프리뷰는 소리를 재생하지 않는다 — ♪ 칩 표시).
- **초상화**: 폴더 규약이 권위다 — `{portraitsRoot}/{char}/{variant}/{emotion}.png`
  (variant 기본 `a`, emotion 2자리 `01`, 폴백 (char, a, 01)).
  `portraits.manifest.json`은 구버전 덤프·자유 경로의 수입 보조일 뿐, 없어도 된다.
- **없으면**: 문자 플레이스홀더로 표시되고, 빈칸에 "어디에 어떤 이름으로 넣으라"는
  안내가 나온다. 채우면 반드시 동작한다(자동 추측 없음).
- 갱신 절차: 파일을 넣고 → **에셋 새로 고침**.

## 2. 출구 (툴이 쓰는 것)

### 2-1. .yarn 트리오 + 선언 (런타임이 읽는 산출물)

- 파일명 규약: `Story_<번들명>.yarn` · `Set_<번들명>.yarn` · `Pres_<번들명>.yarn`
  (번들명은 대사 노드 이름 기반) + `declarations.yarn`(**폴더당 하나, 변수 선언 합집합**).
- 인코딩 UTF-8(BOM 없음), 원자적 쓰기(.tmp → 교체).
- 유니티와의 계약: **대사 결과 Text를 YarnScript에 붙여넣으면 그대로 재생**(H-5).
- 출력 단위 = 대사 노드. 짝이 되는 연출은 그래프의 연출 공급 연결에서 계산된다.

### 2-2. CSV 3종 (사람 도구용 산출물)

- `Script_<번들명>.csv`(번역·녹음) · `Review_<번들명>.csv`(기획 검수) ·
  `Direction_<번들명>.csv`(연출 테이블).
- **UTF-8 BOM · CRLF · RFC4180** — 엑셀에서 바로 열려 한글이 깨지지 않게 하기 위한
  형식 확정. (엑셀 실확인은 §5.5 잔여 항목.)
- 어떤 양식을 산출할지는 [양식…] 선택을 따르고 프로젝트에 저장된다.

### 2-3. 라이브 출력 (자동 재산출)

- 프로젝트의 `outputPath`(프로젝트 상대 저장 선호) 지정 시, **편집할 때마다 디바운스로
  자동 재합성·재저장**된다. 수동 내보내기와 같은 합성기를 지나므로 바이트가 같다.
- 미지정이면 자동 산출 없음 — 편의 기능이 저작을 막지 않는다.
- `.vntool-output.json`(버전 1): 이 폴더에 툴이 쓴 파일의 기록. 점(.)으로 시작해
  Yarn 컴파일 대상에서 제외된다. 노드 삭제·개명으로 낡은 산출 파일이 남으면
  **툴은 지우지 않고 목록으로 보여 준다** — 출력 폴더는 사용자의 폴더다.
- ⚠ 클라우드 동기화 폴더(OneDrive 등)를 라이브 출력으로 지정하면 쓰기 충돌이
  날 수 있다(UI에도 경고 있음).
- ⚠ 출력 폴더의 파일을 손으로 고치지 않는다 — 다음 산출이 덮는다. 고칠 것이 있으면
  원본(툴)에서 고친다.

### 2-4. 프로젝트 저장 · `game.definition.json` 쓰기

- 저장: §1-1의 구조 그대로. 다른 이름으로 저장하면 부속 폴더 구조가 새 위치에
  다시 만들어진다.
- 화자 등록 UI의 저장은 game.definition.json을 **직접** 고쳐 쓴다(§1-2).

## 3. 관리자 운영 수칙 (요약)

1. **백업·이관·git의 단위는 프로젝트 폴더 통째**다. 전부 텍스트라 git이 잘 어울린다.
   출력 폴더는 재생성 가능한 산출물이므로 제외해도 되지만, 유니티가 그 폴더를 직접
   읽는 구성이면 포함해 이력을 남기는 쪽이 안전하다.
2. **손대는 파일은 둘뿐**: `game.definition.json`(어휘)과 에셋 폴더(PNG). 나머지는
   툴이 소유한다.
3. **바깥에서 온 것은 통째로 교체**: ExportedTuning은 유니티 재덤프 → 폴더 덮어쓰기 →
   에셋 새로 고침. 부분 수정 금지.
4. **경로는 프로젝트 상대로**: 에셋 루트·튜닝 재지정·라이브 출력 전부 상대 경로면
   폴더를 옮기거나 다른 컴퓨터로 가져가도 그대로 동작한다.
5. **새로 고침 규칙**: 폴더 내용(에셋·튜닝) 변경은 자동 감지되지 않는다 — 에셋
   새로 고침 버튼이 반영 시점이다. 경로 설정 변경은 즉시 반영된다.
6. **지우지 않는 도구**: 낡은 산출물·고아 파일은 툴이 목록으로 보여 줄 뿐 삭제는
   관리자가 탐색기에서 한다.
