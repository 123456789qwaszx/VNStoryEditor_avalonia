## 1. 무엇을 만드는가

**VnTool** — 비주얼 노벨 저작 도구. C#/.NET 10 + Avalonia, 한국어 코드베이스.
프로젝트 루트 `C:\Users\river\Documents\GitHub\java-start`, 솔루션 `VnTool.sln`.

만들어 내는 것은 유니티 런타임(별도 저장소)이 먹는 데이터다:
`exported/{챕터}.progression.json` + Yarn 번들.

### 목적 — 왜 이 구조인가

**세 사람이 서로를 막지 않고 동시에 일하게 하는 것.** 그래서 층을 갈랐다:

```
A 계층 (기획자)          B 계층 (작가)             연출 계층
챕터 그래프 · 엑셀        시나리오 그래프 · 엑셀      연출 노드
에피소드 구조             대사 한 줄 한 줄            커맨드·무대
간선 = 행선지 + 스탯변화   에피소드 안의 조건·연출     발행된 결과 위에서만
```

**각 값의 주인이 한 곳뿐이어야 한다**가 설계 전체를 관통하는 규칙이다. 같은 사실이
두 곳에 있으면 어긋나고, 어긋남은 최종 출력에서야 드러난다.

## 2. 계층 의미론 — 확정된 규칙 (건드리지 말 것)

### 2.1 소유권

| 값 | 주인 | 툴에서는 |
|---|---|---|
| 대사 본문·화자 | 에피소드 워크북 `episodes/{Id}.xlsx` | **읽기 전용.** 엑셀노드 카드는 잠긴다 |
| 에피소드 구조·간선 | 챕터 워크북 `chapters/{Id}.xlsx` | 툴 편집이 **엑셀 셀에 즉시 저장**된다 |
| 스탯 변화 | **간선 하나뿐** (`간선` 시트 7열 `스탯변화`) | 대본에서 스탯 조작 = 설계 미스, 폐지됨 |
| A계층 조건 식 | 챕터 `조건` 시트 | 작가 화면에는 **라벨만** 보인다 (§2.4) |
| 에피소드 안의 조건·연출 | 시나리오 그래프의 자유 노드 | 작가가 직접 만든다 |
| 줄 신원(LineId) | 프로젝트의 `ExcelLineMap` | B열은 유물. 툴은 워크북에 **쓰지 않는다** (v4) |
| 화자 등록(저작) | 챕터 `화자` 시트 (2026-08-16) | 에피소드 워크북 H열이 그 목록의 드롭다운을 받는다. **v4의 유일한 예외**: 툴이 원고 파일의 숨김 `화자목록` 시트만 갈아 끼운다(대사 행 불가침, 목록 같으면 무접촉) |
| 초상화 매핑 | `game.definition.json`의 speakers | 변함없음. 챕터 화자 시트와는 동기화가 메모리에서만 합쳐 본다 |

### 2.2 전이 규칙 (낙하 폐지 — 2026-08-15 확정)

에피소드가 끝나면:

1. 플레이어가 고른 옵션의 **라벨과 짝인 간선**을 탄다 → `StatChanges` 커밋(clamp) 후 이동
2. 선택지가 없던 에피소드면 **무라벨(진행) 간선**을 탄다
3. 그 외에는 **챕터 런이 여기서 끝난다**

폴백 사슬은 없다. "선택지가 있는데 진행 간선으로 떨어진다"는 개념 자체가 폐지됐다.
검증기는 `진행 간선 + 선택지 병존`을 경고한다.

### 2.3 간선 신원 = (출발, 도착, 라벨)

여러 선택지가 같은 에피소드로 갈 수 있다. 라벨이 다르면 다른 간선이다.
라벨은 자유 입력이 아니라 **그 에피소드 대본의 OPTION 드롭다운**에서 고른다
(선택지가 없으면 `(선택지 없음)` 하나만).

### 2.4 A 계층 격리 (2026-08-15 소유자 지시)

동기화가 만드는 `챕터 {판이름} 조건` 설정노드는 **시나리오 그래프에서 보이지 않는다**
(카드·공급 링크 모두 `GraphProjectionBuilder`가 거른다). A계층 식(`trust >= 3`)과
스탯 변수는 작가에게 노출되면 안 되는 자료이기 때문이다.

**단, 데이터로는 살아 있다** — 엑셀 `조건라벨` ↔ 식 역조회의 신원 저장소라 지우면
동기화가 무너진다. 작가에게는 드롭다운의 **라벨만** 남는다.

> **조건노드(SetNode) 자체는 작가의 도구다.** 에피소드 안에서만 쓰는 B계층 변수·조건은
> 작가가 직접 만들어 쓴다. 금지된 것은 "A계층 데이터를 그 자리에 부어 놓는 것"뿐이다.

### 2.5 출구 규칙

- 자유 노드의 출구 후보에 **엑셀노드는 없다** (기획의 영역으로 넘어가는 선은 금지)
- 자유 노드의 **출구 없음 = (진행)** = 에피소드 종료 후 챕터 간선이 정한다
- 엑셀노드의 옵션 포트·기본 출구는 카드가 아니라 **철도 칩**에 있다 (T2)

## 3. 두 화면

### 3.1 챕터 그래프 (기획자)

- 카드 = 에피소드. **선택지 포트가 카드 오른쪽**에 뚫린다(최대 3개, 채워진 원 = 배선됨).
  포트마다 간선이 나간다. 선택지 없는 에피소드는 카드 중앙에서 직결.
- 탭 셋: **[챕터]**(조건·스탯·픽스처) · **[편집]**(제목·표시/해금·엔딩키·메모·[적용],
  간선 라벨/조건/잠금/스탯변화) · **[대사]**(미리보기)
- 아래 검증 보고 — **동기화 보고가 맨 위**(묻혀서 안 보이던 실사례)

### 3.2 시나리오 그래프 (작가) — 철도 배선

챕터 간선이 작가의 판에 **오렌지 철도**로 미러된다. 규칙 하나: **한 구간에 선 하나.**

```
[EP01] ●선택지 ──▶[씬A]──(작가 배선)──▶[씬B]────●──▶[EP02]
        레일: 입구까지     속: 배선 하나      합류선: 레인 끝으로
```

- **칩**(`● 라루를 믿는다` / `○ 진행`)이 배선 진입점. 누르면 상세 + 자유 씬 배선 플라이아웃
- 가지 순서 = **읽는 순서**(대본 OPTION 순서 → 유령 → 진행 → 엔딩 스텁)
- 레일은 **첫 씬 입구까지만** 댄다. 웹 속은 작가의 실행 배선이 유일한 선
- 웹의 끝(기본 출구 없음 = 진행)에서 **합류선**이 레인 끝으로 모인다
- 스텁: `⏹ 종료`(길이 여기서 끝남) · `▢ {Id} (동기화 전)`(간선은 있는데 노드가 아직 없음)
- 도착 포트 — 여러 가지가 도착 카드 앞 접점 하나로 수렴. 누르면 들어오는 길 목록

### 3.3 노드 시각 체계 (2026-08-15)

색 하나가 아니라 **등뼈(왼쪽 색 막대) + 아이콘 + 카드 형태** 세 채널을 겹친다.
정의는 `GraphEditorView.CardStyleFor` 한 곳. 미니맵·접힌 목록도 같은 언어를 쓴다.

| 종 | 등뼈 | 형태 | 아이콘 |
|---|---|---|---|
| 엑셀노드 | 호박 | **미색 종이, 각진 모서리(4)** | 📄 |
| 자유 씬 | 청록 | 흰 종이, 둥근 모서리(10) | ✎ |
| 설정(조건) | 파랑 | 옅은 파랑 | ⚙ |
| 연출 | 보라 | 옅은 보라 | 🎬 |
| 연출 공급 | 초록 | 옅은 초록 | 🧰 |
