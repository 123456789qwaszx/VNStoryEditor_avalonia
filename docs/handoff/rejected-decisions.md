# 검토했지만 폐기한 방향

**이 문서의 목적은 재발 방지다.** 아래 항목이 다시 제안되면 "이미 검토했고 이런 이유로 접었다"가 답이다.
새로 제안하려면 **여기 적힌 이유가 더 이상 성립하지 않는다는 근거**가 먼저 필요하다.

---

## A. 구조 차원

### A-1. 전면 재작성 — 기각
**검토**: 도메인 모델이 어긋나 보여 새로 쓰는 안.
**기각 이유**: ① 현행 모델이 런타임의 가장 무거운 요구(LineId·노드 타이틀 영구 안정성, 계약서 C1·C2)와 정확히 맞물려 있다.
② 확장 지점이 이미 설계에 있었다(공급 노드 = capability node 레시피). ③ Vn.Core(Yarn 컴파일 엔진)가 출력 검증기로 재활용된다.
④ 잃는 것: 270+ 테스트·검증된 재동기화·불변 발행 파이프라인. 얻는 것: 없음 — 고칠 곳은 국소적이었다.
**출처**: 마스터 플랜 §1.

### A-2. 매니페스트를 초상화 연결의 권위로 — 폐기 (W-asset-02)
**검토**: `portraits.manifest.json`이 키→파일 매핑의 정본이고, 툴은 그걸 읽는다.
**폐기 이유**: 원칙 문서 §3.5의 표가 **런타임의 저장 방식**을 서술한 것인데 툴의 저장 방식까지 정하는 것처럼 읽혔다.
공유되는 것은 키 공간이지 저장 방식이 아니다. 매니페스트가 권위면 아티스트가 PNG를 넣을 때마다 JSON을 열어야 하고, 그건 "이름만 맞추면 연결된다"는 착각을 거짓으로 만든다.
**현재**: 규약 경로 1순위, 매니페스트는 수입 보조.

### A-3. 발행을 출력 게이트로 유지 — 폐기 (D-2)
**검토**: 내보내려면 반드시 발행 → 발행본만 출력.
**폐기 이유**: 실사용에서 "출력을 보려고 매번 발행" 마찰. 발행의 본질적 역할은 **연출이 읽을 고정된 스냅샷**이지 출력 허가가 아니었다.
**주의**: 발행 자체를 없앤 게 아니다. 연출↔대사 버전 짝 경고는 그대로 유지된다(조용한 드리프트 금지).

### A-4. 명시적 RuntimeComposition 레코드 — 폐기
**검토**: 대사 결과 + 연출 결과를 짝지은 레코드를 사용자가 만들어 내보낸다.
**폐기 이유**: 연출 결과가 이미 자기 입력(Id·Version·Hash)을 못박고 있어 짝이 구조적으로 결정된다. 사람이 짝을 또 고르면 어긋난 짝을 만들 자리가 생긴다.
**현재**: `PresentationSupply` 연결에서 계산(`NodeExportResolver`). 모델은 저장 호환용으로만 잔존.

### A-5. 대본 가져오기 트랙 유지 — 폐기 (D-3)
**폐기 이유**: 노드 직접 편집·붙여넣기와 함께 세 입력 트랙이 되면 같은 diff 엔진을 다르게 부르는 경로가 생긴다.
**현재**: 파일 가져오기 UI는 제거, 엔진(`ScriptSynchronizer`)은 붙여넣기가 재사용.

## B. "편해 보이지만 규칙을 바꾸는 것" — 전부 금지

| 폐기한 것 | 이유 |
|---|---|
| **붙여넣기 시 라인 전체 재생성** | LineId가 매번 새로 발급되어 연출·녹음·번역이 전부 끊어진다. 지시서가 "계획에 나오면 반려"로 못박은 항목 |
| **유사 이름 매칭 / 오타 교정 제안** | 규칙이 "이름이 같으면 연결"에서 "툴이 알아서"로 바뀐다(원칙 §2.3). 디버깅이 "왜 연결됐지"를 묻는 문제가 된다 |
| **에셋 일괄 rename 마법사** | 같은 이유. 사람이 이름을 정하는 것이 규약의 핵심이다 |
| **매니페스트 편집·생성 UI** | 매니페스트를 다시 권위로 만든다 |
| **매니페스트 형식 확장** | v1로 충분하다. 수입 통로일 뿐이므로 키우면 다시 정본처럼 보인다 |
| **커맨드 카탈로그를 C# enum에 하드코딩** | 게임마다 어휘가 다르다. 코드가 `bg_spawn`을 아는 순간 그 게임 전용 도구가 된다 |
| **프리뷰 전용 쓰기 경로** | 되돌리기·알림·발행이 그 길만 비켜 간다. 전부 `ProjectEditor`로 수렴(ARCHITECTURE 규칙 15) |
| **예외 대신 "예외 표시 장치"** | 예외가 발견되면 표시하지 말고 예외 자체를 없앤다(원칙 §2.1) |

## C. 범위에서 뺀 것 (지금은 안 한다, 영구 금지는 아님)

| 항목 | 상태 |
|---|---|
| **연출 보조 AI 단계** | 마스터 플랜 3차 개정에서 삭제 — 소유자가 자체 계획 보유. 이 플랜의 범위 밖 |
| **`<<else>>` 지원** | 비범위. 조건 모델이 if/elseif/endif만 다룬다. 지원 시 X11 표기·파서 양쪽 추가 필요 |
| **MixedChain(조건 갈래 안 선택지)** | 미지원 — 발행에서 거부. 지원하려면 별도 설계 결정(계약서 D7의 가용 배열 인덱스 문제) |
| **중첩 조건** | 깊이 0/1만. 같은 이유 |
| **`.yarn` 역파싱(Import)** | 별도 트랙(Vn.Import)으로 분리. ScenarioOnly 파싱은 **입력 방법**이지 산출물 되읽기가 아니다 |
| **좌표·크기·이펙트 프리뷰** | 2a-v1 명시 비범위 → 2b(정지 프레임 렌더러)의 일 |
| **에셋 파일 변경 감시** | 명시적 [새로 고침]만. 감시는 "언제 갱신됐지"를 묻게 만든다 |
| **X8이 제거한 버튼 복원** | 대체 진입점(탐색기 [폴더…]·[새로 고침])이 확인됨 — 복원 불필요 |
| **실시간 다인 협업** | 비범위 |

## D. 시도했다가 되돌린 구현 디테일

- **슬라이더 값 변경마다 커밋** → 드래그가 끊겼다(커밋이 편집 행을 재구성). `PointerCaptureLost`에서 한 번만 커밋으로 변경.
- **자유 텍스트 set 파서**(`변수 += 값` 한 줄씩) → X6에서 구조화 입력(드롭다운+슬라이더)으로 대체하며 제거.
- **`PreviewImageCache`의 IO 계열 예외만 포획** → 깨진 PNG에서 디코더가 무슨 예외를 던질지 열거할 수 없다. X1에서 전체 포획으로 확대.
