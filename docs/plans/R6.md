# R6. Scene 층 — 챕터와 에피소드 사이

> 상위 계획: [PLAN.md](PLAN.md). 상태: **진행 중 (2026-09-16 착수)**.
> 화면 규격: **[R6-explorer.md](R6-explorer.md)** — S-2·S-3·S-4가 대조할 자리.
> 런타임 정본: `ked-progression-runtime/dev` — `Progression-Runtime_README.md` · `Progression-Runtime_Plan.md`

## 1. 목표와 한 줄 요약

**Scene을 층으로 세운다.**

지금 `SceneId`는 에피소드에 붙은 칸 하나와 배지 하나다. 값으로는 있지만 **Chapter와 Episode를
잇는 자리가 없다** — 소유자 관찰(2026-09-16): *"툴 상으로는 Chapter와 Episode를 이어주는
Scene에 대한 흔적을 찾을 수 없습니다."*

끝나면 두 화면이 이렇게 보인다:

```text
Chapter ch01
├─ Scene opening
│  ├─ Episode main01.01
│  └─ Episode main01.02
└─ Scene classroom
   ├─ Episode main01.03
   └─ Episode branch01.03A
```

그리고 **접었다 펼 수 있다**(유니티 하이어라키 꼴).

## 3. 숙련자의 사고흐름

1. ⛔ **Scene은 엔티티가 아니다 — 파생 묶음이다.**
   런타임에도 저장되는 Scene 테이블이 없다: `SceneProgression`은 **실행 시** 현재 에피소드의
   `SceneId`로 만들어진다. 정본은 `Episode.SceneId` 하나다. 툴이 Scene 목록·테이블을 따로
   만들면 **정본이 둘이 되고**, 이 저장소 전체를 관통하는 *"각 값의 주인은 한 곳뿐"*이 깨진다.
   화면의 층은 **투영**이다.

2. **묶는 순서의 근거는 루트다.**
   Scene에는 밖에서 들어오는 자리가 하나뿐이고(`VerifySceneEntries`) 그것이 루트다.
   Scene의 자리·순서는 그 루트의 자리에서 나온다 — 임의 정렬을 발명하지 않는다.

3. **트리 컨트롤이 이 저장소에 없다.** `TreeView`를 쓴 자리가 한 곳도 없다.
   한 번 제대로 만들어 **두 화면이 같은 것을 쓴다** — 두 벌이 되면 접힘 규칙이 갈린다.

4. **대본 탭이 먼저다.** 작가가 매일 여는 자리이고 구조가 단순하다(목록 둘 → 트리 하나).
   연출 그래프는 이미 접기/펼치기(`CollapsedFileProjection`)가 있어 Scene이 **셋째 단**이 되는,
   더 큰 일이다.

5. **빈 `SceneId`를 사람에게 그대로 보이지 않는다.**
   내부 발급값 `__scene_{EpisodeId}`는 퇴화 상태의 구현 세부다 — 화면에는
   **"에피소드별 장면(기본)"**으로 쓴다(R1 §5 요구, 아직 미구현).

### S-0 — 문서 (Documentation)

⛔ **먼저 하는 이유**: `docs/runtime-contract.md`가 **바로 이 주제에서 틀린 말을 한다.**

틀린 정본 위에 UI를 올리면 다음 사람이 그 문서를 믿고 어긋난다.

- 95·305행 정정, 런타임 정본 주소를 `ked-progression-runtime`으로 갱신.
- **"Scene이란 무엇인가"** 절 신설: 엔티티가 아니라 파생 묶음 · 루트 규칙 · 경계의 뜻
  (커밋/롤백/저장) · 빈 값 퇴화.
- R1 §5의 미구현 UI 요구를 R6로 이관 표시.

### S-1 — Scene 묶음 투영 (Model)

`Vn.Authoring.Chapters`에 순수 함수 하나. 화면을 모른다.

```text
ChapterSceneGrouping.Of(chapter) →
  [ Scene { SceneId, DisplayName, RootEpisodeId, Episodes[] }, ... ]
```

- 묶기: `EffectiveSceneId` 기준.
- 순서: 루트의 자리(챕터 시작 → 간선 깊이) 순.
- 루트: 밖에서 들어오는 착지점. 규칙은 코어의 `VerifySceneEntries`와 **같은 판정**을 쓴다 —
  새 불변식을 만들지 않는다.
- 표시명: `SceneId`가 있으면 그대로, 없으면 `"에피소드별 장면(기본)"`.
- ⚠ 루트가 둘인(위반) 챕터에서도 **묶음은 나와야 한다** — 리더의 규율 그대로다
  (*"오류가 있어도 모델은 만든다, 조용히 빈 화면을 주지 않는다"*). 그때는 첫 착지점을
  루트로 삼고 그 사실을 묶음에 실어 화면이 짚게 한다.

### S-2 — [대본] 탭을 트리로 (UI/UX)

⚠ 세부는 **[R6-explorer.md](R6-explorer.md)**가 규격이다. 여기서는 요점만.

지금: `ChapterList`(220px) + `EpisodeList` 두 목록.
뒤: **`ChapterSceneTree`** 하나 — Chapter → Scene → Episode, 접었다 펼 수 있다.

⛔ **결정 하나가 규격의 핵심이다**(규격 §2): 장면ID를 **하나도 안 적은 챕터는 장면 단을
생략한다**. 안 그러면 구판 프로젝트에서 에피소드 수만큼 장면 마디가 생겨 트리가 통째로
노이즈가 된다. 하나라도 적혀 있으면 전부 장면 단으로 본다 — 섞으면 한 화면에 두 규칙이 선다.

- 선택은 **에피소드에서만** 일어난다(Scene·Chapter 마디는 접기/펼치기).
- 아직 아무도 안 쓴 에피소드도 선다(R-E의 그 규율) — 사다리 `[＋ 대본]`은 그대로.
- 빈 장면 표시명은 §3-5.
- 기존 `ScriptTabTests` 21개는 **보존한다** — 선택 경로만 트리로 바꾼다.

### S-3 — 연출 그래프의 셋째 단 (UI/UX)

지금은 `판(챕터) → 노드`이고 판 단위로 접힌다(`CollapsedFileProjection`).
Scene이 그 사이에 들어간다: **판 → Scene → 노드**.

- 접힌 판의 행 목록(`CollapsedNodeEntry`)이 Scene별로 묶인다.
- 펼친 판에서는 같은 Scene의 카드가 **한 영역으로 묶여 보인다**(R1 §5 ①, 미구현분).
- ⚠ 자유 씬(에피소드가 아닌 대사노드)은 Scene에 안 속한다 — 별도 묶음으로 둔다.

### S-4 — 탐색기 다듬기 (UI/UX)

- 접힘 상태를 프로젝트에 기억한다(사람이 접어 둔 것을 다시 펴지 않는다).
- 키보드 이동(↑↓←→).
- 두 화면의 선택이 서로를 따라간다.

## 6. 주의사항

| 증상 | 원인 | 대응 |
|---|---|---|
| Scene 목록을 따로 들고 싶어진다 | 트리를 만들다 보면 마디에 상태를 붙이고 싶다 | ⛔ 정본은 `Episode.SceneId`. 마디는 **투영**이고 상태는 접힘뿐 |
| 화면에 `__scene_ep01`이 보인다 | 퇴화 발급값을 그대로 렌더 | 표시명 규칙(§3-5)을 투영에서 정한다 |
| 루트가 둘인 챕터에서 트리가 빈다 | 위반이면 못 묶는다고 판단 | 첫 착지점을 루트로 삼고 **짚어 준다** |
| 두 화면의 접힘 규칙이 갈린다 | 트리를 두 벌 만든다 | 컨트롤 하나를 두 곳이 쓴다 |
| 대본 탭 테스트 21개가 깨진다 | 선택 경로를 갈아엎는다 | 트리에 선택 손잡이를 두고 테스트는 그것을 쓴다 |

## 7. 완료 기준

- 대본 탭과 연출 그래프가 **같은 묶음**(Scene)을 같은 이름으로 보인다.
- 접힘이 사람의 것이고, 다시 그려도 안 풀린다.
- `Episode.SceneId` 말고 Scene을 들고 있는 자리가 **하나도 없다**.
- 구판(빈 `SceneId`) 프로젝트가 **에피소드마다 제 장면**으로 정상적으로 열린다.
- 기존 테스트 보존 + 각 단계의 characterization test.

## 8. 하지 않는 것

- **Scene 엔티티·테이블·목록** — §3-1.
- **Scene 표시명(별도 이름 칸)** — R1의 `D-R1b` 그대로, 안정 ID만 둔다.
- 런타임보다 강하거나 다른 불변식.
- 수명주기(Commit/Rollback/Replay) 재현 — 그것은 런타임의 것이고 툴은 **경계만** 저작한다.
