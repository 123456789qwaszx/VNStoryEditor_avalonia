# R0. 소비자 오라클 최신화 — 계획서

> 상위 계획: [PLAN.md](PLAN.md). 상태: **대기**. 작업 저장소: `VNStoryEditor_avalonia`만.

## 1. 목표와 한 줄 요약

에디터 안의 `Ked.Progression`을 현재 Unity 런타임 사본과 맞춰, **에디터가 허용한 JSON을 게임이 거부하는 틈을 먼저 닫는다.**

끝나면: 현재 런타임 DTO·로더·불변식이 에디터의 마지막 export 관문으로 실행되고, 제거된 레거시 타입에 에디터 코드가 기대지 않는다.

## 2. 선행 조건

- [x] 런타임 기준 브랜치 `server_DB`와 기준 커밋 확인.
- [x] 에디터 사본이 SceneId·VerifySceneEntries·Fold 이전이라는 실측.
- [ ] 착수 직전에 런타임 최신 SHA를 다시 기록.
- [ ] 런타임 담당자의 진행 중 변경 여부 확인. 변경 중이면 기준 커밋을 고정하고 기다린다.

## 3. 숙련자의 사고흐름

1. **기능 추가보다 심판 교체가 먼저다.** 낡은 심판 위에 Scene을 구현하면 잘못된 콘텐츠가 초록으로 보인다.
2. **파일 몇 개를 골라 복사하지 않는다.** 타입들은 함께 변한다. 반입 단위는 `Ked.Progression` 전체다.
3. **Unity 호스트 코드는 가져오지 않는다.** 순수 진행 코어만 에디터 테스트에서 소비한다.
4. **컴파일 오류를 목록으로 사용한다.** 제거된 Ending/Scenario API와 레거시 DTO 의존부를 숨기지 않고 드러낸다.
5. **규칙을 에디터에 재작성하지 않는다.** `CoreRefusals`가 실제 로더 진단을 엑셀 위치로 번역한다.

## 5. 특이사항

- 런타임 사본이 현재 실질 정본이다. 별도 `ked-progression` 저장소는 기준으로 쓰지 않는다.
- 에디터 사본에 남은 `EndingRule`, `ScenarioAdvance`, `ScenarioTransition`은 새 계약이 아니다.
- `Ked.Presentation.Core` 동기화와 섞지 않는다. 이번 단계는 진행 코어만 다룬다.
- Unity 전용 타입이나 비동기 호스트 계층이 들어오면 경계를 잘못 잡은 것이다.

## 6. 주의사항

| 증상 | 원인 | 대응 |
|---|---|---|
| 일부 파일만 바꿔 컴파일은 됨 | 구 API가 우연히 남음 | 전체 파일 목록과 공개 타입 대조 |
| 에디터 테스트만 초록 | 런타임 신규 불변식 픽스처 없음 | Scene·Auto 거부 픽스처 추가 |
| 진단 위치가 사라짐 | 코어 Path 형식 변경 | LocateInWorkbook 매핑 테스트 |
| 역사 문서까지 대량 수정 | 구현과 기록 정리 혼합 | 계약 코드만, 문서는 R5 |

## 7. 완료 기준

- [ ] 반입 원천 SHA와 파일 목록이 기록됨.
- [ ] 에디터·런타임 `Ked.Progression`의 의미 있는 소스 차이가 설명됨.
- [ ] 솔루션 컴파일 및 전체 테스트 통과.

- [ ] 잘못된 Scene/Auto 샘플은 코어가 거부하고 에디터 진단으로 변환됨.
