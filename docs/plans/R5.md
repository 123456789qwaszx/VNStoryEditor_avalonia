# R5. 표본·문서·인수인계 마감 — 계획서

> 상위 계획: [PLAN.md](PLAN.md). 상태: **R4 완료 후 착수**.

## 1. 목표와 한 줄 요약

구현된 계약을 실제 표본과 읽을 수 있는 문서로 고정하고, 외부 작업자가 저장소 첫 화면부터 검증까지 혼자 따라갈 수 있게 한다.

끝나면: 현재 계약과 역사 기록이 구분되고, 샘플 하나가 Scene·Auto·조건·스탯·Via·EventKey를 실제로 보여 준다.

## 3. 숙련자의 사고흐름

1. **문서는 코드의 복사본이 아니다.** 현재 사실·이유·검증 위치를 연결한다.
2. **샘플은 장식이 아니라 실행 가능한 계약이다.** 골든과 실제 소비자 로더가 함께 붙든다.
3. **역사를 지우지 않는다.** 다만 현재 지시처럼 보이지 않도록 상태를 명시한다.
4. **한 진입점에서 갈라진다.** README → 외부 개요 → PLAN → 현재 상태/상세 계약의 순서가 보여야 한다.
5. **숫자는 쉽게 낡는다.** 파일 수·테스트 수·커맨드 수는 재생성 근거나 기준 SHA와 함께 적는다.

## 5. 대표 표본이 보여야 할 것

- 같은 Scene에 속한 Episode 둘 이상
- Scene root와 다른 Scene으로 나가는 선택
- 같은 Scene 안 Auto 간선
- 표시 조건과 해금 조건
- Number Add와 Bool Set
- ViaNodeId가 있는 선택
- EventKey가 있는 Episode
- 안정적인 NextOptions 순서
- 같은 입력의 고정 checksum

한 파일에 너무 많은 예외를 억지로 넣지 않는다. 정상 표본 하나와 거부 표본 묶음으로 나눌 수 있다.
