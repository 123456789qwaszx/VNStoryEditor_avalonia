`VNStoryEditor_avalonia`가 `ked-presentation-runtime`의 현재 계약을 정확히 저작·검증·출력하도록 맞추는 계획이다.

- 에디터: `master@fdc7a26`
- 런타임: `server_DB@d53cc2f`
- 서버: `dev@2c6c1db`
- 분석: [외부 작업자용 시스템 안내와 런타임 정합성 점검](../external-overview.md)

## 0. 이 문서를 읽는 법

- 이 계획이 런타임 정렬 작업의 정본이다. 세부 작업은 `R0.md`~`R5.md`에 있다.
- 단계는 순서대로 진행한다. 완료 기준을 모두 통과하기 전 다음 단계로 넘어가지 않는다.
- 각 단계는 독립적으로 검증·커밋 가능한 단위다. 커밋 메시지는 `R1: Scene 저작 계약` 형식을 권장한다.
- `ked-presentation-runtime`과 `spring-prepare`는 읽기 전용이다. 계약 변경이 필요하면 해당 담당자에게 인계한다.
- `[결정 필요]`는 사용자 판단 없이 구현하지 않는다.
- “하지 않는 것”은 의도적 제외다. 편해 보여도 범위를 넓히지 않는다.
- 완료 표시는 코드 존재가 아니라 테스트·실제 소비자 로더 통과로 붙인다.

## 1. 목표

최종 상태는 다음 한 문장으로 판정한다.

> 같은 저작 원본은 언제나 같은 런타임 입력을 만들고, 에디터에서 통과한 콘텐츠는 현재 Unity 소비자에서도 통과하며, Scene·Auto·선택지 순서의 의미가 저작 화면에서 숨지 않는다.

## 2. 확정된 경계

| 주제 | 확정 |
|---|---|
| 값의 원본 | 챕터·대사 엑셀과 연출 그래프 중 한 곳만 소유 |
| Scene | 연출·롤백·pending 선택·fold·저장의 경계 |
| Episode | Scene 내부의 저작·실행 블록 |
| Scene 진입 | 장면마다 외부 착지 Episode 하나, 재진입은 root로 허용 |
| Auto | 명시값. 유일 간선·무조건·무스탯·같은 Scene |
| 진행 스탯 | 그래프 간선 조건과 StatChanges만 사용 |
| Yarn 변수 | 대사·연출 상태. 진행 스탯을 투영하지 않음 |
| 선택지 순서 | 화면 순서이자 서버 이력의 OptionIndex |
| 콘텐츠 버전 | progression JSON 원본 바이트의 SHA-256 |
| 서버 | 에디터가 직접 통신하지 않음 |

## 3. 프로젝트 규약

- 핵심 규칙은 `Vn.Authoring`, 화면 접합은 `Vn.App`에 둔다.
- 런타임 불변식을 다시 작성하지 않고 반입한 `Ked.Progression`을 오라클로 사용한다.
- 워크북 변경에는 reader·writer·migrator·샘플·골든 테스트가 함께 움직인다.
- JSON 키와 enum 이름은 런타임 DTO와 1:1로 유지한다.
- 정상 경로에서 오류가 있으면 산출물을 만들지 않고 시트·행을 짚는 진단을 반환한다.
- 기존 프로젝트는 명시적으로 마이그레이션하며 `.bak` 정책을 보존한다.

## 5. 단계별 완료 요약

### R0. 소비자 오라클

- 런타임 사본과 에디터 사본의 파일 차이를 기록한다.
- 한 번의 교체 단위로 재반입한다.
- 제거된 Ending/Scenario 레거시를 정리한다.
- 현재 산출 JSON을 새 로더에 넣는 테스트가 통과한다.

### R1. Scene

- 워크북에서 SceneId를 저작하고 구판은 빈 값으로 이행된다.
- 그래프가 같은 Scene과 root를 보여 준다.
- 두 번째 외부 착지점은 해당 간선 행에서 거부된다.
- JSON에 SceneId가 실리고 런타임 로더가 받는다.

### R2. Auto

- 자동 여부는 문구 공백이 아닌 명시값이다.
- 네 불변식 위반은 저작 위치에서 거부된다.
- JSON에 Auto가 실린다.
- 기존 일반 선택지는 동작이 바뀌지 않는다.

### R3. 결정성·순서

- 같은 입력을 반복 export한 바이트가 같다.
- NextOptions가 SourceRow 순서를 보존한다.
- 배포 기준선 이후 순서 변경 위험을 사용자가 알 수 있다.
- checksum 변화의 원인을 재현하는 검증이 있다.

### R4. 프리뷰·상태 격리

- 선택 가능 간선이 없을 때 프리뷰가 런타임과 같은 결론을 낸다.
- 장면 안 즉시 표시와 장면 끝 fold의 결과 동등성을 확인한다.
- 진행 스탯이 Yarn 조건으로 나가지 않는 회귀 테스트가 있다.

### R5. 마감

- 샘플 progression JSON과 워크북이 Scene·Auto 계약을 실제로 보여 준다.
- 현재 문서와 역사 문서를 구분한다.
- 외부 작업자가 README부터 검증 명령까지 따라갈 수 있다.
- 전체 테스트와 휴대용 패키지 smoke가 통과한다.

## 6. 공통 완료 기준

- `dotnet test .\VnTool.sln` 통과.
- 대표 샘플 export 성공.
- export된 JSON이 현재 런타임 `ProgressionLoader`를 통과.
- Yarn 번들이 실제 Yarn 컴파일러 검증 통과.
- 같은 입력의 재출력이 바이트 동일.
- README와 문서 링크에 깨진 경로 없음.
- 런타임·서버 저장소 변경 없음.
