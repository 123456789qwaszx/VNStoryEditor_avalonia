# R1. Scene 저작 계약 — 계획서

> 상위 계획: [PLAN.md](PLAN.md). 상태: **R0 완료 후 착수**.

## 1. 목표와 한 줄 요약

Episode 여러 개를 하나의 Scene으로 저작하고, Scene root와 외부 진입점 하나 규칙을 화면·진단·JSON에서 동일하게 표현한다.

끝나면: 기획자는 장면의 실제 수명 경계를 볼 수 있고, export된 `Nodes[].SceneId`가 Unity의 연출·롤백·fold·저장 경계를 결정한다.

## 2. 선행 조건

- [ ] R0 완료.
- [ ] [결정 필요 D-R1] 열 이름 확정: `장면` 또는 `장면ID`.
- [ ] [결정 필요 D-R1b] 안정 ID와 사용자 표시명 분리 여부.
- [ ] 런타임의 Scene 불변식과 기본값 재확인.

## 3. 숙련자의 사고흐름

1. **Scene은 시각 그룹이 아니라 상태 경계다.** UI 장식보다 데이터와 검증이 먼저다.
2. **빈 값 호환을 보존한다.** 구판은 각 Episode가 자기 Scene인 퇴화 상태로 안전하게 열린다.
3. **입구 하나는 연결성의 근거다.** 두 번째 착지점은 롤백·이어하기 기준을 모호하게 한다.
4. **재진입은 허용한다.** Scene을 넘는 순환과 허브 표현력을 막지 않는다.
5. **검증 정본은 런타임 코어다.** 에디터는 이해하기 좋은 시트·행 진단과 시각화를 더한다.

## 5. UI 요구

- 같은 Scene의 Episode를 배경 영역·테두리·라벨 중 일관된 방식으로 묶는다.
- root를 별도 표시한다.
- 외부에서 중간 Episode로 들어오는 간선을 선택하면 “여기서 Scene을 나눌까요?”로 설명할 수 있어야 한다.
- 빈 SceneId는 내부 발급값을 그대로 노출하기보다 “에피소드별 장면(기본)”으로 표현한다.
- SceneId 변경이 롤백·저장 경계를 바꾼다는 영향을 편집 UI에서 알려야 한다.

## 6. 주의사항

| 증상 | 원인 | 대응 |
|---|---|---|
| 같은 Scene에 root 둘 | 중간 Episode 외부 착지 | 해당 간선 행에서 오류 |
| 모든 빈 값이 한 Scene | 빈 문자열끼리 동일 비교 | 런타임의 Episode별 기본 발급 사용 |
| Scene 이름 변경으로 세이브 불일치 | ID를 표시명처럼 편집 | 안정 ID 정책 결정 |
| UI만 묶이고 JSON은 비어 있음 | 화면 작업 선행 | 모델→IO→Exporter→UI 순서 |
| 재진입까지 오류 | 간선 수와 착지점 수 혼동 | root로의 여러 간선은 정상 |

## 7. 완료 기준

- [ ] 구판 워크북을 열면 의미 변화 없이 Episode별 Scene으로 동작.
- [ ] 같은 Scene의 여러 Episode가 JSON에 같은 SceneId로 출력.
- [ ] 시작 Episode와 외부 착지점으로 root가 결정됨.
- [ ] 두 번째 착지점은 export 전에 시트·행 진단.
- [ ] Scene을 나갔다 같은 root로 재진입하는 그래프는 통과.
- [ ] 그래프에서 Scene과 root를 식별 가능.
- [ ] 런타임 `ProgressionLoader` 통과.
- [ ] 전체 테스트 통과.

## 8. 하지 않는 것

Scene 중간 저장, Scene 사이 무대 승계, 런타임 롤백 구현, 전역 Scene 카탈로그.
