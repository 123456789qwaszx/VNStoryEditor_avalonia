## W7. 변수 선언 중복 제거 (Phase 0 이월, 소형)

Phase 0의 "각 Story 노드 상단 선언" 방식은 여러 번들을 한 유니티 프로젝트로 컴파일할 때 중복 선언 오류를 낸다.

- 익스포트 단위에 **전용 선언 파일**(`declarations.yarn` — 커맨드 전용 노드 하나 또는 파일 헤더 선언부)을 도입하고, Story 노드 상단 선언은 제거.
- 여러 합성을 같은 폴더로 내보낼 때 선언 파일은 **합집합으로 한 번만** 생성. 같은 변수의 초기값이 합성 간에 다르면 발행 검증 오류.
- 수용 기준: 두 개 합성을 같은 폴더로 내보내고 Vn.Core 실컴파일 통과(중복 선언 0). W5 테스트 확장.

## W8. 선택지 (핵심 — 계약서 C3·D5·D6·D7 전부 관련)

### 모델 — 조건 전환과 동형의 "선택 전환 체인" (설계 제안)

기존 `BeginIf/BeginElseIf/EndIf` 체인과 같은 방식으로, 대본 라인 위에 얹는 전환으로 모델링한다. `ConditionFlowResolver`의 구조를 재사용하되 별도 체인 종류로:

- `BeginChoice(optionId)` — 이 라인이 **옵션 라벨 라인**이다(라인 본문 = 버튼 텍스트). 새 선택 블록을 연다.
- `BeginNextOption(optionId)` — 같은 블록의 다음 옵션 라벨 라인(elseif와 동형, 깊이 불증가).
- `EndChoice` — 블록 닫힘.
- 라벨 라인과 다음 라벨 사이의 라인들 = 그 옵션의 **본문**(선택 후 메인 레인에서 일반 라인으로 재생됨).
- 옵션별 데이터: `OptionId`(안정 식별자, `op_` 접두 신규), 라벨 라인의 `SetOperations`(선택 효과), 옵션 출구(BranchExits 재사용 — 본문 끝에서 jump), 표시용 스탯 미리보기는 **SetOperations에서 자동 생성**.
- 조건 체인과 선택 체인의 중첩은 Phase 1 비지원(발행 검증에서 거부). 깊이 규칙은 조건과 동일하게 0/1.

이 모델링의 이점: 대본 순서가 그대로 진실이고(작가의 평평한 대본에 라벨·본문이 라인으로 존재), 갈래별 라인 수·출구·그래프 포트가 기존 기계로 계산된다. Claude Code가 ConditionFlowResolver 구조에 맞춰 세부는 조정해도 되나, 아래 **불변 요구**는 지킬 것.

### 불변 요구

1. **순서 안정성 = 세이브 계약** (계약서 C3). 선택지 리플레이는 위치 기반(블록 서수 + 옵션 인덱스)이다. OptionId를 저장하고, 발행된 결과와 비교해 **옵션 순서가 바뀌거나 기존 옵션 위에 삽입되면 발행 검증 경고**를 낸다(차단은 아님 — 출시 전엔 자유). 경고 문구에 "출시된 세이브가 다른 선택지를 리플레이하게 됩니다"를 명시.
2. **라벨은 접두 없이 출력** (D6 결정). `-> <라벨 텍스트> <미리보기 태그들>`.
3. **미리보기 태그 자동 생성** (D5): SetOperations 중 `+=`/`-=` 정수 연산만 `#<변수소문자>:{+|-}<값>`으로. `=` 대입·비정수는 태그 생성 안 함(런타임 파서가 버림). 변수명에 대문자가 있으면 소문자화하되 발행 검증에서 알림(누적 표시 조회는 소문자 키로 일어남).
4. **실제 효과는 본문의 `<<set>>`** (D5): 옵션 라벨 라인의 SetOperations를 본문 첫 줄들로 출력. 태그는 표시 전용이다.
5. **조건부 옵션(D7)은 Phase 1 비지원** — 옵션 라벨 라인에 조건 전환이 겹치면 발행 거부. (가용 배열 인덱스 리플레이 문제를 아예 만들지 않는다.)

### 이미터 — Pres 락스텝과 선택의 동기화 (이 W의 난점)

선택지 블록 자체는 side advance 0이지만(계약서 B), **선택된 옵션의 본문 라인들은 일반 라인이라 advance를 1씩 소비한다.** 조건과 달리 선택은 변수가 아니라 플레이어 입력이므로 Pres 사본이 `<<if>>`로 그대로 재현할 수 없다. 해법 — **합성 추적 변수**:

- Story 출력: 각 옵션 본문의 첫 문장으로 `<<set $__ch_<blockOrdinal> = <optionIndex>>>`를 주입(작가 set들보다 먼저).
- Pres 사본: 선택 블록 자리에 `<<if $__ch_N == 0>> …0번 본문 사본… <<elseif $__ch_N == 1>> … <<endif>>` 를 출력. 저장소 공유 + 서브 레인은 메인이 본문 첫 라인에 진입한 뒤에만 평가하므로(그 시점에 set은 이미 실행됨) 같은 갈래를 탄다. 갈래별 본문 라인 수는 같은 결과에서 생성되므로 일치.
- `$__ch_*`는 선언 파일에 자동 포함, 시킹 리플레이에서도 결정적(계약서 C5와 정합 — 리플레이는 저장된 선택 기록으로 같은 옵션을 다시 고른다).
- 옵션 본문 라인에도 `#line:` 태그(일반 대사 라인이므로 세이브 타깃 가능 — C1).
- 옵션 출구 jump 전 `pres_end`(A5) 규칙은 기존과 동일하게 적용.

### 수용 기준

options.yarn 상당의 샘플(2블록, 본문 라인·set·범위 없는 정수 효과 포함)을 툴에서 재현 → 트리오 출력 → 실컴파일 통과 + 골든. 왕복 테스트: 옵션 라벨 문구 수정 → 재발행 → OptionId·순서·`$__ch` 번호 불변. 순서 변경 시 경고 발생 테스트. UI: 라인 카드에서 선택 전환 지정·SetOperations 편집(조건 드롭다운과 같은 자리).

## W9. CSV 내보내기 (마스터 플랜 §2.5의 2·3·4)

- 공통: 모든 내보내기는 발행 결과(합성) 기준 — Phase 0 파일 내보내기와 같은 입구. **CSV는 UTF-8 BOM 포함**(엑셀 한글 호환 — .yarn의 no-BOM 규칙과 의도적으로 다름을 주석으로 명시), CRLF 허용, 셀 이스케이프 표준(RFC4180).
- **(2) 번역·녹음**: 열 = LineId, 화자, 대사, (녹음용은 노드명·인덱스 추가). locale 선택 가능(모델은 이미 locale 구분).
- **(3) 기획 검수**: 열 = 노드, 인덱스, LineId, 화자, 대사, 조건 상태(갈래 이름), 선택 블록/옵션, SetOperations, 출구. 한 줄 = 대본 한 줄.
- **(4) 연출 테이블**: 열 = LineId, 대사(참조용 읽기 전용), 커맨드 순서, 커맨드명, 인자들, 메모(#main_free 등 메타).
- 수용 기준: 샘플 합성에서 3파일 생성, 엑셀에서 한글 정상 확인(수동), 열 스키마 골든 테스트.

## W10. 연출 공급 노드 + 커맨드 프리셋 (마스터 플랜 §2.1–2.2)

- `CommandSupplyNode`: 공급 카테고리 집합 + 커맨드 프리셋 목록. `NodeLinkKind.CommandSupply` 추가. 구현 순서는 ARCHITECTURE §5.2 capability node 레시피 그대로.
- `AvailablePresentationCommandResolver`: 연결된 공급 노드들의 카테고리 합집합 + 프리셋 → PresentationNodeEditor 드롭다운. **공급 노드 미연결 시 전체 카탈로그 폴백**(저작을 막지 않는다).
- `CommandPreset { PresetId(pp_ 접두), DisplayName, CommandDefinitionId, ArgumentValues(파라미터 순서), Note }` — 공급 노드 소유. PresentationNode 바인딩에서 프리셋 참조 + 부분 오버라이드 허용.
- **발행 시 값으로 동결**: PresentationResult에는 해석된 최종 커맨드·인자만 들어간다(프리셋 후속 수정이 발행본에 영향 없음 — 연출 결과 스키마 v3). 발행 후 프리셋이 삭제·변경되어도 결과 재출력은 동일 텍스트.
- 그래프: 공급 간선은 Settings 간선과 같은 비실행 연결로 표시.
- 수용 기준: 카메라 노드(shot+transition 공급) 예제 — 연결 전 드롭다운 전체/연결 후 제한 확인 테스트, 프리셋 수정 후 기존 발행 결과 해시 불변 테스트, 프리셋 사용 라인의 출력 텍스트 골든.

## W11. `[adv/]` 인라인 동기화 지원

- 모델: PresentationNode의 라인 바인딩에 **마커 그룹** 도입 — 한 LineId의 커맨드들을 0..N 그룹으로 나누고, 그룹 경계마다 Story 본문에 `[adv/]` 마커가 삽입될 위치(문자 오프셋 또는 어절 인덱스)를 기록.
- 이미터: Story 라인 본문에 마커 삽입, Pres 사본은 그 라인 자리에 **1 + 마커 수** 개의 라인(첫 그룹은 본문 사본 라인에, 이후 그룹은 빈 후속 라인에) — 계약서 B의 라인 예산 준수. 마커명은 `adv` 고정(`[advance/]` 아님).
- Phase 0의 "[adv/] 발견 시 검증 경고"는 이 W에서 정식 지원으로 대체.
- 수용 기준: 마커 2개 라인 샘플의 트리오 골든 + 실컴파일, 마커 없는 기존 프로젝트 출력 불변(회귀).
